# EIGHT PC Agent

会社が貸したパソコンに入れる常駐ソフト。
mf.8grp.co.jp（社内グループウェア）の「端末管理」に記録を送る。

**メンバーが自分で入れて、管理画面で一覧できる**形にしてある。
IT側からの一斉配布（Intune / GPO）は要らない。

---

## 1. 何を取り、何を取らないか

実装がそうなっていることを、コードのどこで確かめられるかも書いておく。

| 取るもの | どこで |
|---|---|
| 起動・終了・ログオン・ロック・スリープ | `internal/collect/win_session.go` |
| 1日の稼働時間・離席時間 | `internal/collect/tally.go` |
| 使ったソフトの名前（実行ファイル名）と合計時間 | `internal/collect/win_foreground.go` |
| 見たサイトの**カテゴリ**と合計時間 | `internal/collect/category.go` |
| USBメモリの抜き差し・ソフトの出入り | `cmd/eight-agent-svc/platform_windows.go` |

| **取らないもの** | 実装でどう塞いでいるか |
|---|---|
| キーボードで打った内容 | フックを一切張っていない。`GetLastInputInfo` は「最後に触った時刻」しか返さない |
| パスワード・クリップボード | 読む口が無い |
| メール・チャットの本文 | 同上 |
| 画面の録画・スクリーンショット | 画面をキャプチャするAPIを呼んでいない |
| **ウィンドウのタイトル** | `GetWindowText` を呼んでいない。`grep -r GetWindowText` で0件 |
| **URLの全文** | `internal/collect/category.go` の `Of()` が返すのは6語のどれかだけ。`category_test.go` がそれを確かめている |
| ファイルの中身 | 読む口が無い |

送る構造体（`internal/api/client.go` の `Event` / `Usage` / `AppUsage` / `WebUsage`）に、
これらを入れる**場所そのものが無い**。入れる場所を作らないのが、いちばん確実な歯止め。

## 2. なぜ2つのプロセスに分かれているのか

Windows の **Session 0 Isolation** により、
サービス（SYSTEM）からは対話セッションのフォアグラウンドウィンドウが取れない。
「いま何のアプリを使っているか」はサービスからは分からない。

```
┌─ eight-agent-svc.exe（サービス / SYSTEM）──────┐
│  起動終了・ロック・USB・ソフトの出入り            │
│  待ち行列・送信・シークレットの入れ替え           │
└─────────────┬────────────────────────┘
              │ 名前付きパイプ \\.\pipe\eight-agent
┌─────────────┴────────────────────────┐
│ eight-agent-ui.exe（ログオン時 / ユーザー権限）   │
│  前面のアプリ・離席の判定                        │
│  URL → ホスト名 → カテゴリ に **ここで**落とす    │
│  タスクトレイ（記録中であることが本人に見える）    │
└──────────────────────────────────────┘
```

> **URL の変換は必ず UI プロセスの中で終わらせる。**
> サーバに送ってから落とすと、送信経路とサーバのログに一度は全文が乗る。
> そこが漏れたら、落とした意味がない。

## 3. 入れかた（メンバーが自分でやる）

### 3-1. 管理者：登録コードを出す

グループウェア → **システム管理 → 端末管理 → 「登録コードを出す」**。
渡す相手を名簿から選ぶと、`ABCD-2345-KMNP` のようなコードが1度だけ出る。
**7日で切れる。1回しか使えない。**

### 3-2. メンバー：自分のパソコンで実行する

```
eight-agent-svc.exe -enroll ABCD-2345-KMNP
```

これだけで
1. このパソコンが台帳に載る（`source=agent`）
2. 端末専用のシークレットが `%ProgramData%\EIGHT\` に保存される（DPAPI で包む）
3. **既定のブラウザが自動で開く** → `device-consent.html?link=...`

### 3-3. メンバー：ブラウザで確認する

開いた画面に、記録していること／していないことが出る。
読んで **「このパソコンです」** を押す。

**ここを押すまで、エージェントは1件も送らない。**
`gw_devices.notified_at` が null のあいだ、
サーバは `collect:false` を返し、待ち行列にも集計にも何も入らない。
就業規則への明記と本人への周知が済んでいなければ、入れてもデータは溜まらない。

押した時点で、そのパソコンは**そのとき社内システムにログインしていた人のもの**になる。
人事が名簿から割り当てる手間が要らない。

### 3-4. 状態を見る

```
eight-agent-svc.exe -status
```

記録しているか、未送信が何件あるか、取っていないものが何かを出す。
本人はタスクトレイからも見られる（`http://127.0.0.1:14812/`）。

## 4. 組み立て

```
./build.sh          # 確かめて dist/ に組む
./build.sh test     # 確かめるだけ
```

Linux から Windows 向けに組める（cgo 無し）。
`internal/` は OS に依らないので、Linux でテストできる。

```
go test ./internal/...      # 集計・待ち行列・カテゴリ変換
GOOS=windows go vet ./...   # Windows 向けの見直し
```

### 組んだあと、Windows 側でやること

1. **会社の証明書で署名する**（`signtool sign /fd sha256 ...`）
2. SHA256 を取る
3. 管理画面の「端末管理 → 設定」に 版・URL・SHA256 を登録する

> **署名の検証を省かない。**
> 自動更新の口は、そのまま「全PCで任意のコードを動かせる口」になる。
> サーバは 版・URL・SHA256 の3つがそろうまで「更新なし」を返す
> （`api/devices/manifest.js`）。検証できない配布物を落として実行させないため。

## 5. サービスとして登録する（管理者権限）

```
sc create EightAgent binPath= "C:\Program Files\EIGHT\eight-agent-svc.exe -run" start= auto
sc failure EightAgent reset= 86400 actions= restart/5000/restart/30000/restart/60000
sc start EightAgent
```

UI プロセスは **タスクスケジューラの「ログオン時」** で起動する。
`HKLM\...\Run` は使わない（ユーザーが消せる。タスクなら管理者権限が要る）。

```
schtasks /create /tn "EIGHT Agent UI" /tr "C:\Program Files\EIGHT\eight-agent-ui.exe" ^
  /sc onlogon /rl limited /f
```

## 6. この環境で確かめたこと・確かめていないこと

| | |
|---|---|
| ✅ | `windows/amd64` 向けにビルドが通る（PE32+ の exe ができる） |
| ✅ | `go vet` が通る（Linux 向け・Windows 向けの両方） |
| ✅ | 集計・待ち行列・カテゴリ変換の単体テスト（16件） |
| ❌ | **Windows 実機での動作** — この環境に Windows が無い |
| ❌ | サービスとしての登録、Session 0 越しのパイプ |
| ❌ | Authenticode 署名 |
| ⚠ | `currentHost()`（アドレスバーの読み取り）は**まだ空を返す**。UI Automation の COM 呼び出しは実機で詰める必要がある。そのあいだ、サイトのカテゴリだけが取れない（アプリ名と稼働時間は取れる） |

**1台で2週間ためしてから、全員に配ること。**
