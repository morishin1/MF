引数の YYYY-MM 月の承認済みドラフトを MF に送信してください。

## 前提
- `data/periods/YYYY-MM/journals_draft.json` に `approval.status = "approved"` のレコードが存在する
- `.env.local` に有効な `MF_ACCESS_TOKEN` がセットされている

## 手順

1. **対象抽出**
   - `journals_draft.json` から `approval.status === "approved" && send_status === "not_sent"` のものだけを抽出
   - 1件もなければ「送信対象なし」と表示して終了

2. **冪等性チェック**（必須・最重要）
   - `data/periods/YYYY-MM/journals_sent.json` を読み込む（無ければ空配列で開始）
   - 各対象について `idempotency_key = ksp_{draft_id}_v1` を生成
   - すでに同 `idempotency_key` が `journals_sent.json` に存在する場合は送信をスキップし、ドラフトの `send_status = "sent"` を補正

3. **送信ユーザー確認**
   - 「N件をMFに送信します。続行しますか？」と件数を表示してユーザー確認
   - YESなら次へ、NOなら終了

4. **MF送信**（1件ずつ順次）
   - MCPツール `mcp__mf-accounting__*` の仕訳作成APIを呼ぶ
   - リクエストペイロードのSHA256を計算
   - 成功時:
     - `journals_sent.json` に `{ draft_id, mf_journal_id, idempotency_key, sent_at, request_payload_hash, response_snapshot }` を追記
     - ドラフトの `send_status = "sent"`、`mf_journal_id` を記録
     - `data/log/mf_send_log.jsonl` に1行追記（成功）
   - 失敗時:
     - 4xx系: エラー内容を記録、`send_status = "error"`、`mf_send_log.jsonl` に追記、次の仕訳へ
     - タイムアウト・ネットワーク断: `send_status = "unknown"`、`mf_send_log.jsonl` に `status: unknown` で記録 → 次回 `/送信状況確認` で照合

5. **完了サマリー**
   - 成功 / スキップ / エラー / 不明 の件数を表示
   - 次のアクション: `/試算表取得 YYYY-MM`

6. **監査ログ**
   - `data/log/audit.jsonl` に `{ ts, action: "journal_send", period: "YYYY-MM", success, skipped, error, unknown }` を追記
