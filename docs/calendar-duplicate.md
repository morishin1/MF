# カレンダー予定の複製

## 操作

`calendar.html` の「自分」で、予定詳細・予定一覧・日別予定の「複製」を選択する。
内容・数字（予定）・区分・場所・本人メモと日時を「未保存」の下書きへ引き継ぐ。
新しい開始日または開始時刻への変更が必須。元と同じ日時のままでは保存できない。
区分・場所・本人メモは任意の詳細欄にまとめ、通常は日付変更→保存で済む。
開始日・開始時刻を変えると、時間幅を保ったまま終了日時も移動する。終了日時は個別にも変更できる。
終日の終了日はその日を含み、既存仕様どおり最終日23:59まで。時刻は日本時間。

## 境界

- 複製元は本人取得済みの `source=self` かつ `visibility=shared` の業務予定のみ。全員画面・他人・外部予定・予約・休暇・HR自動生成・私用・非公開からは複製しない。
- 明示した許可項目だけを既存の `API.createEvent` に渡す。元予定への更新・削除なし。
- ID、所有者、tenant、履歴、完了状態、外部同期ID、参加者、Google書出し指定は引き継がない。
- サーバーがログイン中の所属・本人に固定し、既存RLSを通す。API・DB・認証・権限の変更は不要。
- 保存前は閉じる・キャンセル・Esc・背景で破棄。保存中は入力と閉じる操作を止め、連打しても送信は1回。
- 応答不明は自動再送せず、閉じて再複製や別の追加経路でも再送しない。ページ再読み込みで登録済みか確認するよう案内。確定的な入力拒否は草案を残して修正可能。
- Back/Forward・ページ離脱では未保存のフォームを破棄する。ダイアログ用の履歴は増やさない。
- 数字は予定値（0を含む）のみ引き継ぐ。実績・完了扱いにはしない。旧schemaでは数字入力を無効にして時間・内容だけ保存できる。読み込んだ数字の保存能力が不明な場合やschema競合は、数字を黙って落としたり自動再送せず下書きを保持する。
- 複数日予定の表示は既存と同じ開始日基準。期間全日への描画は今回の範囲外。

## ローカル確認

```sh
npm test
node test/calendarduplicate.mjs
node --experimental-test-module-mocks test/calendarduplicateapi.mjs
node test/calendarduplicatepreview.mjs
# ローカル静的サーバ＋合成APIのみ
TEST_BASE=http://127.0.0.1:8713 node test/ui/calendarduplicateui.mjs
```

ブラウザテストは自分・全員、3つの複製導線、保存前編集、取消、連打、応答不明、
非JSTタイムゾーン、終日・日またぎ・年またぎ、スマホ幅、対象外予定、数量の旧schema、Back/Forwardを扱う。
`CALENDAR_DUPLICATE_SCREENSHOTS=1` を指定すると既存の `shotPath` 配下へ診断用画像を出す。

## ログイン不要のダミー確認版

```sh
node scripts/build-calendar-duplicate-preview.mjs /tmp/calendar-duplicate-preview
```

`index.html` は単独で開ける。実画面のHTML/CSSと同一の複製コントローラを使用し、
認証とAPIを架空予定のメモリ実装に差し替えたもの。外部通信・永続保存・実データ・通知なし。
CSPで通信を禁止し、再読み込みで元に戻る。画面にも確認版であることを明記する。
本番の認証や公開設定を変更する仕組みではない。公開・本番反映は別途承認が必要。
