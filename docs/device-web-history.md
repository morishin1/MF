# WEB利用の記録（在宅勤務の確認）

端末管理の一部。**勤務時間中にどのサイトを使っていたか**を見るための仕組み。
`db/057_device_one_pc.sql` を流すと使えるようになる。

---

## 1. いちばん先に決めること

**この機能は、社員に伝えたことを1つ変えます。**

057 より前、社員の画面にはこう書いてありました。

> 取らないもの：… 社内システム以外で見たページ … 見たページのURL（種類だけ）

057 からは **ドメインとページの場所（URLのパス）まで取ります。**
告知（`api/devices/me.js` の `AGENT_NOTICE`）と管理画面の注意書きは、
このリポジトリ側で書き換え済みです。

残っているのは会社側の手当てです。**これが済むまで配らないでください。**

- [ ] 就業規則、または端末管理規程に、この記録を取ることを書く
- [ ] 書いたものを周知する（読んだ記録を残す。`library.html` に置ける）
- [ ] 利用目的を決めて書く（個人情報保護法の利用目的の特定・通知）
- [ ] 保存期間を決める（既定90日。`gw_device_policies.keep_visits_days`）
- [ ] 誰が見られるかを決める（いまは人事・管理者と本人）

> **URLのパスは、思っているより多くを映します。**
> `/recruit/apply/step3`（転職活動）、`/psychiatry/`（通院）、
> `/roudou-kumiai/`（組合活動）。
> 消しきれないので、**見たことが本人に残る**側で釣り合いを取っています
> （管理者がWEB利用を開くと `gw_device_views` に残り、本人の画面に出ます）。

## 2. 何を取って、何を取らないか

| 取るもの | 例 |
|---|---|
| アクセス日時 | 09:02 |
| ドメイン | `chatgpt.com` |
| URLのパス | `/c/…`（`?` より後ろは無し） |
| サイトカテゴリ | AI |
| 利用開始・終了 | 09:25 〜 09:57 |
| 実際に見ていた時間 | 32分 |
| 使用ブラウザ | Chrome |
| Device ID / 社員ID | 台帳の行と、名簿の行 |

| 取らないもの | どう塞いでいるか |
|---|---|
| パスワード・フォームの中身 | 拡張に `host_permissions` も `content_scripts` も無い。ページに入れない |
| チャット・メールの本文 | 同上 |
| ページ本文 | 同上 |
| Cookie・認証トークン | `cookies` 権限が無い |
| 検索キーワード | `?` から後ろを、**端末の中で**捨てる |
| URLの断片（`#…`） | 同上 |
| ページのタイトル | `tab.title` に触らない。テストが見張っている |

削る場所は4つあり、どれか1つが緩んでも次で止まります
（拡張 → 継ぎ役 → 常駐ソフト → サーバ）。詳しくは `agent/extension/README.md`。

## 3. 勤務時間とセキュリティを分ける

| | 対象 | 時間外 |
|---|---|---|
| **働き方を見る**（WEB利用・稼働時間） | 原則、勤務時間内のぶんだけ | 既定では出さない |
| **情報漏えいに関わる**（USB・ソフトの出入り・未通信） | いつでも | 残す |

勤務時間は、タイムカードの打刻（`gw_time_entries`）を使います。
打刻が無い日は会社の既定（`gw_device_policies.work_from` / `work_to`、初期値 9:00〜18:00）。
夜勤のように日をまたぐ設定も読めます。

判定は**記録を入れるとき**に決めて `in_work_hours` に持ちます。
見るたびに突き合わせると、あとから解釈がぶれるためです。

## 4. 見かた

### 一覧（`admin-devices.html`）

細かい履歴は出しません。**○ / △ / ×** だけです。

| | 意味 |
|---|---|
| ○ 正常 | ふつうの日 |
| △ 要確認 | 勤務中に SNS・動画・買い物が長い／勤務時間のわりに操作が少ない／深夜の稼働 |
| × 異常 | **その日の記録が届いていない**（Agent かブラウザ連携が止まっている） |

× は「記録が取れていない」であって、人の行いを × とはしません。

### その人を開いたとき（［WEB利用］）

```
山田 太郎 さんの WEB利用          今日
 △ 要確認   勤務中に SNS・動画・買い物が 0:45

 勤務      09:00〜18:00   9:00

 WEB利用   4:32
 アプリ利用 2:03
 離席      0:43

 WEB利用 4:32
 [業務 3:21] [AI 42分] [SNS 18分] [動画 27分] [その他 24分]

 履歴
 09:02  mf.8grp.co.jp /home.html   社内システム  18分  chrome
```

カテゴリで絞っても、上の合計は動きません（絞り込みで数字が変わると読み違えるため）。

## 5. アラート

どれも **「確認してください」であって「不正」の判定ではありません。**
`severity` は `warn` までで、`critical` にしていません。

- 勤務時間中に SNS・動画・買い物が長い（既定90分。`distract_min_minutes`）
- 勤務時間なのに操作がほとんどない
- 深夜のWEB利用が多い
- Agent が止まっている／ブラウザ連携が止まっている

SNSを見ていた＝サボり、ではありません。調べものでSNSを見ることも、
休憩が打刻に入っていないこともあります。**事情を本人に確かめてください。**

## 6. 保存期間

| | 既定 | 設定 |
|---|---|---|
| WEB利用の履歴（1件ずつ） | 90日 | `keep_visits_days` |
| 日別の集計 | 13か月 | `keep_daily_months` |
| できごと | 400日 | `keep_events_days` |

履歴はいちばん重いので、いちばん短くしてあります。

## 7. 入れるとき

社員がやることは1つだけです。

```
EIGHT-Agent-Setup.exe をダウンロード
  → 実行（管理者の確認が1回）
  → ブラウザが開く
  →「このパソコンです」を押す
  →「記録すること」を読む
  → 完了
```

登録コードは打たせません。コマンドも使わせません。
ブラウザの拡張も、このインストーラが一緒に入れます。

配る前に済ませること（`agent/extension/README.md`）:

- [ ] 拡張の鍵を作り、ID を決める
- [ ] `.crx` と `updates.xml` を `mf.8grp.co.jp/ext/` に置く
- [ ] `EXT_ID=…` を付けて `agent/build.sh` を実行する
- [ ] `EIGHT-Agent-Setup.exe` に**コード署名する**
- [ ] Windows 実機で `docs/device-agent-testing.md` を通す

## 8. まだ確かめていないこと

Windows の実機で動かした確認は**1件もできていません**（開発環境に Windows が無いため）。
組み上がることと、OSに依らない部分の判断は自動で確かめてあります。

実機で最初に確かめるのは、この2つです。

1. 本人が「このパソコンです」を押すまで、**1件も届かないこと**
2. アドレスバーに打った検索語が、**どこにも出ないこと**
   （`select distinct host, path from gw_device_web_visits` に検索語が無い）

この2つが通らないうちは、次に進まないでください。
