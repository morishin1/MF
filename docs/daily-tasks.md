# 毎日の実行管理（明日の3件 → 今日やる3つ）

タスク管理を「たまった仕事の一覧」から「毎日3つ終える仕組み」に変えたときの記録。
2026-09-16。

---

## 0. 何を変えたのか

これまでの `gw_tasks` は一覧だった。増える一方で、今日どれを終わらせるのかは誰も決めていない。
登録した数ではなく、**毎日3つ終えたかどうか**で回るようにした。

```text
会社目標 → KPI → AIが優先順位を確認 → 明日の3タスク → 担当確定 → 日報
→ 翌朝の「今日やる3つ」→ 完了
```

1日の流れ:

| # | 何が起きるか | どこで |
|---|---|---|
| ① | 明日のタスクを3件登録 | 日報画面のいちばん上 |
| ② | AIが内容をチェック | 「AIに見てもらう」 |
| ③ | AIが優先度・担当者を提案 | 同上（案と理由だけ） |
| ④ | 本人または管理者が確認・合意 | 「この案にする」「担当を変える」 |
| ⑤ | 明日のタスクとして確定 | 「この内容で確定する」 |
| ⑥ | 日報入力を解放 | 確定した瞬間に開く |
| ⑦ | 日報を提出 | これまでどおり |
| ⑧ | 翌朝、ダッシュボードに「今日やる3つ」 | ホームのいちばん上 |
| ⑨ | 完了チェック | 「完了する」ボタン |

---

## 1. 表は増やさない

タスクそのものは `gw_tasks` のまま。列を足した（`db/072_focus_tasks.sql`）。

| 列 | 何のため |
|---|---|
| `focus_date` | 何日の重要タスクか。null なら、ふつうのタスク |
| `focus_rank` | その日の中の順番 |
| `focus_for` | **誰の3件として決めたか**。担当（`assignee_id`）とは別 |
| `purpose` | 目的 |
| `kpi_link` | 関連KPI・事業 |
| `ai_review` | AIの講評 `{verdict, reason, fix, doneCondition, kpi}` |
| `ai_assignee` / `ai_assignee_why` | AIの担当の案。**確定するまで担当には入れない** |
| `carried_from` / `carry_count` | 持ち越し。決めたときだけ動く |
| `not_done_reason` | 終わらなかった理由 |

日ごとの状態だけ、新しい表（`gw_focus_days`）で1行持つ。

```text
draft（3件そろっていない） → ready（そろった） → ai_checked（AIが見た） → confirmed（人が確定）
```

タスクの列に状態を散らすと「3件のうち1件だけ確定」のような状態が作れてしまう。

### `focus_for` と `assignee_id` を分けた理由

自分の3件のうち1件を人に渡すことがある。渡した先では「その人が今日やること」になるが、
決めたのはこちらなので、こちらの3件からは消えない。1つの列で兼ねると、
渡した瞬間に自分の3件が2件になる。

- **決める側の一覧**（明日の3件）… `focus_for` で引く
- **やる側の一覧**（今日やる3つ）… `assignee_id` で引く

## 2. 判定は1か所（`lib/focus.js`）

画面・API・cron の3か所で「確定したか」を書くと、必ず食い違う。純粋関数にまとめた
（テスト `test/focustest.mjs` 24件）。

- `focusState({day, tasks})` … いまの状態と「次に何をすればよいか」
- `progressOf(tasks)` … `1 / 3`。分母はその日に決めた数（積んであるタスクの数ではない）
- `nippoGate({day, tasks, focusDate})` … 日報を書いてよいか。書けない理由もここで作る
- `nextFocusDate(today)` … 明日＝次の営業日。金曜の夜に決めたら月曜ぶん
- `boardRow` / `boardSummary` … 管理者の一覧の1行と、上の数

重要タスクに要るもの（欠けていると夜に できた／できなかった を判定できない）:

```text
タスク名 / 目的 / 完了条件 / 担当者 / 期限 / 優先度  （＋任意で 関連KPI・事業）
```

---

## 3. AIは案を出すだけ（`lib/task-ai.js`）

`reviewFocus()` が見るのは、書かれた内容と数だけ。

- 本当に明日やるべきか／会社・事業目標につながっているか／KPIにつながっているか
- 単なる作業になっていないか／完了条件が明確か
- 担当者が適切か／その人に寄っていないか／もっと優先すべき未完了タスクがないか

返すのは **OK/NG ではなく、理由と直した文**。`verdict` は `ok` / `fix` / `drop` の3つで、
`fix` のときは書き換え案と完了条件の案が付く。

担当の提案は、役割・部署・いまの未完了件数・明日の重要タスク件数を見て出す。
出した先は `ai_assignee` で、**`assignee_id` には入れない**。人が「この担当にする」を
押してはじめて変わる（`test/focusapi.mjs`「AIは直さない。案を出すだけ」）。

AIの鍵（`OPENAI_API_KEY` / `ANTHROPIC_API_KEY`）が無い環境では、AIの確認だけができない。
**確定は止めない**。AIが無いと明日が決められない仕組みにはしない。

---

## 4. 日報は「明日を決めてから」

`api/nippo/index.js` の提出で、翌営業日ぶんが `confirmed` でなければ
`400 focus_required` を返す。画面（`nippo.html`）も、確定するまで日報の欄を触れなくする。

今日を振り返ってから明日を決める形にすると、振り返りで力を使い切って、
明日の欄が「引き続き頑張る」で埋まる。順番を逆にする。

`db/072` をまだ流していない環境では、これまでどおり出せる（`test/gatetest.mjs`）。
新しい決まりで、今日の日報が出せなくなるほうが困る。

日報の画面には、今日の重要タスクも並ぶ。完了を押しながら、
終わらなかったものには理由を1行書ける。

---

## 5. 翌朝の「今日やる3つ」（`home.html`）

いちばん上・いちばん大きく。常に `0 / 3 完了` を出す。
押すと `1 / 3` → `2 / 3` → `3 / 3` と進み、3件終わると **「今日の重要タスク完了」**。

タスクが10件あっても、まずこの3件を終わらせる画面にしている。

---

## 6. 未完了は、自動で動かさない

終わらなかった重要タスクは、決めるまで日報画面に残り続ける。選べるのは4つ。

| 決め方 | 何が起きるか |
|---|---|
| 明日へ持ち越す | 翌営業日の重要タスクになる。`carry_count` が1つ増える |
| 優先度を下げる | 重要タスクから外れ、ふつうのタスクに戻る |
| 別の人へ渡す | 担当が変わって通知が飛ぶ。重要タスクからは外れる |
| やらないことにする | 取りやめ。理由が記録に残る |

AIに案を出させることもできる（`reviewCarry`）。2回以上持ち越しているものには、
そのまま持ち越すのではなく、下げる・渡す・やめる を検討させる。

自動で繰り越すと、終わらないタスクが毎日並んで、一覧を見る意味が無くなる。

## 7. 権限

| | 見えるもの | できること |
|---|---|---|
| 一般メンバー | 自分の重要タスクだけ（今日・明日・未完了） | 決める・直す・確定する・完了する |
| 管理者・人事 | 全員ぶん | 上に加えて、代わりに登録・確定・担当の振り分け |

他人の `employeeId` を指定できるのは管理者だけ（`api/tasks/focus.js` の `targetOf`）。
一般メンバーが指定すると 403。

## 8. 管理者の一覧（`admin-tasks.html`）

出すのは3つだけ。今日の3件と完了数／明日の3件の状態／止まっていること。

| 担当者 | 今日の3タスク | 完了数 | 明日の3タスク | 状態 |
|---|---|---|---|---|
| A | 3件 | 3/3 | 登録済（確定） | 完了 |
| B | 3件 | 1/3 | 未登録 | 注意 |
| C | 3件 | 2/3 | AI確認中 | 進行中 |

絞り込み: 日付・月・担当者・部署・事業（KPI）・完了／未完了・状態・AI提案あり。
**止まっている人が上に来る**。毎日見る画面なので、探させない。

行を押すと、その人の今日・明日の中身が開く。管理者はそこから代わりに確定できる
（本人が休んでいる日に止めないため）。
