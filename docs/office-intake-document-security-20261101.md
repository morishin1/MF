# Office 入社書類・社労士確認：安全な導入手順（2026-11-01）

## この変更の位置づけ
既存の「本人提出 → 人事（Office）が受付 → 担当社労士が確認／差戻し → 完了」を維持し、
通常の入退社書類を非公開の `hr` バケットと専門家タスクで運用する。
`gw_procedure_files` と `gw_procedure_items` が提出実績の原本。書類は社労士タスク側へ複製しない。
マイナンバーの実データは **本システムに保存しない**。社労士が別経路で直接取得・管理し、
Officeには `gw_procedures.mynumber_status`（依頼済み／提出済み／確認完了など）のみ記録する。

## 既存の書類の所在
- 本人のアップロード: Supabase Storage の private bucket `hr` に
  `<tenant_id>/<procedure_id>/<file_id>.<ext>`、台帳 `gw_procedure_files`。
- Google Drive連携が設定済みで複製が成功した場合、各本人フォルダの
  `03_入社提出書類` や `04_社会保険・労務` 等へ保存（`drive_file_id` を台帳に記録）。
- **人ごとの実際の提出件数や今福さん／山内さんの書類実体は未確認**。
  「提出済み」の画面表示だけでなく `hr` の実ファイルを認証後に開いて照合する。
- 以前は Drive の `機微情報` フォルダを本人へ自動共有する実装があった。
  **このPRで将来の自動共有を止めるだけでは既存のDrive権限を解除できない**。
  管理担当が過去の権限・外部リンク・直接アップロードファイルを監査し、必要な権限だけに絞る。

## 必須のデプロイ前点検
1. `hr` バケットが `public=false` であること。DB・Storage のRLSと権限関数が本番でも一致すること。
2. `db/157_onboarding_file_read_scope.sql` を検証用 DB で先に適用。
   旧 `hr_files_rw` 直接アクセスを停止し、バックエンド経由の署名URLで通常の書類が読めることを確認。
   （直接 `storage.from('hr')` を使う旧クライアントがないことを検索・確認）
3. `MFA_ENABLED` は現行コードでは既定で任意。機微書類を扱う担当者にはMFA有効化・強制の要否を決定して適用。
   既定で二段階認証が強制されているとは報告しない。
4. 本番データは公開ログ・AI・Slackに表示しない。ファイル名だけでも個人情報を含み得る。
   閲覧ログが `gw_sensitive_access_log` に残ることを確認する。監査ログ書込みが失敗しても
   既存コードは閲覧を許すので、監査成功を必須にする設計は別途検討する。
5. 既存 `gw_procedure_files` の不明なファイル・機微ファイルを権限のある担当者だけが棚卸しする。
   個人番号・番号確認書類を見つけてもその内容を転記しない。保管／移送／削除は社労士と安全管理責任者が判断する。
6. 職務上閲覧不要な一般Officeメンバー・税理士・他社員の権限を拒否する。権限は画面非表示だけでなく
   API応答・DB RLS・ストレージからの直アクセス・既存Driveの共有権限で検証する。

## ロール別の受入確認（ダミー文書と検証用アカウントで）
| 役割 | 通常の本人書類 | 他人の通常書類 | 個人番号の実データ |
|---|---|---|---|
| 本人 | 自分の提出・閲覧、進捗表示 | 拒否 | Officeで取扱いなし |
| 人事権限ありOffice担当 | 業務範囲で確認・受付 | 業務範囲で確認 | Officeで取扱いなし |
| 担当社労士 | 共有設定済み書類・確認タスク | 非共有分は拒否 | 社労士側の別経路 |
| 税理士・一般社員 | 原則拒否 | 拒否 | 拒否 |

確認観点:
- 本人Aが書類を提出 → ファイル実体存在 → 受付状態 `submitted`。
- `share_with_advisor=true` の通常書類だけが社労士タスクに現れ、社労士が確認完了／差戻しできる。
- 差戻し理由が本人とHRに伝わる。個人番号は差戻し理由・タスク名・ファイル名に書かない。
- 社労士が別人・非共有書類・マイナンバー書類にファイルURLを要求 → 404/403。
- 一般社員が他人の `fileId` を指定しても URL は取得できない。
- ダウンロード用URLは5分で期限切れ。保存先を public に変えない。
- 今福さん／山内さんについては提出の有無だけでなく、本人が再閲覧できることを当人の同意を得て実機確認。

## 運用導線
- 管理担当：Office → 入退社（既存 `admin-hr.html`）、対象社員の手続き・提出ファイルを確認。
- 社労士：Office → 社労士・税理士（`office/professionals.html?tab=labor`）。
  担当割当、受付中、期限超過、再提出、確認済みを確認。
- 本人：入社手続き `onboarding.html` と自分の書類の提出状況を確認。
- マイナンバー：番号のファイルや値をOfficeにアップロードさせず、社労士からの別案内に従って提出する。
  Officeでは `mynumber_status` を手作業または検証済み外部連携で更新する。
