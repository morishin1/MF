# 端末管理 内部仕様（管理者・開発者向け）

**この文書は社員に配らないでください。**

社員向けには大分類だけを伝えます（`docs/device-guide-for-members.md`）。
判定条件やしきい値を配ると、避ける方法を配ることになります。
一方で、社内で決めたことが曖昧なままだと運用が回らないので、
**ここには正確に書きます**。社員向け表示と内部仕様を混同しないでください。

| | 社員向け | ここ（内部） |
|---|---|---|
| 記録すること | 大分類6つ | 実際の項目 |
| 記録しないこと | 定型文で「必要のない個人情報は取得しない」 | 具体的に列挙 |
| 判定条件 | 出さない | 正確に書く |
| 保存期間 | 出さない（規程には書く） | 正確に書く |

---

## 1. 位置づけ

会社貸与PCの端末管理は**会社ルール**です。同意の取得ではありません。

- 社員に「監視してよいですか」と許可を求める仕組みにしない
- 会社として端末管理を行うことを**事前に周知**し、本人が内容を確認した日時を記録する
- 社員側で拒否して端末管理を解除する仕組みは作らない

実装:

| | どこ |
|---|---|
| 周知した日時 | `gw_devices.notified_at` |
| 本人が押したか、管理者が周知したか | `gw_devices.notified_kind`（`self` / `admin`） |
| 管理者が周知したときの経緯 | `gw_devices.notified_note`（必須。空では登録できない） |
| 本人が端末を外す | **できない**（`api/devices/me.js` の `forget` は 403） |

周知が記録されるまで、利用時間は1件も入りません（`collect.Agent` がそう作ってある）。
これは拒否権ではなく**事前周知の担保**です。本人が押せないときは、
管理者が対面・書面で周知し、管理画面の「周知済みにする」で前に進めます。

### 端末の登録

本人がマイページから始めます。管理者が登録コードを発行する運用は廃止しました
（社員はログインしているので、誰なのかはもう分かっている）。

```
マイページ →「会社PCのセキュリティ設定」
  → POST /api/devices/setup          … 1回きりの札を作る（15分・1人1本）
  → GET  /api/devices/setup?download=…  … 札を確かめて、配布先へ 302
       落とすファイル名: EIGHT-Agent-Setup-<札>.exe
  → 社員が実行
  → インストーラが自分のファイル名から札を読む（agent/internal/setup）
  → POST /api/devices/pair           … 札に PC の情報を足す
  → 既定のブラウザで /device-setup.html?pair=<札>
  → 本人のブラウザなので、押させずに確定（claim）
  → GET /api/devices/pair?token=…&code=1 … 登録コードを1回だけ引き取る
  → POST /api/devices/enroll         … 端末シークレットを受け取る
  → 本人が「内容を確認しました」     … ここまで記録は始まらない
```

札（`gw_device_pairings`）の性質:

| | |
|---|---|
| 中身 | 32バイトの乱数（base64url）。保存するのは sha256 だけ |
| 期限 | 15分 |
| 本数 | 1人1本。作り直すと、使っていない前の札は消える |
| 持ち主 | `kind='selfserve'` は**作った時点で**決まる |
| 再利用 | 不可（`used_at` が入ると受け取らない） |
| 他人 | 別の人がログインしたブラウザで開かれても結びつけない（403） |

中身を変えずにファイル名だけで渡すので、**署名もハッシュもそのまま通ります**。
配る版を人ごとに作り分ける必要もありません。

ファイル名から読めなかったとき（名前を変えられた等）は、インストーラが
自分で札を作ります（`kind='installer'`）。そのときだけ、本人が画面で
「このパソコンを設定する」を押します。止まりません。

> 配布先が Supabase Storage なら、署名つきURLでファイル名を指定します。
> 別の場所（自社サーバ等）に置く場合は名前を変えられないので、
> 必ず installer 側の道に落ちます。動きますが、1回押す手間が増えます。

## 2. 実際に取得する情報

### 2-1. ブラウザ側（社内システムを開いているあいだ）

| 項目 | 保存先 |
|---|---|
| 端末の印（乱数。ブラウザに保存） | `gw_devices.device_uid` |
| OS・OSバージョン・ブラウザ名・画面の大きさ | `gw_devices` |
| 社内システムを開いていた時間（1日の合計） | `gw_device_usage.active_min` |
| そのうち深夜・休日にあたる時間 | `gw_device_usage.night_min` ほか |

### 2-2. エージェント（会社貸与PCを使っているあいだ）

| 大分類（社員向け） | 実際に取るもの | 保存先 |
|---|---|---|
| 端末の利用状況 | 起動・終了・ログオン・ロック・スリープの時刻、稼働時間、離席時間 | `gw_device_events` / `gw_device_usage` |
| アプリケーションの利用状況 | 実行ファイル名・製品名・合計分数 | `gw_device_app_usage` |
| WEBの利用状況 | ドメイン、パス（削ったもの）、カテゴリ、開始/終了時刻、アクティブ秒数、ブラウザ名 | `gw_device_web_visits` / `gw_device_web_usage` |
| 外部機器の接続状況 | USB の接続・取り外し、機器のID | `gw_device_events`（`usb_attach` / `usb_detach`） |
| ソフトウェアの変更状況 | 「プログラムと機能」の増減（名前とバージョン） | `gw_device_events`（`app_install` / `app_uninstall`） |
| セキュリティ上必要な端末情報 | ホスト名、BIOSシリアル、OSビルド、エージェントの版 | `gw_devices` |

## 3. 取得しない情報

コードに入れる場所がありません（表に列が無い、構造体に項目が無い）。

- キーボードで打った内容
- パスワード
- メール・チャットの本文
- 画面の録画・スクリーンショット
- 開いていたウィンドウのタイトル
- ページの中身
- フォームに入れた内容
- Cookie・認証トークン
- ファイルの中身
- URL の `?` 以降（検索語・メールアドレス・ワンタイムの鍵が入る）
- URL の `#` 以降

守っているところ: `agent/internal/collect/extension_test.go`（拡張の権限を検査）、
`agent/internal/collect/forbidden_test.go`。

## 4. WEBデータの加工

4段階で削ります。**1か所が緩んでも、次で止まります。**

```
① ブラウザ拡張 … URL から ? 以降と # 以降を落とす（agent/extension/background.js）
② 継ぎ役      … もう一度削る（agent/cmd/eight-agent-host、collect.PathOnly）
③ エージェント … 送る直前にもう一度（collect.HostOnly / PathOnly）
④ サーバ      … 受け取ってからもう一度（lib/devices.js の cleanHost / cleanPath）
```

`cleanPath` の中身:

- `?` 以降、`#` 以降を落とす
- 空白・制御文字を落とす（本物のURLのパスに生の空白は入らない。
  入っているのはアドレスバーに打った検索語を読んだとき）
- ワンタイムの鍵に見えるセグメント（長い英数字など）を `…` に伏せる
- 6セグメントまで。120文字まで

例:

| 開いたもの | 保存するもの |
|---|---|
| `google.com/search?q=新宿 ランチ` | `google.com`（パスなし） |
| `example.com/news/2026/kessan` | `example.com` + `/news/2026/kessan` |
| `bank.co.jp/login?token=xxxx` | `bank.co.jp` + `/login` |
| `x.com/i/status/aBcD1234EfGh5678` | `x.com` + `/i/status/…` |

アクティブ時間は「タブが前面にあり、かつ操作があったあいだ」だけを数えます
（`agent/extension/background.js`）。開きっぱなしのタブは数えません。

## 5. 保存期間

すべて `api/cron/devices.js`（毎日1回）が消します。人が思い出して消す仕組みにしません。

| データ | 既定 | 設定 |
|---|---|---|
| WEB履歴（1件ずつ） | **90日** | `gw_device_policies.keep_visits_days` |
| イベント（起動・USB・ソフト変更など） | 400日 | `keep_events_days` |
| 1日ごとの集計（利用時間・アプリ別・サイト別） | 13か月 | `keep_daily_months` |
| 使用終了にした端末（記録ごと） | 90日 | 固定 |

## 6. 閲覧権限

| 誰が | 何を |
|---|---|
| 本人 | 自分の端末情報と利用時間。**誰がいつ自分の情報を見たかも** |
| 人事・管理者 | 全員の台帳、アラート、詳細（WEB利用を含む） |
| それ以外 | 見られない |

列の隠しは RLS ではなく API 層で行っています（**RLS は行を絞るもので、列は絞れない**）。

### 管理者の閲覧も監査する

管理者が社員の詳細やWEB利用を開くと、次の2つに残ります。

1. `gw_device_views` … 誰が・誰の情報を・いつ・どの範囲を見たか
   → **本人のマイページに出ます**
2. `gw_activity_log` … `device.view_web` / `device.view_device`

会社から一方的に見るのではなく、見たことが見られる側にも見える形にしてあります。
これはこの機能でいちばん大事な性質なので、**外さないでください**。

## 7. アラートの判定

**社員には公開しません。** 判定は `lib/devices.js` の1か所にまとめてあります。

| ルール | 条件 | 重さ |
|---|---|---|
| `distract_in_work` | 勤務時間内の SNS・動画・買い物の合計が `distract_min_minutes`（既定90分）以上 | warn |
| `night_web` | 深夜のWEB利用が60分以上 | warn |
| `no_activity` | 勤務が240分以上で、PCの操作が60分未満（退勤を押していない日は対象外） | warn |
| `agent_silent` | エージェントから24時間以上届いていない | warn |
| `confirm_waiting` | 周知の確認が `confirm_wait_days`（既定3日）以上つかない | warn |
| `unknown_device` | その人が使っていなかった端末から入られた | warn |
| `no_access` | `stale_days`（既定60日）以上使われていない | info |
| `usb_attach` / `unapproved_software` | USB接続・未承認ソフト（設定で入切） | 設定による |

**critical を機械が付けることはしません。** どれも「管理者に確認を促す」ためのものです。
機械が「不正」と決めると、確かめずに処分する運用になります。

判定の入口は2つですが、条件は共通です。

- 画面の `○ / △ / ×` … `dayVerdict()`
- 夜間バッチが立てるアラート … `webAlerts()`

**両方を同じしきい値で動かしてください。** 片方だけ直すと、
画面に △ が出ているのに確認する先が無い（またはその逆）が起きます。

## 8. 私物PC

業務は原則、会社貸与PCのみ。私物PCには EIGHT Agent を入れません。

| 区分 | `gw_devices.ownership` | 画面 |
|---|---|---|
| 会社貸与 | `company` | 何も出さない |
| 私物（承認なし） | `personal` | 「私物（承認なし）」（赤） |
| 私物（承認あり） | `personal` + 期限内の承認 | 「私物（承認済み）」（緑） |
| 未確認 | `unknown` | 「未確認」（黄） |

エージェントが入っているものは自動で `company` になります（会社が配ったものしかない）。

### 事前承認

`gw_device_exceptions` に、対象社員・端末・理由・承認者・利用期限を残します。

- 期限は必須。**最長365日**（無期限の代わりに遠い日付を入れられないようにするため）
- 出したことも取り消したことも消さない
- 承認・取り消しは本人にも通知される
- 出せるのは人事だけ

### 未登録端末から入られたとき

`gw_device_policies.unregistered_action` で扱いを選べます。

| 値 | 意味 | 実装 |
|---|---|---|
| `notice` | 管理画面に出すだけ | **済**（既定） |
| `warn` | 本人の画面にも出す | 未 |
| `notify_admin` | 管理者に通知する | 未 |
| `restrict` | 一部の機能を止める | 未（入口を止める作りが別に要る） |
| `deny` | 入れない | 未（同上） |

設定の受け皿は先に作ってあります。**止める側はまだありません。**

## 9. 管理画面の設計方針

**正常な社員を細かく見るための画面にしない。**

```
一覧           … Agent ○△× / ブラウザ ○△× / 最終通信 / 要確認件数 だけ
  ↓ △ か × のときだけ
詳細           … PC利用・アプリ・WEB・USB・ソフト変更・Agent状態・過去の要確認履歴
```

一覧に細かい履歴を出さないのは、見る用がないのに毎日目に入る状態を作らないためです。
詳細を開くと本人に残る、という性質もここで効きます。

管理画面TOPには「端末管理でやること」だけを出します（0件のときは出しません）。

- 本人の確認待ち … 押すまで記録が始まらないので、放置すると台帳が空のまま溜まる
- 未確認のアラート … 確認するまで残る

**週1回まわして、どちらも0にする**のが運用です。
