対象：`db/101`〜`db/103` の適用、アプリのデプロイ、**1人分の勤務表でのE2E確認**、後始末。

## 4. 使い方：どの画面で何をするか

誰が：経営者・責任者・経理（二段階認証を登録・確認済みであること）。

| 順 | 画面 | 操作 |
|---|---|---|
| 1 | `/office`（月次業務） | 月を選ぶ。行の「現在工程」が「勤務表待ち」なら **「勤務表を登録・確認」**、「稼働確認待ち」なら **「勤務表を確認・確定」** を押す（右ドロワーの「勤務表を開いて確認・確定」でも同じ） |
| 2 | `/office/timesheet.html`（勤務表の確認） | 左に勤務表、右に読取結果。**「勤務表を追加」**で、メール等で受け取った勤務表を登録（外部提出フォームから届いたものは、最初から左に出る） |
| 3 | 同上 | **「AI で読み取る」**（30秒〜1分）。読み取った内容は **下書き** で、まだ稼働時間にはならない |
| 4 | 同上 | 色のついた日（要対応）から、左の勤務表と見比べて直す。欄を離れる（Tab）と、その日だけ保存される |
| 5 | 同上 | 下の「確定できます」になったら **「この内容で確定する」**（AI・一括操作では確定されない。人が押したときだけ） |
| 6 | `/office` | 「← 月次業務へ戻る」。稼働時間（確認済 168.5h）が出て、現在工程が「請求作成待ち」へ進む |
| — | `/office/terms.html`（契約条件） | 単価・精算幅などを登録する（稼働確定後の売上の精算に使う）。勤務表の画面・ドロワーからも開ける |

### 表示の見方（読取不能・低 confidence・休憩不明）

- **赤い印（【入力が必要】）**：実働を出せない日。休憩が空／開始・終了が空／勤務か休みか未確認。**空のまま**（AI は推測で埋めない）。値を入れるまで、合計に入らず、確定もできない。理由は行の右に出る（例：「休憩が不明です（補完しません）」）
- **黄色い印（要確認）**：実働は出せるが、人の目で見てほしい日。AI の自信が低い（「AI 低」＋理由）／勤務表の実働と計算が違う／日跨ぎ・月跨ぎ／平日なのに空白。**「確認した」を押すか、値を直すと**確認済みになる。確認済みにするまで確定できない
- 判読できなかった項目（字が潰れている等）は、値を入れず、その理由を出す
- 「読めなかった日を休みに」「休憩を一括入力」「要確認をまとめて確認済みに」は、**人が押したときだけ**動く

### 対応するファイル

**PDF・JPEG・PNG だけ**（外部提出フォームと同じ）。HEIC など、ほかの形式には対応しません（増やしません）。形式は、拡張子ではなくファイルの中身（先頭のバイト列）で決めます。

| 形式 | 登録・表示 | AI読取 |
|---|---|---|
| PDF | ○（10MBまで。左に表示） | ○（PDF として渡す） |
| JPEG | ○（10MBまで） | ○（5MB まで。AI 側の上限。超えると「PDF にするか小さくして出し直す／手入力」と案内） |
| PNG | ○（10MBまで） | ○（5MB まで。同上） |
| それ以外 | 断る（画面で選んだ時点で、送信せずに案内） | — |

### 同じ勤務表を2回登録したとき

- **Office から登録**：同じ人・月・契約に同じ中身があれば、登録せず「同じファイルが、すでに届いています」（ファイルは1件のまま。AI も呼ばない）。別の人・別の月に同じ中身があれば、確認のうえで登録でき、**両方に警告**（別のファイルではありませんか？）
- **外部提出フォームから2回届いた**：画面を開いた時点（AI読取の前）に、中身を確かめて、2件とも「同じファイルが複数」の印を出す。原本（先に届いたほう）を読み取る
- 中身が違えば、別のファイルとして扱う（読み取り元は、選んだファイル。新しいファイルが届いたら「読み取り後に新しいファイルが届いています」と知らせる）

### 確定したあと、既存の5つの印はどうなるか

| 出来事 | 印 | 補足 |
|---|---|---|
| 勤務表が届いた（外部フォーム／Office から登録） | `timesheet_received` を立てる | 外部フォームは従来どおり |
| **確定**（confirmed） | **`work_confirmed` を立てる**（`timesheet_received` も） | 請求の印（`board_created`・`sent`）は触らない |
| 確定の取消し（理由が要る） | `work_confirmed` を外す | 請求書の作成・送付の印があれば、取り消せない |
| 差し戻し（理由が要る） | `timesheet_received` を外す | 再提出を待つだけ。**メールは送らない** |
| 既存の月初作業管理で印を手で付ける | そのまま使える | 勤務表の行が無い印は「確認済（手動）」で、警告にしない。勤務表が確定していないのに印がある／確定しているのに印が無い、のときだけ「要確認」 |

## 5. 本番前のE2E：1人分の勤務表で通す

**やってはいけないこと**：メール・請求書・振込は、この手順のどこにも出てきません（Phase 3 にその機能は無く、差し戻しもメールを送りません）。テストデータは、**名前で一目で分かる**ものにしてください。

### 5-0. 準備

- テスト用の要員：`【E2Eテスト】田中 太郎`（メンバー管理で登録。区分はプロパー）
- テスト用の現場契約：客先 `E2Eテスト株式会社`、契約開始 対象月の月初以前、終了日は空
- 勤務表：**本物に近い1人分**（社内で扱ってよいもの。個人情報を含むなら、社内の取り決めに従う）。PDF・JPEG・PNG のどれか
- 対象月：直近で勤務表が出ている月（未来の月でもよいが、期限超過の表示は出ない）
- 二段階認証を済ませた、経理・責任者・経営者のアカウント

### 5-1. AI だけ先に確かめる（DB に触れない）

```
ANTHROPIC_API_KEY=<本番と同じキー> [ANTHROPIC_MODEL=<本番と同じ>] node scripts/office-read-check.mjs <勤務表ファイル> --month <YYYY-MM>
```

見ること：

- [ ] **かかった秒数**が 60 秒に十分収まる（収まらないなら、この先へ進まず、知らせてください）
- [ ] 日ごとの読取結果が、実際の勤務表と合っている（誤読・見落としの数を数える）
- [ ] 読めない所が**空のまま**出ている（もっともらしい値で埋められていない）
- [ ] 「人が見る量」（入力が必要な日・要確認の日）が、現実的な数

### 5-2. 契約条件を登録する

`/office` → 対象の行 → ドロワー「契約条件を登録する」（または `/office/terms.html?contract=…`）。
例：月額 700,000円・精算幅 140〜180時間・超過 4,000円／控除 3,500円・円未満は切捨て。**売上単価・仕入単価は別の欄**（既存の「単価」欄は使わない）。

### 5-3. 一連の操作（各行が「できた」になること）

| # | 操作 | 期待する結果 | ✔ |
|---|---|---|---|
| 1 | `/office` を開き、対象月・対象の行を探す | 現在工程が「勤務表待ち」、稼働時間は「—」 | ☐ |
| 2 | 「勤務表を登録・確認」→「勤務表を追加」で、勤務表を選ぶ | 左に勤務表が表示され、状態が「提出済み・未読取」。`/office` の勤務表の印（受領）が立つ | ☐ |

| 4 | 「AI で読み取る」 | 30秒〜1分で、状態が「確認待ち」。**確定にはなっていない**（`/office` の稼働確認の印は、まだ立たない） | ☐ |
