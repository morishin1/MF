# 入社手続きの改修 — 設計と進め方

依頼: 手作業・Slack・Google Drive 中心の運用を、**ステータス駆動**のオンボーディングにする。
管理者・入社予定者・社労士の3者が同じ案件を、権限ごとに必要な画面だけで扱う。

この文書は「既存に何があり、何を足すか」を先に決めたもの。
第1段階は実装済み（下の「段階ごとの実装」）。

## 0. 先に確認した、既にあるもの

「作り直す」前提で読み始めたが、部品はほぼ揃っていた。足りなかったのは**それらをつなぐ1本の軸**。

## 1. 5段階（実装済み）

```
① conditions      労働条件の指定・作成依頼      管理者
② advisor_review  労働条件の確認・承認          社労士
③ signing         労働条件・誓約書の締結        入社予定者
④ intake          入社情報の入力・書類の提出    入社予定者（並行して社内準備）
⑤ complete        入社手続き完了
```

**段階は計算する**（`lib/onboard-stage.js` の `computeStage`）。
正は5つの表の事実（作成依頼・署名・届出・同意・チェックリスト）で、
`gw_procedures.stage` はその写し。手で書き換える列ではない。

写しを持つ理由は1つ。前回と比べて「進んだ」を検知して、次の担当者へ1通だけ知らせるため
（`lib/onboard-advance.js` の `advance`。同じ段階で何度走っても通知は増えない）。

事実が変わる場所すべてで `advance` を呼ぶ:

| 事実 | 場所 | 進む |
|---|---|---|
| 作成依頼を出した | `api/sign/orders.js` create | ①→② 社労士へ通知 |
| 書面が届いた／発行した | `api/sign/orders.js` attach / send | ②→③ 本人へ通知 |
| 本人が署名した | `api/sign/me.js` | ③→④（同意もそろっていれば） |
| 届出を出した | `api/onboarding/me.js` submit | ④の中 |
| チェックを付けた | `api/hr/index.js` / `api/onboarding/items.js` | ④→⑤ |

④ で本人の作業と社内準備は**並行**。本人が出し終えても社内準備が残れば完了にならず、
「次の担当」は管理者に切り替わる。

## 3. 情報の3段階と、誰が何を見られるか

| 区分 | 何 | 誰が | どこで止めるか |
|---|---|---|---|
| 通常 | 氏名・部署・入社日・段階・社内準備 | 管理者・人事・上長・IT・経理 | RLS（既存） |
| 機密 | 住所・生年月日・口座・年金/雇用保険番号・扶養・契約書・提出書類 | 人事（hr/owner）・本人・共有された項目だけ社労士 | RLS（既存）+ **閲覧ログ（070 で追加）** |
| 最重要 | マイナンバー・その確認書類・本人確認書類 | `mynumber_handler` と必要な社労士のみ | **別表・別バケット・別ロール（第3段階）** |

RLS は行を絞るが列は絞れない。列の出し分けは API 層（service_role）で行い、
画面でボタンを隠すだけにはしない。URL を直接叩いても、権限が無ければ 0 件か 403。

### 閲覧ログ（`gw_sensitive_access_log`、070）

誰が・いつ・誰のぶんを・何を（届出/口座/書類/契約/マイナンバー）・どうした（見た/落とした/変えた/消した）。
本人が自分のぶんを見たときは残さない。削除の policy は作らない（誰も消せない）。
第1段階では、提出書類を開いたときと、他人の届出を一覧で開いたときに残る。

### ストレージ

- `hr` バケットは非公開。公開 URL は発行しない
- 閲覧は署名付き URL（5分）。他人に送っても、期限が切れれば開けない
- Storage の RLS（`hr_files_rw`）でも、本人・人事・共有された社労士以外は拒否

## 4. まだ決めていないこと（返事が要る）

### 4-1. マイナンバーを持つか

**いまの設計は、番号そのものを持たない**（`db/037` 冒頭、`lib/onboard-form.js`）。
理由は、番号法の安全管理措置（取扱区域・アクセス記録・確実な廃棄）が「列を1つ足して済む話ではない」から。
社労士へは別途、貴所の指定する方法で渡す運用にしてある。

今回の依頼は「分離して安全に保存」。持つと決めるなら、次を全部やる:

- 専用表 `gw_mynumber`（employee_id・暗号文・鍵の版・登録者・登録日時・削除予定日）。`gw_employees` には置かない
- アプリケーション層で暗号化（鍵は Vercel の環境変数、ローテーション可能な版付き）
- 触れるのは `mynumber_handler` ロールだけ。人事・管理者の権限では**列そのものを返さない**
- 見た・出した・消したを全件ログ（`gw_sensitive_access_log` kind=mynumber）
- 検索・一覧・CSV には出さない。出すのは社労士向けの MF 給与取込だけ、それも権限者が明示的に押したとき
- 保存期限（退職後の法定保存期間）と、期限後の削除運用

**持たない**という選択肢も残る（社労士のシステムで直接収集してもらう）。どちらにするか決めてください。

### 4-2. MFA

Supabase Auth の TOTP（アプリ認証）で実現できる。人事・労務・`mynumber_handler`・社労士・システム管理者に必須化するには:

1. 各自がマイページで登録（画面が要る）
2. サーバ側で、機密の API は `aal2` のトークンだけ通す（`requireUser` の隣に `requireStrong`）
3. 登録していない人が機密 API を叩いたら「先に MFA を登録してください」へ誘導

登録の日を決めて、その日から強制にする。いきなり強制すると、その日に誰も入れなくなる。

### 4-3. 保存地域

`docs/SETUP_PHASE1.md` は Tokyo（ap-northeast-1）推奨で書いてある。実際のプロジェクトがどこかは、
Supabase の Project Settings → General で確認してください。バックアップは同じリージョン内。
私からは見えません。

### 4-4. Google Drive をいつ止めるか

`lib/hr-drive.js` は未設定なら何もしない。`GDRIVE_HR_FOLDER_ID` を外せば、フォルダの個別作成・共有権限の手動設定は止まる。
ただし過去に Drive に入れた書類はそのまま。mf 側の `hr` バケットへの移し替えは別途。

## 5. 段階ごとの実装

### 第1段階（済）

- `db/070_onboarding_stage.sql` — stage / stage_at、閲覧ログ表、`mynumber_handler` ロールの予約
- `lib/onboard-stage.js` — 5段階の判定・進捗・KPI（純粋関数、`test/stagetest.mjs`）
- `lib/onboard-advance.js` — 段階の再計算と通知。事実が変わる5か所から呼ぶ
- `lib/sensitive-log.js` — 閲覧ログ。書類を開いた・他人の届出を見た
- `api/hr/index.js` — 一覧に段階・次の担当・止まっているもの・入社まで日数・KPI
- `admin-hr.html` / `admin-dashboard.html` — 5つの数と新しい列
- `test/aiguard.mjs` — 入社系から AI を呼ばないことを毎回確かめる

### 第2段階（次）

- 社労士画面（`advisor.html`）に「労働条件のプレビュー → 修正 → 承認・発行」を1画面で。
  発行＝書面を付けて署名依頼まで（いまは管理者が「送る」を押す2手）
- 本人画面（`onboarding.html`）の上に STEP 1〜4 の進捗バー。「今やること」を1つだけ大きく
- オリエンテーション（会社説明・就業ルール・勤怠・情報セキュリティ・設備・PC/Slack）。
  `gw_consent_docs` と同じ仕組み（版付き本文＋「確認しました」）で、動画・PDF はリンク
- 通知に「入社日が近いのに未完了」「不足書類がある」を足す（cron）
- Slack 通知を、入社系だけ既定オフに

### 第3段階（決めてから）

- マイナンバー（4-1 の返事が要る）
- MFA（4-2）
- 保存期限と削除（種別ごと。`gw_retention`＋cron）
- MF 給与取込 CSV（社労士向け。出したことをログに残す）

## 6. 「最終的に無くしたい作業」との対応

| 無くしたい作業 | どれで無くなるか |
|---|---|
| Slack での入社情報送信 | 社労士画面で直接見る（第2段階）。Slack は既定オフ |
| 紙の入社連絡票 | `gw_onboard_profiles`（済） |
| Drive フォルダの個別作成・共有権限の手動設定 | `GDRIVE_HR_FOLDER_ID` を外す（4-4） |
| 紙書類のスキャン | `hr` バケットへの提出（済） |
| 入社状況を担当者が記憶して管理 | 5段階と KPI（第1段階、済） |
| 社労士への個別連絡 | 段階が進んだら自動で通知（済） |
| 保存場所の分散 | `hr` バケットに一本化（Drive を止めた後） |
