# 旧タスク管理を、グループウェアへ移す

旧: `https://8grp.co.jp/8/zimu/task/`（表は `public.zimu_tasks`）
新: `https://mf.8grp.co.jp/admin-tasks.html` / `tasks.html`（表は `public.gw_tasks`）

## 先に、いちばん聞かれること

**旧のデータは消えていません。**

このリポジトリは `zimu_tasks` を1か所も参照していません（読みも書きもしない）。
新しい画面が別の表（`gw_tasks`）を見ているので、旧のタスクが出てこないだけです。

見えないときに、まず疑うのはここ:

| 症状 | 理由 | 確かめ方 |
|---|---|---|
| 旧画面を開いても空 | 旧の RLS は `zimu@8grp.co.jp` だけに許可している。別のアカウントで開くと1件も出ない | `zimu@8grp.co.jp` でログインし直す |
| 新画面に出てこない | 新画面は `gw_tasks` を見ている。移すまで出ない | 下の「データを移す」 |

数だけ見たいときは、Supabase の SQL Editor で:

```sql
select count(*) filter (where coalesce(archived,false)=false and status <> '完了') as 未完了,
       count(*) as 全部,
       max(updated_at) as 最終更新
  from public.zimu_tasks;
```

## 何を移したか（第1段階）

旧で実際に効いていたのは、一覧でも通知でもなく次の3つでした。それを移してあります。

| 仕組み | 旧 | 新 |
|---|---|---|
| 依頼 → 受諾 | `done_condition` / `accepted_at` | 同じ列を `gw_tasks` に追加 |
| 完了に結果を書く | `result` | 同じ |
| 繰り返し | `recur` / `is_template` / `template_id` / `occ_key` | 同じ。生成は `api/cron/tasks.js`（毎日 0:10 JST） |

### 依頼 → 受諾 → 完了

- 頼むときに「どうなったら終わりか」を書ける（`admin-tasks.html`）
- 頼まれた側は、受けるまで **未確認の依頼** として一覧に出る。受けるまで完了は押せない
- 受けるときに期限を引き直せる。引き直すと、頼んだ人に通知が飛ぶ
- 頼まれた仕事は、**何をしたかを1行書かないと完了にできない**。その1行は通知にも入る

自分で立てたメモには、受諾も結果も求めません。
全部に求めると面倒で完了を押さなくなり、その時点で一覧が信用できなくなります。

### 繰り返し

- 毎日（平日のみ／全部）／毎週／毎月n日（休みなら前後の営業日へ）／毎月第n営業日
- 祝日表は `lib/holidays.js`。**年に1回、手で足します**
  （足し忘れると第n営業日がずれるので、`test/recurtest.mjs` が先に落ちて教えます）
- 作るのは **当月＋翌月だけ**。旧は12か月先まで作っていて、
  月1件の繰り返しでも一覧に12件並び、片付けても減らない見え方になっていました
- `occ_key`（`template_id|YYYY-MM-DD`）に一意制約があるので、何度走っても増えません

## まだ移していないもの（第2段階以降）

使ってみて要るものから足します。順番は相談して決めます。

| 仕組み | 旧での中身 |
|---|---|
| エスカレーション | 期限3営業日超過／繰越3回以上／支援要請48時間放置 → 社長が「指示／期限引き直し／引き取り」で応じる |
| 支援要請 | `needs_help` / `help_note`。「手が足りません」を出す |
| 繰越の理由 | 翌日へ送るときに理由を必須にする（押すだけで何度でも先送りできないように） |
| 複数人で共有 | 1つのタスクに人を複数紐づける（コピーにしない） |
| 1日3回の確認 | 朝／14時／退勤前だけに固定する |
| 当月スコープ | 担当者の画面は当月末までに絞る |
| しきい値の設定 | `zimu_settings` でコードを変えずに変える |

## 手順

### 1. SQL を流す

Supabase の SQL Editor に貼って Run。上から順に。

1. `db/068_task_flow.sql` — 列を足す（べき等）
2. `db/069_zimu_task_import.sql` — 旧の未完了ぶんを移す（**1回だけ**）

069 は、旧の表がこのプロジェクトに無ければ、その場で止まって
「別プロジェクトかもしれない」と言います。黙って空で終わりません。

### 2. 移った結果を見る

```sql
select count(*) from public.gw_task_imports;          -- 移した件数
select count(*) from public.zimu_tasks;               -- 旧は減っていないこと
select t.title, t.due_on                              -- 担当者が付かなかったもの
  from public.gw_tasks t
  join public.gw_task_imports i on i.task_id = t.id
 where t.assignee_id is null;
```

担当者が付かないのは、旧側に `assignee_id`（auth.users の id）が無く
氏名だけで持っていた行です。画面から付け直してください。
氏名で機械的につなぐことはしません（「田中」と「田中 一郎」で行方不明になるため）。

### 3. 繰り返しを作り直す

繰り返しの「元」は移していません。旧と新の両方が生成すると二重になるためです。
`admin-tasks.html` の「繰り返す」から作り直してください。

作り終えたら、**旧側の繰り返しを止めてください**（旧画面で「元」を消す）。
止めないと、旧の一覧に毎月増え続けます。

### 4. 旧画面をどうするか

しばらくは残して、過去の完了タスクの参照用にしてください。
新しい側で回っていることが確かめられたら、旧画面に
「タスクはグループウェアへ移りました」と出して入口を閉じます。
