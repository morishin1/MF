# ENGER 共通ログイン・営業/パートナー商談UI 要件追補（2026-11-15）
## 目的
既存の **https://enger.jp/business/login** を、企業担当者・営業社員・外部営業パートナー共通の入口として使う。**別のログイン画面・商談ナビは新設しない**。見た目は現行ENGER BUSINESSに揃え、ログイン後は利用権限だけを分ける。

## 画面の体験
1. 共通ログイン（企業は企業IDまたはメール、社員・パートナーはメール＋パスワード。役割選択は不要）
2. サーバ側で本人・ロール・有効期限・契約・企業割当を認可判定
3. 企業→既存ENGER BUSINESS、社員→既存Sales、パートナー→割当企業のみのSales
4. 社員/パートナーは企業詳細から既存「商談を始める」→既存6ステップ商談ナビ→結果・オファー→Office契約依頼
5. パートナーは本人のKPI・報酬見込みのみ（報酬はPhase 2）。社内は契約・参画・請求・継続支援

## デザイン指定（現行の実装を参照）
- 写真付き左側メッセージ／白い右側ログインカードを維持
- 基調：背景 #F6F3EC／文字 #3E4C5E／CTA #C0521F（hover #A34617）／入力背景 #FBF9F5
- フォント：Zen Kaku Gothic New / Noto Sans JP。白カード角丸14px、フォームの操作領域44px以上
- 法人専用の「法人ログイン」「企業（採用ご担当者）」などは「ENGERログイン」「企業・営業担当者・営業パートナー共通」に変更
- ログイン後もカード、余白、タイポグラフィ、ボタンの見た目を揃え、機能だけ権限別
- 役割選択タブ、複数のログインボタン、別ドメインへの再ログイン要求は出さない
- 既存の企業ID・パスワード導線／パスワード再設定／法人画面の深いリンクは維持

## 重要な既存実装との差分
- enger-lp `src/pages/business/login.astro` は現在企業専用。送信先 `/api/auth/login` は `variant='business'` と `isBusinessMeetingUser` の判定で社員・パートナーを拒否する。**ログインの改修が必要**。
- 社員・パートナーに `app_metadata.apps=['business']` を便宜的に付与しない（企業情報への権限越境につながる）。
- `enger.jp` と `gw.8grp.co.jp` は別オリジン。CookieやlocalStorageをそのまま使う単純なリダイレクトではMF Salesへ認証引き継ぎできない。安全なワンタイムコード交換／承認済みSSO設計、MFA継承、期限・ログアウトを必須にする。JWT・refresh token・パスワードはURLへ載せない。
- MF側で `partner_sales` の認可基盤を先に追加し、既存Sales社員権限は変えない。パートナーは担当企業だけの専用APIを使う。権限・企業割当が不明なら拒否。

## 受入テスト
- 企業担当者が現行企業IDとパスワードでログインでき、現行の企業専用ページ・商談リンクを利用できる
- 営業社員が共通画面のメール＋パスワードからSalesへ進み、従来の「商談を始める」を利用できる
- パートナーが同画面から割当企業限定のSalesへ進み、商談ナビを利用できる
- 未契約、停止、割当外企業、越境API、失効セッション、二重商談、同席、再ログイン、MFA、戻る、スマートフォンで安全に動く
- 画面上の権限分岐だけでなく、API・DBの読み書きが本人/担当企業のみに制限される

## 実装順序（提案）
1. PR1：MFの `partner_sales` 認可と既存社員非退行テスト
2. ログイン統合専用PR：enger-lpで共通ログインと本人認可判定、別オリジン認証引き継ぎを実装（権限確認ができるまでは公開しない）
3. PR2〜：企業割当、ENGERの提案可能判定、専用API、UI、商談ナビ接続、Office引き継ぎ、KPI
4. Phase 2：HRトライアル接続・報酬台帳

## 決定
共通ログインのURLとデザインは **enger.jp/business/login** を正とする。既存GWログインは他業務向けに残してよいが、ENGER営業の公式入口を増やさない。元要件の「既存GWログインから開始」の記述は本追補で置換する。
