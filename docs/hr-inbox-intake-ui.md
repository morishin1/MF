# HR採用メール新着受付：受信箱から採用管理へ（画面改修）

2026-10-24。対象は `/hr/inbox.html` と採用ダッシュボード（`/hr/applicants.html`）の入口。
Gmail取込（`docs/hr-inbox-gmail-sync.md`）は変えていない。取り込んだメールを人が確認して、応募者に登録するまでの画面と API の改修。

## 何ができるようになったか

| 要望 | 実装 |
|---|---|
| メールから氏名・連絡先が分かる | 本文・件名・返信先から **候補** を出す（`js/hr-inbox-text.js`）。取れなければ「未取得」。どれも人が直せる |
| 本文URLをクリック可能に | `http://` `https://` だけリンクにする。ほかはすべてエスケープして文字のまま（`javascript:` や HTML タグは実行しない）。新しいタブ・参照元を渡さない |
| 状態とボタンの意味 | 画面上部「状態とボタンの意味」、各ボタンの title に説明 |
| 媒体を選び、本人情報を確認して採用管理へ | 「応募者として登録する内容」で確認・修正 →［応募者として登録］で応募者を作り、メールを紐づける（サーバ側で1回の操作） |
| 選考中・業務委託・無限道場・スポット人材・終了 | 登録先で選ぶ。選考中／業務委託はここで登録できる。無限道場とスポット人材は別の入口なので案内だけ（下記）。終了は「対応終了（登録しない）」 |
| ダッシュボードに新着マークと未読件数 | 採用ダッシュボードの「採用メールの新着受付」に「新着あり／未対応 N件／未読 N件」 |

## 未読と未対応は別

- **未対応**＝状態が「新着」「確認中」。登録・対応終了するまで。全員で同じ。
- **未読**＝その人がまだ本文を開いていない。人ごと。本文を**表示できたあと**にだけ既読を付ける（取得に失敗したら既読にしない）。
- 開いただけでは対応済みにしない。登録・対応終了で一覧（未対応）から外れ、記録（状態・メモ・最終操作者・監査ログ）は残る。「未対応に戻す」で戻せる。
- 既読の表（下記 SQL）が未適用のあいだは、未読は「確認できません」と出す（0件と出さない）。それ以外の操作は使える。

## 状態

| 状態 | 意味 | 未対応に数える |
|---|---|---|
| 新着 `new` | まだ誰も対応していない | はい |
| 確認中 `review` | 担当者が確認中 | はい |
| 登録済み `linked` | 応募者に紐づけ済み（変更不可。付け替えは未実装） | いいえ |
| 対応終了 `ignored` | 登録しないと判断（**理由必須**） | いいえ |

DB の値（`new/review/linked/ignored`）と制約は db/147 のまま。画面の言葉だけ変えた（「要確認」→「確認中」、「対象外」→「対応終了」）。

## 安全のための決まり

- **通知元と本人を区別**：媒体の通知専用アドレス（no-reply 等、Wantedly などのドメイン）は本人のメールとして扱わない。返信先・本文のメール欄・個人の差出人だけを候補にする（どれも「未確認」表示）。
- **登録前にメールを処理済みにしない**：応募者の登録に成功したときだけ「登録済み」にする。入力エラー・重複で止まったときはメールはそのまま。
- **重複候補**：同じメール・同じ氏名・似た氏名の応募者（無限道場・終了した人も含む）を出す。本人なら［この人に紐づける］。別人なら「すべて別人であることを確認しました」に印を付けてから登録できる。サーバも同じメール・同じ氏名を調べ、画面で見せていない候補があれば止める（409）。
- **二重クリック・同時操作**：画面が見ていた版（`updated_at`）を送り、サーバで「その版のときだけ」札を取る。2回目・別の人の同時操作は 409 で止まる（応募者は1人だけ）。
- **登録だけ成功／紐づけ失敗**：応募のタイムラインに「受付ID」の目印を付けて登録する。再試行すると、新しく作らず、その応募者に紐づけ直す（二重登録しない）。
- 応募者の登録は、手入力の登録と同じ処理（`lib/hr-applicant-create.js`）。入力検査・担当・給与の扱い・RLS（利用者の権限）は同じ。

## 登録先ごとの扱い

| 登録先 | この画面で | 補足 |
|---|---|---|
| 選考中（通常の採用） | 登録できる | 応募形態は空（選考中タブ） |
| 業務委託 | 登録できる | 応募形態「業務委託」（業務委託タブ。条件提示で変わることがある） |
| 無限道場 | 登録できない | 無限道場の新規登録は LP からのみ（`lead_category=mugendojo`）。登録済みのリードがあれば紐づける |
| スポット人材 | 登録できない | `gw_hr_spot_talents`・`/hr/spot.html` で別管理。そちらで登録し、このメールは理由を書いて対応終了にする |
| 終了（登録しない） | — | 「対応終了（登録しない）」で理由を残す |

「選考中」「業務委託」「無限道場」「終了」は応募者一覧のタブ（`lib/hr.js` `listTabOf`）の区分。進捗の `status` を上書きして区分を表すことはしていない。
