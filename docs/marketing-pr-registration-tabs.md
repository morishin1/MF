# Marketing PR作成：5つの小タブ→下書き保存→プレビュー→社内本登録

更新：2026-10-25。PR #199 のデザインを継承した確認用変更。PR TIMESやSNSへの外部配信は含めない。

## 画面

- Marketing上位4タブは「ダッシュボード / PRを作る / 拡散する / 効果を分析」。PR画面内だけ次の5つを切り替える。
- **基本情報**：リリース種別、タイトル、サブタイトル。
- **発表内容**：概要、背景、特徴最大3件、今後の展望。
- **開催・提供情報**：種別に応じた日時、会場、料金、対象、提携先、URL。
- **会社・問い合わせ**：会社概要、連絡先。会社名は編集可能。
- **画像・仕上げ**：画像の名前・説明、最後に下書き保存ボタンとプレビューを見るボタン。
- プレビューはPR TIMES用の全文。最終入力後だけ開き、修正が必要なら元の小タブに戻る。
- プレビュー確認後のボタンは「内容を確認して本登録」。未保存なら無効。保存と本登録は社内登録であり、PR TIMES掲載ではない。
- 以前の『発信・制作の確認画面』『既存8spでPR草案を作る』ボタンはPRタブから削除。

## 保存・本登録のAPI（開発用）

- GET /api/marketing/pr-drafts：本人の草案・本登録の最大40件。
- GET /api/marketing/pr-drafts?id=<uuid>：本人の1件。
- POST action=save：社内PR原稿の下書きを新規またはversion条件で更新。内容はSQL tableのpayloadに記録。
- POST action=register：本人によるプレビュー明示確認、既存下書きのversion一致、必要項目の検査後に社内本登録。
- 原本テーブル：gw_marketing_pr_drafts（テナント、作成者、状態、version、payload、登録時刻）。SQL db/proposal_marketing_pr_drafts.sql は**未適用**。
- 権限：認証済みかつMarketing利用権限のユーザーのみ。さらに本人作成の草案だけ閲覧/更新。RLS有効でauthenticatedの直接権限なし。
- SQLが未適用なら画面は『社内保存は準備中』と表示して保存を無効化。プレビューの閲覧のみ可能。完了を偽装しない。
- 登録後は上書き不可。公開済みの扱いではなく、別途PR TIMESへの入稿・媒体への配信が必要。
- 入力画像は実ファイルを保存せず、ファイル名・説明・サイズのみ。メディア保存は別改修。

## SNSはAPIを使わず手動シェア

- PR TIMESまたは自社記事の公開済みURLを入力し、Xの投稿画面を開くか紹介文とURLをコピーする。
- Instagramはストーリーズのリンクスタンプ用URLと投稿用紹介文を別々にコピー。キャプションのURLをクリック誘導とは扱わない。
- Facebook、LINE、ブラストメールもPRリンクと説明文をコピーし、各サービスの正規画面から担当者が送信。
- UTMは媒体×施策ID。自社GA4で測るなら自社ページをリンク先とする。PR TIMES上のページPVは自社GA4では測れない。
- 外部APIトークンや自動投稿・課金なし。公開/送信の成功実績はまだ未接続。

## 本番移行の受入条件

1. 5つの小タブ間で入力値を失わず、縦長フォームに戻らない。
2. 最終タブ以外にプレビューボタンを出さず、必須項目の不足を伝える。
3. 保存は未適用SQLで確実に無効。本登録は保存済み・version一致・本人権限・確認済みの場合だけ。
4. 登録成功と外部公開・SNS投稿成功を混同しない。登録の二重クリックや競合は409で止める。
5. X共有は外部の投稿作成画面を開くだけ。InstagramはURLコピーと紹介文コピーを分ける。
6. PreviewのブラウザUI、スマホ、API unit、SQL/RLS、元PR #199との差分を確認。

外部配信・本番SQL実行・本番マージは別承認とする。
