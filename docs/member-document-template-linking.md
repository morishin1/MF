# Office・KEIEI 書類ボタンと「社内文書・雛形」の連携

## 背景（2026-11-08）
本番DBを読み取り確認した時点で、社内文書は18件（うち格納ファイル8件）、電子契約の雛形3件、差し込み雛形0件。必要な書類の雛形は揃っていなかった。

## 今回の実装
- すべての書類ボタンのモーダルに「本人に渡す雛形」を表示。雛形は社内文書（ライブラリ）、社内文書の「雛形」タブ、電子契約の雛形、官公庁の公式様式、既存の正式手続きから解決する。
- 既存データは複製しない。『どのライフサイクル書類にどの雛形を使うか』を `gw_member_doc_template_links` に格納。Office人事・KEIEIのみ参照/変更。RLS有効、一般ログインの直接参照不可。紐づけ変更は監査ログへ。
- 雛形の `source=general` はモーダル内でプレビューして、社員情報を差し込み、Wordでも開けるRTF形式で保存。RTFはダウンロードファイルなので本人へ添付で渡せる（自動メール送信ではない）。
- `source=library` は権限を確認してPrivate Storageを短時間URLで開く。公開済みの社内文書のみ、ログイン済みメンバー向けリンクをコピーできる。署名URLを恒久共有リンクとして流用しない。
- `source=sign` は `admin-esign.html?tab=send&employeeId=...&templateId=...` に移動し、選択した雛形で正式に署名依頼を組み立てる。白紙の承諾済みPDFや電子署名済み扱いはしない。
- `source=official` は国税庁・厚生労働省の最新版様式の公式ページを別タブで開く。
- `source=original` は本人・前職・保険者等が発行する書類。会社が偽の雛形を作成しない。
- 関連資料の例：規程等確認書の雛形と、社内文書に既存登録された「就業規則」を別々にリンク。
- 社内文書の雛形編集画面で「社内確認前／配布承認済み」を切り替えられる。未確認の間はユーザーへの配布を推奨せず、「確認用Word」を保存できる。

## 追加した社内確認前の雛形（12件）
職務経歴書、ITスキルシート、給与・報酬振込口座届、入社基本情報届、緊急連絡先届、社内規程等確認書、業務委託基本契約書（法務確認用）、契約更新覚書（法務確認用）、退職届、業務引継ぎチェックシート、貸与品返却確認書、退職時機密・資料返却確認書（法務確認用）。

登録場所は社内文書ページの「雛形」タブ（`gw_doc_templates`）。新規作成用のSQLは `db/166_member_document_template_drafts.sql` で、冪等で既存雛形を上書きしない。**すべて初期状態は社内確認前**。

## 重複作成しない雛形と原本
- 労働条件通知書・雇用契約書：既存の電子契約「労働条件通知書 兼 雇用契約書」を優先。厚労省の2026年10月以降の様式も参照。
- 秘密保持・誓約：既存の電子契約雛形を利用。
- 扶養控除等申告書：国税庁の公式ページ（年次で更新されるためPDFの年分を固定しない）。
- 内定通知・本人承諾：HRの正式な発行・承諾処理。
- 年金手帳／基礎年金番号、雇用保険被保険者証、前職の源泉徴収票：本人や発行元から原本を受領。
- 退職証明書、退職時源泉徴収票、離職票、資格喪失証明書：Officeの正式な退職・労務発行フロー。
- その他の任意書類：共通雛形を強制せず、必要時に適切な書類名でリンクする。

## 運用・検証
1. Officeの契約・書類一覧からメンバー → 書類ボタン → 「本人に渡す雛形」。
2. 雛形が登録済みなら内容を確認。社内確認前のものは正式配布前に承認する。
3. 「社内文書と紐づける」で既存文書、差し込み雛形、電子契約雛形を選び保存。リンク先はテナント内で検証する。
4. 雛形が存在しなければ「社内文書で雛形を作成」を開く。書類キーを持った状態で雛形を保存し、ボタンから自動的に参照できる。
5. 採用書類・提出原本・署名済み契約は別の社員個人データなので、雛形の選択・ダウンロードだけでは提出済み・署名済みに変更しない。
6. 本番マージ前に、Office/KEIEIの認可、他テナント不可、一般メンバーによるAPI拒否、PDF/RTFダウンロード、社内文書への正しいリンク、ドラフトの承認操作を実画面で確認する。
