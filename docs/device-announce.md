### なぜ WEB利用が取れていないか

組み立て（GitHub Actions「EIGHT Agent を組み立てる」）は通っています。
ところが**配る側の手順が、一度も実行されていません**。

直近の実行（run #4 / 2026-09-14）で、次の工程がすべて `skipped` になっています。

```
Storage に置く場所をもらう      skipped
Storage へ上げる                skipped
更新の署名を作る                skipped
配れる状態にする                skipped
ブラウザ拡張を置く              skipped   ← ここ
```

止まっている理由は、`agent-build.yml` の「配る支度ができているか見る」が
次のどちらかで手前に落ちているためです。

- `publish` を `true` にせずに実行した
- Secret が足りない（`DEVICE_RELEASE_TOKEN` / `AGENT_UPDATE_PRIVATE_KEY`）

`AGENT_UPDATE_PRIVATE_KEY` については、それを作るワークフロー
「EIGHT Agent 更新鍵を初期化」の実行回数が **0回** です。つまり鍵がまだありません。

結果として `https://mf.8grp.co.jp/ext/eight-ext.crx` と `/ext/updates.xml` は
中身が無く、拡張をブラウザに入れる道がありません。
マイページの「会社PCの設定が終わっていません」を押しても、入れられるものが置かれていない状態です。

### WEB利用を動かすのに要ること

1. GitHub → Actions →「**EIGHT Agent 更新鍵を初期化**」を1回だけ実行
   → 出てきた**公開**鍵を Variables `AGENT_UPDATE_KEY`、**秘密**鍵を Secrets `AGENT_UPDATE_PRIVATE_KEY` へ
2. Secrets に `DEVICE_RELEASE_TOKEN` を入れる（サーバ側の環境変数と同じ値にする）
3. 「**EIGHT Agent を組み立てる**」を **publish = true** で実行する
4. 拡張をブラウザへ入れる道を決める
   —「拡張を入れるだけ」で回す設計だが、Chrome / Edge は社外の `.crx` を手で入れさせない。
   実際には `ExtensionInstallForcelist` をポリシーで配る必要があり、いまそれを配れるのは EXE だけ。
   **ここが決まらないと、拡張中心の運用は始まりません。**
5. `db/064` と `db/067` を適用する（未適用なら。利用停止・紛失・削除と、
   拡張が外れたことの検知がこの2つに載っている）

4 が決まるまでは、下の文章だけを送ってください。

### 登録画面から、説明を全部外した

`https://mf.8grp.co.jp/pc` には、記録する内容の説明を置いていません。
押すボタンも「内容を確認しました」から「**この端末を登録する**」に変えました。
見せていないものを「確認しました」と押させると、その記録が何を指すのか分からなくなるためです。

**周知は、この文書の文章を送ることで行う形になりました。** 画面は登録だけを引き受けます。

なお文そのものは残してあります（`api/devices/me.js` の `NOTICE`）。
マイページの「端末管理について」と、下の文章がこれを使います。
言葉づかいの約束（監視と言わない・同意を求めない・取っていないものを取ると言わない）は
`test/ui/noticeshot.mjs` の「周知の文」で見張っています。

WEB利用の行については、`WEB_AREA` として分けてあり、
その端末で拡張が実際につながっているときだけ付きます（`test/dvapitest.mjs` の7件）。

## 1. 送るリンク

```
https://mf.8grp.co.jp/pc
```

押すと、その端末の登録画面（`device-consent.html`）が開きます。**配るものはありません。**

押したときに何が起きるか：

1. ログインしていなければ、**その画面のままログイン欄が出る**
   （別の画面へ飛ばされないので、ログインすると続きから始まります）
2. 画面を開いた時点で、**その端末が台帳に載る**
3. 「**この端末を登録する**」を押すと、その日時が残る

**押すまで、利用時間は1分も数えません。** 押した人・押していない人は、
管理画面（`admin-devices.html`）で「確認待ち」として分かります。

> **画面には、記録する内容の説明を置いていません。**
> 以前は画面に全部出していましたが、外しました。
> そのため、**何を記録するかを伝えるのは、下の文章だけになりました。**
> リンクだけを送って本文を省くと、誰にも何も伝えないまま登録させることになります。
> **リンクは、必ず下の文章と一緒に送ってください。**

スマホから押しても同じように動きます。端末ごとに1回ずつ押してもらう形なので、
会社PCとスマホの両方で社内システムを使う人は、両方で押すことになります。

> リンクを配るだけでも意味があります。**押した瞬間が、管理されていると分かる瞬間**です。
> 画面を開いただけで黙って記録が始まる作りにはしていないのは、そのためです。

## 2. そのまま送れる文章（いま送ってよいぶん）

> **件名：社内システムに入っている端末の記録について**
>
> おつかれさまです。
>
> 社内システム（mf.8grp.co.jp）に、**どの端末から入っているか**を台帳として記録します。
> 情報セキュリティ・業務管理・労務管理のために、会社として行うものです。
>
> **目的は、会社のパソコン以外から社内の情報が見られていないかを確かめることです。**
> 退職した人の端末がまだ入れてしまう、といったことに気づけるようにするためのものです。
> 働きぶりを点数にしたり、評価に直接使ったりはしません。
>
> **記録すること**
>
> - その端末から社内システムに入ったこと
> - その端末の種類（Windows／Mac、ブラウザの名前、画面の大きさ）
> - 社内システムを開いていた時間の、1日の合計
> - そのうち深夜・休日にあたる時間
>
> 対象は、**社内システムを開いているあいだ**だけです。
>
> **記録しないこと**
>
> - キーボードで打った内容、パスワード
> - メールの本文、チャットの本文
> - 画面の録画
> - 開いているウィンドウの題名
> - URL の全文（`?` 以降・`#` 以降は取りません）
> - ページの中身、入力したフォーム、Cookie、ログインの情報
>
> **みなさん側からも見えます**
>
> 自分の端末情報は、いつでもマイページから確認できます。
> **管理者があなたの端末情報を開いたときは、その記録もあなたの画面に残ります。**
>
> **お願いしたいこと（1分）**
>
> 下のリンクを、**業務で使っている端末から**押してください。
>
> https://mf.8grp.co.jp/pc
>
> 1. リンクを押す（ログインしていなければ、その画面でログインしてください）
> 2. 「**この端末を登録する**」を押す
>
> それだけです。入れるもの・落とすものはありません。
>
> **2 を押してもらうまで、利用時間は1分も数えません。** 押した日時が記録として残ります。
> 押していない端末は「確認待ち」として残り、こちらから声をかけることになります。
>
> 押したあとは、端末に分かりやすい名前を付けたり（例:「事務所のノート」）、
> 自分の端末の一覧や、管理者がいつ自分の端末情報を見たかを確かめたりできます。
>
> **業務に使うパソコンについて**
>
> 会社の業務、社内システムへのアクセス、会社データの閲覧・保存・編集は、
> **原則として会社貸与PCを使用してください。私物PCでの業務利用は禁止します。**
> やむを得ず私物PCを使う必要があるときは、**事前に管理者の承認**を受けてください（期限つきです）。
>
> 端末を台帳から外すのは管理部です。返却のときにこちらで外します。
>
> 内容についての質問は、人事・管理部までお願いします。

## 3. 聞かれたら、こう答える

| 聞かれること | 答え |
|---|---|
| 断ることはできますか | 会社ルールとして行うものなので、解除はできません。内容の質問は人事へどうぞ |
| 何を見ているか全部分かるの | いまは、社内システムを開いた事実とその時間です。打った内容・本文・画面の中身は取っていません |
| 私物のスマホで見てもいいの | 業務は原則、会社貸与PCです。必要な事情があれば事前に相談してください |
| 家のパソコンから入ったら | 台帳に無いパソコンとして印が付きます。事情を確認させてください |
| 押さないとどうなる | 「確認待ち」として残り、こちらから声がかかります。押すまで利用時間は数えません |
| 自分で端末を外せますか | 外せません。返却のときに管理部が外します |
| 見ているサイトも分かるの | **いまは取っていません。** 取るようになるときは、事前に改めてお知らせします |

最後の行を落とさないでください。あとから WEB利用を足すときに、
「前は取っていないと言っていたのに」を防げるのはこの1行だけです。

## 4. まだ送らない文章（拡張を配れるようになってから）

WEB利用を取り始める日が決まったら、上の文章に**差し替えではなく追加**で送ります。
文面は `docs/device-guide-for-members.md` の3章にあります。

送る前に、次の2つが済んでいることを確かめてください。

- **端末管理規程（または就業規則）に書いて周知してある**
  WEBの利用状況を記録することは、書いていないまま始めてよい話ではありません。
- 社労士の確認が済んでいる

しきい値（何分から要確認か）・検知条件・判定基準は、社員向けには出しません。
聞かれたら「情報セキュリティ上の理由から公開していません」と答えてください。
はぐらかしているのではなく、避ける方法を配らないためです。
