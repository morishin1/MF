# 二段階認証（MFA）は任意のセキュリティ設定

2026-10-01 の方針。それまでは「対象の権限は必須・2026-10-01 から強制」だった。
**必須 → 任意** への変更だけで、MFA の機能そのものは消していない。DB の変更はない。

main には、先に「必須を止める全体スイッチ」`MFA_ENABLED`（PR #54）が入っている。この変更は、その上に
「必須にしない間の画面」を、任意のセキュリティ設定として整えたもの（スイッチは残す）。

## 決めたこと

| | |
|---|---|
| 必須にするか | **誰にも必須にしない**（経営者・人事・管理者・社労士も）。`MFA_ENABLED` が "true" のときだけ、これまでどおり止める（再開用） |
| 2026-10-01 以降の強制 | **しない**（`MFA_ENABLED` が true でない間） |
| 登録していないこと | エラー・警告にしない（共通ヘッダの帯も、マイページの必須・期限の案内も、`/keiei` の「リスク」にも出さない） |
| 登録する機能 | **残す**。マイページの「二段階認証（任意のセキュリティ設定）」。登録した人は、ログインのとき認証アプリの6桁を聞かれる（必須を止めている間も） |
| 自分で登録を外す | できる。直前に6桁で確かめた（aal2）ときだけ。パスワードだけで外されないため。「強制期間中は外せない」は、必須を止めている間は無い |
| owner の保護（db/099） | **そのまま**。最後の owner を外せない・owner の付与は owner だけ・乗っ取り経路の遮断は、MFA とは別のしくみ |
| 給与・個人情報を守るもの | **ロール**（`canKeiei`＝owner、`canManageHr`＝人事・管理者 など）の判定。MFA は守りに使わない |

## コードの変更点（#54 の上）

- `lib/mfa.js`：コメントだけ（`MFA_ENABLED` が true でない間は「任意」、という方針の説明）。動作は #54 のまま
  （`mfaState` は `enabled:false`・`required:false`・`blocked:false`、`requireMfa` は strict も含めて通す）
- `mypage.html`：マイページの MFA 欄を、必須を止めている間も**隠さない**（#54 では隠していた）。見出しは「二段階認証（任意のセキュリティ設定）」。
  必須・期限の案内は、サーバが `required: true` を返したとき（`MFA_ENABLED=true` に戻したとき）だけ
- `index.html`（ログイン）：登録した人には、必須を止めている間も6桁を聞く（#54 では聞かなかった。聞かないと、登録しても何も効かない）。
  登録していない人は、これまでどおりパスワードだけで入れる
- `js/layout.js`・`api/mfa.js`：変更なし（登録を促す帯は `required` が false なら出ない）

## テスト

- `test/mfatest.mjs`：#54 の「一時停止」の確認に、次を追加
  必須を止めている間もマイページの設定欄を隠さない／「任意」の文言／ログインは登録した人に6桁を聞く／登録を外すには6桁の再認証
- `test/ui/mfaoptionalui.mjs`：実際のブラウザで、役割ごとの文言・帯が出ない・登録済み・登録を外す・リセット後の再登録・スマホ幅（390/360px）。
  `required:true` を返したときだけ必須の案内が出ること

## 注意（設計上の割り切り）

- 登録した人でも、パスワードだけ（aal1）のトークンを、サーバは止めない（必須を止めている間）。ログイン画面が6桁を聞くだけ。
  二段階認証を「守りの層」に数えないのは、この方針の結果
- `/keiei`（PR #39 / #46 の中）の入口・owner のリセットは、MFA を要求しない（別 PR）
