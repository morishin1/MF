# 二段階認証（MFA）は任意のセキュリティ設定

2026-10-01 の方針変更。それまでは「対象の権限は必須・2026-10-01 から強制」だった。
**必須 → 任意** への変更だけで、MFA の機能そのものは消していない。DB の変更はない。

## 決めたこと

| | |
|---|---|
| 必須にするか | **誰にも必須にしない**（経営者・人事・管理者・社労士も） |
| 2026-10-01 以降の強制 | **しない** |
| 登録していないこと | エラー・警告にしない（マイページにも、共通ヘッダの帯にも、`/keiei` の「リスク」にも出さない） |
| 登録する機能 | **残す**。マイページの「二段階認証（任意のセキュリティ設定）」。登録した人は、ログインのとき認証アプリの6桁を聞かれる |
| 自分で登録を外す | できる。直前に6桁で確かめた（aal2）ときだけ。パスワードだけで外されないため |
| owner の保護（db/099） | **そのまま**。最後の owner を外せない・owner の付与は owner だけ・乗っ取り経路の遮断は、MFA とは別のしくみ |
| 給与・個人情報を守るもの | **ロール**（`canKeiei`＝owner、`canManageHr`＝人事・管理者 など）の判定。MFA は守りに使わない |

## コードの変更点

- `lib/mfa.js`：`needsMfa()` は常に false。`mfaState()` は `required/enforced/blocked` が常に false（`enrolled` と `verified` だけが意味を持つ）。
  `requireMfa()` は**何も止めない**（約30の API の呼び出しを書き換えずに済むよう、関数として残した）。
  `selfUnenroll()` は、6桁で確かめた（aal2）人だけ外せる（「強制期間中は外せない」は無くなった）
- `js/layout.js`：「二段階認証を〇〇までに登録してください」の帯（`mfaNudge`）を削除
- `mypage.html`：見出しを「二段階認証（任意のセキュリティ設定）」に。必須・期限・強制の文言と帯を削除。登録・解除・リセット後の再登録の導線は残す
- `api/mfa.js`：コメントだけ（動作は変わらない。登録・解除・リセットの監査ログも、そのまま）

## テスト

- `test/mfatest.mjs`：任意の方針を固定（誰にも必須でない／2026-10-01 以降も止めない／API 約30の入口が `requireMfa` で止まらない／文言に必須・期限がない／機能は残る）
- `test/ui/mfaoptionalui.mjs`：実際のブラウザで、役割ごとの文言・帯が出ない・昔の「必須」状態をサーバが返しても警告を出さない・登録済み・登録を外す・スマホ幅（390/360px）

## 注意（設計上の割り切り）

登録した人でも、パスワードだけ（aal1）のトークンを、サーバは止めない。ログイン画面は、登録した人に6桁を聞くが、
それを飛ばしてトークンを作る経路があっても、API は通す。二段階認証を「守りの層」として数えないのは、この方針の結果。
将来また必須にするときは、`lib/mfa.js` の `needsMfa`・`mfaState`・`requireMfa` を作り直す（履歴: 2026-09 の版）。
