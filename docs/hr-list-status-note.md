# HR 応募者一覧：状態選択と社内メモ

## 変更範囲

`hr/applicants.html` の通常応募者一覧に状態プルダウンと社内メモ列を追加する。
無限道場リードは専用フローのため変更しない。

- 状態の変更先は既存 `STATUS_LABEL` の通常対応状態を使用。最新詳細の `statusOptions` で確認する。
- 選択だけでは保存しない。既存 `action: setStatus` の `dryRun` で注意を表示し、明示的な保存と必要時の確認チェックを要求する。
- 通知工程（`offer_*`）・承諾済み・完了は変更先に出さない。現在値は表示する。承諾済み・完了・社員登録済みの応募者は、このプルダウンで戻せない。
- 期限超過バッジ、警告、対応期限、NEXT は既存の自動判定のまま。期限超過を手動選択の状態として扱わない。
- 状態変更の確認画面で「現在の対応を完了」を明示した場合のみ、現在の対応期限を終了する。次期限が空なら未設定、日付を指定したら新期限で判定する。チェックしない状態変更・メモ変更では期限を維持する。
- 完了を伴う状態変更は、既存 `setStatus` に `completeCurrentAction` と期待状態/期限、次期限を送る。状態と期限を同じ DB update で変更し、期待値不一致は409。差分を既存履歴/監査に記録する。
- 詳細を開く操作は応募者名セル（氏名）や末尾の矢印など通常の行領域。状態プルダウンと社内メモ列の操作は詳細を開かず、それぞれの編集に限定する。画面テストで詳細を開くときは行中央の座標ではなく氏名を明示的にクリックする。
- 社内メモは既存 `gw_hr_applicants.note`（2000文字）を使用。NEXT、面談メモ、採否判断コメントとは別。空欄で保存すると削除。
- メモを開くと最新詳細を読み、保存直前に同じ対象フィールドを再読する。他担当者の変更を検知すると保存せず開き直しを案内する。状態は保存直前に注意内容も再確認する。
- 保存中の入力・重複保存を抑止。閉じる／Escape／履歴移動後の遅延応答ではフォームを復活させない。

## 変更しないもの

DBスキーマ、認証、権限、RLS、SQL、外部メール・通知の送信処理は変更しない。
状態操作は通常 status のみ、完了を明示した場合だけ対応期限も同時更新。メモ操作は note のみを既存 API に送る。
選考段階、面談、採否判断、担当者を同時変更しない。

## 検証と限界

架空データ・モック API でのみ検証する。実応募者の更新、実メール送信、本番反映は行わない。
`test/ui/hrlisteditui.mjs` は実ブラウザの回帰テスト。実行にはローカル静的サーバと起動可能な Chromium が必要。
既存の `test/hrstatusflowapi.mjs` と `test/hrapplicantapi.mjs` が保存 API と部分更新の契約をカバーする。

完了を伴う状態・期限変更は期待値比較を同じ更新条件に含める。通常状態変更・メモ変更は既存APIを維持しており、UI の再読と保存の間の同時更新を完全には防げない。
単一の対応期限には所属工程情報がないため、過去データを推測して一括消去しない。専用フローの全自動期限終了は今回の対象外。
状態遷移の最終権限検査、警告判定は既存 API が引き続き行う。
