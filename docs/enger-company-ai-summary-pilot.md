# ENGER × Sales AI企業サマリー（クラウドAI方式）PoC実装契約

## 目的
企業サマリー作成ではなく、案件・人材の提案と商談化に使う。既存デザインを維持する。ローカルAIは使わない。

## 現状確認（2026-11-07）
- Supabase lms の public.gw_sales_companies は4,036件、site_url登録は2,711件。
- 既存 public.gw_sales_ai_analyses は0件で、営業アタック判断向けの別データ構造。混同・上書き禁止。
- ENGER DX（morishin1/enger-matching）の src/lib/business-ai.ts には gBizINFO + WebサイトのAI下書き処理がある。採用広報用の生成物を商談向けと混同しない。
- 法人番号は gw_sales_companies には存在しない。既存のENGER企業IDと照合して取得するまで名前だけで法人を確定しない。

## フロー
1. 認証済みのSales担当が企業詳細を表示: 保存済みサマリーを即時返す。GETで生成しない。
2. 未生成／期限切れの対象はバックエンドで重複防止キー (tenant_id,company_id) によりジョブ予約。通常は30日をTTLの初期値とするが、商談予定・提案中を優先する。
3. Web収集ジョブ: gBizINFOは法人番号が確定した場合のみ。サイトは許可された公開 HTTPS のみ。私用IP・localhost・メタデータIP・DNSリバインド・リダイレクト先を拒否し、レスポンスサイズ・タイムアウト・最大ページ数を制限。robots・利用規約・レート制限に従う。
4. gBizINFO/公式サイト/採用情報と、権限確認したSalesの企業紐づけ履歴・ENGERの案件人材情報を収集する。別法人・別テナントを混ぜない。
5. クラウドAIへ必要最小限の抽出情報だけ渡し、固定JSONを生成。公開情報と内部情報を別フィールドに分離。PII・パートナー名・メール本文は原則AI入力に入れない。
6. facts（出典URL・確認日付き）、hypotheses（推定）、unknowns、next_actions、summary、markdownを検証してから保存する。営業仮説から案件・人材を自動登録しない。
7. ENGER DX企業詳細／商談一覧、Sales企業詳細／商談管理は同じ企業IDの保存結果を参照。パートナー企業の権限を維持。

## UI
企業詳細の編集アクションは「企業情報MDファイル」「MDアップロード」の2つを基本とする。MDはクラウド生成の詳細と根拠を出力する。アップロードはプレビュー・権限チェック・企業ID一致・サイズ上限・確認後の取り込みが必要。AI未生成／失敗／更新日を目立ちすぎない文字で表示。既存デザインは変えない。

## 100社パイロット
- 4,036社から site_url あり・非表示でない企業のうち優先度順に100社（現行取引、商談予定、提案中を優先）を抽出。100件以上は実行不可にする。
- feature flag 既定OFF、手動実行開始、処理上限と支出上限、各社の成功・失敗・情報欠損ログ、再試行最大3回、進捗表示。
- 100社完了時に法人同定一致率、情報取得率、出典一致率、営業アクション有用率、1社当たり費用をレビュー。
- 権限・テナント分離テスト、Web SSRFテスト、タイムアウト時の冪等再試行、既存画面の回帰テスト、ブラウザE2Eを通す。
- 自動生成は初回だけではなく更新トリガーを持つが、閲覧のたびにAIを呼ばない。

## 既存実装を守る
- 既存企業マスターの status、NG、評価、アタック履歴、提案同期の判定・更新ロジックは変更しない。
- マイグレーションは db/ 配下に配置、PRプレビューで確認してから実DB適用。
- サーバ環境変数のAIキーはブラウザに露出しない。API課金の開始前に料金・上限を確認。
- 本番マージ・100社実行はE2Eと安全性の確認後。
