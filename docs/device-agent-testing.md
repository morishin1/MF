# Windows実機テスト チェックリスト

管理者PC1台で確かめる手順。**上から順に。** 途中で止まったら、そこで直す。

展開の順番は次のとおり。このチェックリストは **① の中身**。

```
① 管理者PC1台で検証   ← ここ
② 社内規程・告知の整備
③ 社員1名で2週間試験
④ 全員展開
```

> **② が終わるまで、①以外のPCには入れない。**
> 本人が「このパソコンです」を押すまでサーバは何も受け取らない作りなので、
> 押さなければデータは溜まらない。それでも、規程が無いまま人に配らない。

## 0. 始める前に

| | 確かめること |
|---|---|
| ☐ | Supabase で `db/053` → `db/054` → `db/055` を**この順で**実行した |
| ☐ | `db/check_status.sql` を貼って、053・054・055 が「✅ 適用済み」になっている |
| ☐ | mf.8grp.co.jp に管理者でログインでき、**システム管理 → 端末管理** が開く |
| ☐ | テストに使う Windows PC がある（Windows 10 22H2 以降 / 11） |
| ☐ | その PC で mf.8grp.co.jp が開ける（社内プロキシがあるなら通してある） |

**この検証では、まだ自動起動（サービス登録）をしない。**
手で `-run` して、目の前で動かすところまで。

## 1. 組み立てて持っていく

Linux / Mac で：

```
cd agent
./build.sh
```

`dist/eight-agent-svc.exe` と `dist/eight-agent-ui.exe` ができる。
この2つを Windows PC の `C:\EIGHT\` に置く（正式な置き場所は `C:\Program Files\EIGHT\`。
検証のあいだは書き込み権限の要らない場所でよい）。

| | 確かめること |
|---|---|
| ☐ | `./build.sh` が最後まで通る（テスト16件も通る） |
| ☐ | 2つの exe が `dist/` にできている |
| ☐ | Windows PC にコピーできた |

> **この段階では署名していない。** SmartScreen が「WindowsによってPCが保護されました」
> と出る。検証のあいだは「詳細情報 → 実行」で進んでよい。
> **③ の社員1名の試験より前に、署名を用意すること。**

## 2. 登録する

管理画面で **端末管理 → 登録コードを出す**。
渡す相手に自分を選び、有効期限は **1日** にする（検証用なので短く）。

コマンドプロンプト（管理者でなくてよい）で：

```
C:\EIGHT\eight-agent-svc.exe -enroll ABCD-2345-KMNP
```

| | 確かめること |
|---|---|
| ☐ | 「このパソコンを登録しました。」と出る |
| ☐ | **既定のブラウザが自動で開く**（`device-consent.html?link=...`） |
| ☐ | 開いた画面に「8GRP-PC-xx をあなたのパソコンとして登録しました」と出る |
| ☐ | `C:\ProgramData\EIGHT\identity.dat` ができている |
| ☐ | そのファイルを**メモ帳で開いて、シークレットが読めないこと**（DPAPI で包んである） |
| ☐ | 管理画面の台帳に、そのPCが **[エージェント]** の印で載っている |
| ☐ | 状態が **「本人の確認待ち」** になっている |

**わざと失敗させる**

| | 確かめること |
|---|---|
| ☐ | 同じコードをもう一度 `-enroll` に渡すと「この登録コードは使えません」 |
| ☐ | でたらめなコードでも、同じ文言で断られる（理由を言い分けない） |
| ☐ | 管理画面の **登録コード**タブに、発行者・宛先・期限・**使用日時・使った端末**が並ぶ |

## 3. 本人が確認するまで、何も送られてこないこと

**ここがこの機能でいちばん大事な確認。**

まだ「このパソコンです」を押さない状態で：

```
C:\EIGHT\eight-agent-svc.exe -status
```

| | 確かめること |
|---|---|
| ☐ | 「記録 していません（使う方が告知を確認するまで、記録は取りません）」と出る |
| ☐ | 「取っていないもの」の一覧が出る |

そのまま `-run` で10分ほど動かす：

```
C:\EIGHT\eight-agent-svc.exe -run
```

| | 確かめること |
|---|---|
| ☐ | ログに「収集していません: …（not_notified）」と出る |
| ☐ | 10分たっても、管理画面の**稼働の表に1行も増えない** |
| ☐ | `C:\ProgramData\EIGHT\queue\queue.jsonl` が**できていない、または空** |

→ ここで1件でも入っていたら、**先に進まない。** 収集の門が壊れている。

## 4. 確認して、記録が始まること

ブラウザで `device-consent.html` を開き、記録している内容を読んで
**「このパソコンです」** を押す。

| | 確かめること |
|---|---|
| ☐ | 押す前に「追加で取っているもの」（USB・アプリ・サイトの種類）が出ている |
| ☐ | 基本の告知から「入っているソフト、USBメモリ、ファイル」の行が**消えている**（入れた人には嘘になるため） |
| ☐ | 押すと「記録しています」に変わる |
| ☐ | 管理画面の状態が「本人の確認待ち」→「正常」になる |

`-run` を動かしたまま15分ほど、ふつうに PC を使う（Excel を開く、ブラウザで社内サイトを見る）。

| | 確かめること |
|---|---|
| ☐ | 管理画面 → その端末 → **パソコンの稼働** に今日の行が出る |
| ☐ | 稼働の分数が、実際に触っていた時間とだいたい合う |
| ☐ | **離席** の分数が出る（5分ほど席を外して確かめる） |
| ☐ | **よく使ったソフト** に `EXCEL.EXE` などが出る |
| ☐ | ソフトの一覧に**ファイル名が混ざっていない**（実行ファイル名だけ） |

## 5. サイトのカテゴリ（UI Automation）

**④ 全員展開の必須条件。** ここが通らないうちは全員に配らない。

Chrome / Edge でいくつかサイトを開いて、10分ほど置く。

| | 確かめること |
|---|---|
| ☐ | 管理画面の **サイトの種類** に「業務」「調べもの」などが出る |
| ☐ | github.com を見たあと「業務」が増える |
| ☐ | x.com を見たあと「SNS」が増える |
| ☐ | **URL もサイト名も、画面のどこにも出ていない** |
| ☐ | Firefox でも取れる（取れなければ、そう記録しておく） |

**わざと確かめる（いちばん大事）**

| | 確かめること |
|---|---|
| ☐ | アドレスバーに検索語（例：`新宿 ランチ おすすめ`）を**入力した状態**で1分置き、その語がどこにも送られていない |
| ☐ | `https://example.com/orders/12345?customer=yamada` を開いて、**`example.com` しか残っていない** |
| ☐ | Supabase の `gw_device_web_usage` を直接見て、`category` 列に6語（work/research/sns/video/shopping/other）**以外**が無い |

```sql
select distinct category from public.gw_device_web_usage;
```

→ ここに URL やホスト名が出たら、**全員展開を止める。**

**取れなかった場合**

カテゴリが1件も増えないときは、`vtElementFromHandle` などの vtable の番号か、
アドレスバーの探し方が実機と合っていない。
`agent/cmd/eight-agent-ui/uia_windows.go` の頭にある番号と、
`FindFirst` の条件（最初の Edit を拾っている）を見直す。
**アプリ名と稼働時間は、これが取れなくても動く。**
カテゴリだけ諦めて ③ に進む判断もある（そのときは規程からもカテゴリの行を外す）。

## 6. USB・ソフトの出入り

| | 確かめること |
|---|---|
| ☐ | USBメモリを挿す → 数分後、**できごと**に「USB接続」が出る |
| ☐ | 抜く → 「USB取り外し」が出る |
| ☐ | **マウスやキーボードを挿しても、アラートは出ない**（大容量記憶装置だけ） |
| ☐ | 何かソフトを入れる → 「ソフトのインストール」が出る |
| ☐ | 設定タブの「入れてはいけないソフト」に、いま入れたソフトの名前の一部を足す |
| ☐ | もう一度入れ直すと **「重大」** のアラートが出る |
| ☐ | できごとに**ファイル名やフォルダのパスが混ざっていない** |

## 7. 通信が切れても止まらないこと

`-run` を動かしたまま、PC の Wi-Fi を切る。10分ほど使う。

| | 確かめること |
|---|---|
| ☐ | エージェントが落ちない（ログに「送れませんでした（溜めておきます）」が出る） |
| ☐ | `queue\queue.jsonl` の行が増えていく |
| ☐ | Wi-Fi を戻すと、次の送信で溜まったぶんが届く |
| ☐ | 管理画面で、**同じできごとが2行に増えていない**（seq で1行にしている） |
| ☐ | 届いたあと `queue.jsonl` が空になる |

---

## 8. 未通信になることの確認

`-run` を **Ctrl+C で止める。** そのまま翌日まで置く。

| | 確かめること |
|---|---|
| ☐ | 24時間後、管理画面の状態が **「未通信」** になる |
| ☐ | 一覧の**いちばん上**に出る（未通信は上に並べている） |
| ☐ | 「未通信」タブで絞り込める |
| ☐ | 「ソフトが止まっているかもしれません」と添えて出る |
| ☐ | アラートに `agent_silent`「24時間以上、記録が届いていません」が1件出る |
| ☐ | 翌日また止まったままでも、**アラートは1日1件**（増え続けない） |

> 夜間バッチ（`/api/cron/devices`、毎日 03:20 JST）が出す。
> すぐ確かめたいときは `CRON_SECRET` を付けて手で叩く。

## 9. 管理者の操作

| | 確かめること |
|---|---|
| ☐ | **使う人を変える** → 状態が「本人の確認待ち」に戻る |
| ☐ | 変えたあと `-status` が「記録していません」に戻る |
| ☐ | **紐付けを解除** → ブラウザの行が、PCの下から出て別行になる |
| ☐ | 解除しても、**両方の記録が消えていない** |
| ☐ | **停止する** → `-status` が「このパソコンは管理者が停止しています」 |
| ☐ | 停止中は稼働の表が増えない |
| ☐ | **再開する** → また記録が始まる |
| ☐ | **使用終了にする** → エージェントが 403 を受けて「登録し直しが要ります」と出て止まる |
| ☐ | 詳細に「管理者の操作」の行が出る（いつ・誰が・何をしたか） |
| ☐ | 組織設定・ログ に `device.assign` `device.unlink` が残っている |

## 10. 本人から見えること

本人（＝この検証では自分）のマイページで：

| | 確かめること |
|---|---|
| ☐ | 「会社のパソコン」に、このPCが出る |
| ☐ | 自分の稼働時間が出る |
| ☐ | **「自分の記録を見た人」に、さっき管理画面で開いた自分が出ている** |
| ☐ | CSV を書き出すと、それも閲覧履歴に残る |
| ☐ | タスクトレイ代わりの `http://127.0.0.1:14812/` が開き、記録している内容が読める |

→ 閲覧履歴が残っていなければ、**片側だけ透明な仕組みになっている。**
そのまま人に配らない。
