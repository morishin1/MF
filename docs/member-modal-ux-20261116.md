# メンバー管理：一覧・モーダル・商談アカウント

## 変更後の操作

- 一覧に基本区分（トライアル／試用期間／通常）と業務上の役割（エージェント／社内営業）を併記する。部署・雇用区分と権限を混同しない。
- 契約・書類はSVGアイコンと登録状況へ集約し、クリックで既存の原本確認・アップロードモーダルを開く。
- PCは幅固定の一覧、狭い画面はカードへ切り替える。書類やナビゲーションを横スクロールしない。
- メンバー追加で基本情報・基本区分・エージェント役割を設定。登録結果のモーダルにID、初期パスワード、ログインURL、次の設定を表示する。
- 一覧の「パスワード変更」から共通Authのモーダルを開く。閉じたらパスワード表示とコピー用の値を消す。
- エージェント設定は一覧からモーダルで開き、役割付与→担当企業→契約・NDA確認→利用開始の順で操作する。
- 共通ログインは https://enger.jp/business/login 。担当企業から商談6ステップ、保存・再開、結果・NEXTのSales引継ぎへ進む。既存の enger-lp #311 の商談実装を再利用。

## データとリリース順

1. `supabase/migrations/20261115222806_member_engagement_stage.sql`（手動運用用の同一SQLは `db/183_member_engagement_stage.sql`）を適用。
2. アプリをデプロイ。

`gw_employees.engagement_stage` は表示・管理専用の nullable な列。既存行は書き換えず、未指定なら連携済みHRの採用区分・有効契約の試用期間を参照する。手動指定はそれを上書きし、通常へ移行できる。読取失敗は「区分要確認」とする。APIは管理者・MFA・経営者保護を再利用。DBトリガーでも本人による直接変更を拒否する。認証・雇用・給与・商談認可の条件には使用しない。

ロールバックはアプリのrevert。追加列は残しても旧アプリに影響しない。ENGERの契約・NDA・担当企業スコープと本人認可は維持する。
