# MF グループウェア UI/UX統一計画 v1.0

## 決定事項
- **HR／Salesが先行しているデザインを社内サービスの共通基準とする。**
- Officeの既存業務カレンダー等は独自の業務機能を維持しつつ、同じフォント・アイコン・カード・操作規則にする。
- 初期段階はメンバー向け画面に限定。Office・KEIEI・HR・Salesの権限／API／DBは変更しない。
- PCでは既存の左メニューを維持。スマホでは下部タブを維持し、段階的にユーザビリティを検証する。
- スクロールを増やさず、主要操作と要確認件数を先に、任意の詳細は折りたたむ。
- 本番マージ前にPC（1440px）・スマホ（390px）の表示を最低限検証する。

## Phase 1（このPR）
- 新規 `css/member-design.css` を **`body.gw-member-ui` に限定**して適用。
- `home.html`、`tasks.html`、`nippo.html`、`messages.html`、`menu.html`、
  `timecard.html`、`career.html`、`mypage.html`、`notices.html`、`schedule.html`
  に同じ基盤を読み込む。
- `js/layout.js`、`css/app.css`、`css/layout.css` は変更しない（共有ファイルの全画面キャッシュ更新を避ける）。
- フォントが失敗してもアイコン名が画面を押し広げないよう幅を固定。
- PCは本文が左メニューに重ならない、スマホは左メニューを非表示にして下部タブを残す。
- 静的テストとPlaywrightのPC・スマホ表示テストを追加。

## Phase 2（本PRのPreview確認後、別PR）
- カレンダー機能のPR #138を最新のUI基盤に取り込み、Officeの月間カレンダー部品を共通化。
- `/calendar.html` の自分／全員、月／週／日、日報の翌営業日予定必須化を維持する。
- 月間7列・アイコン・ドロワー・時間割の詳細AIレビューを実機で検証。
- #138 と Phase 1 が競合するHTMLは **新しいデザインのlinkとbodyクラスを残して調整**する。

## Phase 3
- Office/KEIEIを同一のデザイントークン・業務別コンポーネントへ段階的に整理。
- カード、一覧、入力フォーム、モーダル、通知、ページタイトルの統一。
- レスポンシブの崩れ、横スクロール、権限ごとのメニューを継続テスト。
