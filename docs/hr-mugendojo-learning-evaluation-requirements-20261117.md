# HR「育成・評価」要件定義 v1.1 — 無限道場参加アイコン追加

制定日：2026-11-17
対象：株式会社エイト グループウェア HR（応募者一覧／詳細／育成・評価）と無限道場 LMS

## 目的

CEO REVIEWを独立した学習確認画面として利用しない。HRで「誰が無限道場に取り組んでいるか」を一目で判別し、2週間の学習・実践成果・担当者の評価を把握する。採用の最終決定操作は別扱いとする。

## HR応募者一覧「書類」列に無限道場アイコンを追加（今回の追加要件）

- 履歴書・職務経歴書・スキルシート・内定通知・契約書のアイコン列の**末尾**に、区切りを入れ「school」（無限道場）アイコンを**1つ**表示。
- **ON（押した状態）**：濃色・選択状態。意味は「HR担当者が無限道場を開始したことを確認済み」または「LMSで学習開始が確認済み」。
- **OFF（未選択）**：薄いグレー。意味は「HRで未開始として登録」。LMSの情報が取得できないときは OFF と断定せず、「未確認」を別途表示する。
- 画面操作は**アイコンを1回クリック → ON/OFFを保存**すること。行クリックの応募者詳細を開かず、別人の設定を変えない。
- `aria-pressed`、`aria-label`、マウスオーバー時の説明文に「無限道場：実施中（確認元：LMS／HR、確認日時）」または「未開始」／「未確認」を明記。色だけで判断させない。
- 更新成功後、その行だけ状態を同期し、失敗時は変更前に戻してエラーを表示。採用区分・選考ステータス・契約・本人への通知は変えない。
- **書類列の見た目に置くが書類種別としては扱わない**。書類提出数・不足警告・書類アップロードAPIには混ぜない。
- HR担当者の操作で記録したON/OFFには、設定者・更新日時・根拠種別（手動／LMS）を残す。表示のみ可能な人は操作不可。実際の操作権限はサーバ側で審査。
- LMS側が`started=true`など実際の開始を返した場合は「LMS確認済み」としてON表示し、手動OFFが実際の開始を隠さない。LMSの接続失敗は「未参加」としない。
- 同姓同名やメール変更による別人の進捗混入を防ぐ。既存LMS連携はメール照合だが、本人の一致が曖昧なときは「未確認」とする。
- アイコンクリックは設定、**名前／詳細画面クリックは学習進捗を確認**。両操作を混在させない。スマホ幅でも横スクロールを発生させず、タップ対象とツールチップを確保する。

### 表示状態

| 状態 | アイコン | 明示ラベル | 根拠 |
|---|---|---|---|
| 学習開始確認済み | 強調色・ON | 無限道場 実施中 | HRの開始確認、またはLMS実績 |
| 未開始確認済み | グレー・OFF | 無限道場 未開始 | HR担当者の明示設定 |
| 未確認・連携失敗 | 中立／補足記号 | 無限道場 未確認 | 照合なし／LMS取得失敗 |

未確認を「やっていない」と誤判定しない。現在のLMS APIは体験版のみの参加・進捗に対応するため、通常講座での自動確認は通常講座APIの追加後に有効化する。

## 育成・評価画面の基本要件

1. HRの独立「CEO REVIEW」メニューは廃止し「育成・評価」に置き換える。ただし社長のみ実行可能な採用決定操作は応募者詳細に残し、権限を維持する。
2. 無限道場開始済みの人・2週間トライアル対象者を一覧表示。学習中人数、評価待ち人数、2週間の経過日数・残日数、学習進捗、課題提出、最終学習日を一覧に表示。
3. 受講者クリックで詳細モーダル：進捗%、完了レッスン／総数、課題の提出／未提出、MVV回答、AI体験、3分チャレンジ、成果物、振り返り、AI・講師のフィードバック（権限が許す範囲）を表示。
4. **14日で講座全体の100%修了を要求しない**。2週間の個別目標と講座全体進捗を分ける。7日目途中確認と14日目最終評価を設定できる。
5. HRの既存2週間トライアル評価（コミュニケーション・MVV・協力／報連相・主体性・仕事への姿勢の5項目、◎/○/△/×）を再利用。推薦・追加確認・見送り提案と最終的な採用決定は区別する。
6. LMSが学習記録の正本。HRは閲覧用サマリーを都度取得し、LMS回答本文・AI会話・非公開データを不必要に複製しない。通常講座の提出とフィードバックはLMSに既存画面があるため、必要なサマリーだけHR用安全なサーバー間APIで追加取得する。
7. データがない／未登録／未開始／取得不能／修了は区別して表示。0%は未開始の証明ではない。学習状況だけで合否を自動確定しない。

## 既存実装の再利用箇所

- HR応募者一覧の書類アイコン：`hr/applicants.html` `docsCell()`、`js/hr-applicant-list.js` `documents()`。書類配列そのものに混ぜず表示部品の末尾で追加。
- LMS体験API（HR側）：`api/hr/applicants/lms-trial.js`（GET: 本人の体験状況）、`lib/hr-lms-client.js`。
- LMS体験の正本（LMS側）：`v3-next/src/app/api/hr/lms/trial-status/route.ts`、`src/lib/hr-trial-status.ts`。
- LMS通常講座の進捗・フィードバック（講師画面）：`v3-next/src/app/mgn/teacher/students/[id]/page.tsx`。
- トライアルの既存5項目評価：`api/hr/trial-fit.js`、`lib/hr-trial-fit.js`。

## 受入条件

- [ ] HR一覧の全応募者の書類列に無限道場アイコンが1つだけあり、ON/OFF/未確認が判別できる。
- [ ] 権限ありでクリックすると対象者だけ切り替わり、サーバで保存され、画面再読み込みでも維持。
- [ ] 別テナント・権限なし・無効な応募者IDでは操作を拒否。操作の監査履歴あり。
- [ ] 学習を開始したLMSの実績があるのに手動OFFで隠せない。通信失敗時は未参加と誤表示しない。
- [ ] 既存の書類数・書類アップロード・応募者の選考・契約・通知に影響を与えない。
- [ ] アイコンを押しても詳細モーダルは開かず、学習進捗は詳細から開ける。
- [ ] 390px・1280pxで操作可。キーボード・スクリーンリーダーも状態を判別可。
- [ ] 受講中の人は、2週間目標と実際の受講進捗・人による評価を同じ詳細画面で確認可。

## リリース単位

- P0：書類列へのアイコン、参加状態の保存・一覧表示・権限・監査・UIテスト（本人の状態を勝手に変えない）。
- P1：LMS体験開始の正確な照合、育成・評価の統合一覧。
- P2：通常講座の進捗・提出・講師/AIフィードバック、7日/14日評価と個別目標の連携。

このファイルは**要件定義**であり、コード変更・DB変更・本番反映は含まない。
