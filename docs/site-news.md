# サイトのお知らせ（8grp.co.jp/news/）

mf の **業務・運営 → サイトのお知らせ**（`admin-site-news.html`）で、
自社サイトのお知らせを書き、直し、公開します。

## どこへつながっているか

```
mf「サイトのお知らせ」          事務ポータル 8/zimu/news/
        │                              │
        └──────┬───────────────────────┘
               ▼
      Supabase  public.news_articles   ←── Notion（取り込んだ記事）
               │
               ▼  毎朝 8:00（JST）GitHub Actions: news-sync
        HTML を生成（8grp-site の scripts/news-sync/sync.py）
               │
               ▼  rsync（だめなら FTPS）
          Xserver → https://8grp.co.jp/news/<slug>/
```

**表は mf で作っていません。** 事務ポータルが前から使っている
`public.news_articles`（8grp-site の `8/zimu/news/articles.sql`）に、同じ形で書きます。
だから mf 側に流す SQL はありません。表がまだ無い環境では、画面がそう案内します。

事務ポータルの画面（`8grp.co.jp/8/zimu/news/`）は、今までどおり使えます。
どちらで書いても同じ行を触るので、両方に同じ記事が並びます。

## 使いかた

| やること | どうする |
|---|---|
| 新しく書く | ［新しく書く］→ タイトル・概要・本文を入れて ［下書きとして保存］ |
| 続きを書く | 一覧の ［直す］。下書きのまま何度でも保存できます |
| サイトに出す | ［公開にする］。**次の朝8時の同期で出ます** |
| サイトから下ろす | ［下書きに戻す］。次の同期で下ります |
| 消す | 下書きに戻してから ［消す］ |

### 気をつけること

- **公開にしても、その場ではサイトに出ません。** 反映は毎朝8時の同期です。
  画面の上に「次は ◯月◯日 08:00」と出してあります。
- **公開日を先の日付にすると「公開予定」** になります。ページは作られますが `noindex` で、
  検索には出ません。プレスリリースの解禁日に合わせるときに使います。
- **公開中のものは、そのままでは消せません。** 先に下書きに戻してください。
  公開中のまま消すと、同期に「もう出さない」を伝える手がかりが無くなり、
  Notion から取り込んだ記事は翌朝また出てしまいます。
- **URL は、あとから変えないでください。** 一度公開した記事の URL を変えると、
  前の URL が 404 になります。画面も、既にある記事の URL は勝手に変えません。

### URL の決まり

種別で頭が決まります（生成スクリプトと同じ対応）。

| 種別 | URL | 一覧での表示 |
|---|---|---|
| エイトブログ／エイトコラム／社長ブログ | `blog-volN` | BLOG |
| お知らせ | `eight-news-volN` | NEWS |
| プレスリリース | `press-volN` | PRESS |
| 採用コラム | `recruit-volN` | RECRUIT |
| メディア寄稿 | `media-volN` | MEDIA |

N は記事の通し番号です。タイトルに `vol.12` と入っていれば、その番号を使います。

## 本文について

使えるのは **見出し・段落・箇条書き・太字・リンク・引用・表** だけです。
それ以外のタグは、保存のときに外れます（文字は残ります）。

これは見た目の都合ではありません。生成スクリプトは本文を
**エスケープせずにページへ入れる**（`scripts/news-sync/sync.py`）ので、
ここに入った HTML は、そのまま 8grp.co.jp で動きます。
`<script>` が1つ混ざれば、それが公開ページで動いてしまいます。

そのため mf は、**サーバ側で** 本文を削ってから保存します（`lib/site-news.js`）。
画面の「サイトでの見え方」も同じ許可リストで出しているので、
そこに見えているものが、そのままサイトに出ます。

> 事務ポータルの画面はブラウザで本文を掃除しています。画面を通らずに表へ直接書くと
> その掃除は効きません。mf 側はサーバで削るので、この口からは入りません。

## 記録

誰が何をしたかは `gw_activity_log` に残ります（`site_news.create` /
`update` / `publish` / `unpublish` / `delete`）。
表の `updated_by` には、押した人の名前が入ります。
公開にしたときは Slack にも流れます。

## 決めていないこと

- **その場で反映したい場合**：GitHub Actions の `news-sync` には手動実行ボタン
  （workflow_dispatch）があります。mf からこれを押せるようにするには、
  GitHub のトークンを mf の環境変数に入れる必要があります。要るかどうかは未決です。
- **画像**：いまは本文に画像を入れられません（`<img>` は外れます）。
  入れるなら、置き場所（Supabase Storage か Xserver か）と、
  サイト側の表示の決まりを先に決める必要があります。
