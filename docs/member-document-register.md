# Office / KEIEI 共通・メンバー契約書と必要書類の台帳

## 読み取り
社員マスター gw_employees.id を軸に、契約条件 gw_contracts、電子署名 gw_sign_requests、社労士作成書類 gw_doc_orders、入社時書類 gw_procedure_files、採用書類 gw_hr_documents と gw_hr_offers を横断して表示する。

HRの書類は応募者の社員IDが一致し、承諾・Office引き渡し済みのオファーがある場合に限り表示。名前・メールアドレスが似ているだけの自動紐づけはしない。原本をコピー・移動しない。

## ステータス
在籍区分は invited / active / leaving / left。契約書が保存されていることと電子署名済みは別判定する。電子署名済みの根拠は署名日時と署名済みPDF。契約情報だけが登録されている場合は「契約情報のみ」。
書類は「未登録」「受領・確認待ち」「確認済み」「提出記録のみ・ファイル未連携」「対象外」を区別する。未登録は、実物が未提出という断定ではない。

## 必要書類の基準
入社手続きに既存のチェックリストがあれば、その人に設定した必須・対象外を優先する。
チェックリストがない場合は既存の入社書類ルールを使い、正社員・契約社員・パート・アルバイトは「雇用契約書・労働条件通知書」「履歴書・職務経歴書」「扶養控除等申告書」を初期基準とする。業務委託は業務委託契約書。BPは所属企業契約の確認が必要と表示する。雇用区分未設定は0件完備とはしない。初期基準は人事の確認が必要で、法律上の必須書類を自動確定するものではない。

## 新規アップロード
DBファイル db/163_member_document_register.sql により専用の追記型台帳 gw_member_documents を追加。private Storage hr のテナント・社員ID別の新規パスへPDF・JPEG・PNG（10MB以内）を置く。サーバで中身とサイズ・SHA256を確認する。受領後の内容確認を別操作とし、確認しても電子署名済みには変えない。旧版は消さない。

## 権限・検証
APIはOffice人事・経営者だけが利用可能。給与・報酬を含む書類は更に給与閲覧権限を必要とする。署名付きURLは5分。マイナンバーはこの画面では収集しない。台帳はRLS有効、ログインユーザーによるData APIの直接参照は禁止。参照・保存・アップロード・確認の監査ログを記録する。

テストでは雇用区分別の必須書類・対象外・契約締結判定・HR引き渡し境界・同一社員ID・権限を確認。OfficeとKEIEIで同じ社員書類集計APIを利用する。


## 2026-11-08: 全幅表示・稼働区分・非稼働タブ
- 雇用契約のメンバー書類一覧は、Officeの共通ナビゲーションとサイドバーを維持しながら利用可能領域を幅100%にする。
- 横スクロールはせず、採用・内定・入社・在籍・退社の書類ボタンが画面幅に応じて折り返す。
- 初期タブは「稼働」（既存名簿で active のメンバーが既定）。「非稼働」「非表示」は別タブ。
- 行の3つのチェックボックスは相互排他：稼働 / 非稼働 / 非表示。選択後にサーバへ保存し、該当タブへ移動。
- 表示区分の上書きは gw_member_document_display で管理し、Office/KEIEIの共通書類台帳に反映する。初期割当：gw_employees.status が active なら working、それ以外は inactive。
- 「非表示」は書類台帳上の表示のみ。人事の社員名簿や雇用・退職・アカウント状態を変更しない。
- 変更が保存できなかった場合は元に戻し、エラーを表示する。DB未適用なら区分変更は不可。
- DBファイル db/164_member_document_display.sql は追加のみ、RLS有効、一般ログインの直接読み書きを禁止。変更は監査ログへ。
