## 導入手順

1. 既存 `db/147_hr_inbound_mail.sql`、受信台帳既読の `db/proposal_hr_inbox_reads.sql`、トライアル `db/180_hr_trial_periods.sql` の適用を確認。
2. 加算型の `db/182_hr_integrated_intake.sql` を適用。新規テーブルはRLS、本文・個人情報の読取は採用権限に限定。人物・受信解析RPCは service_role からだけ実行できる invoker 関数。
3. 開発コードをプレビューに反映。処理フラグはすべて0のまま架空データで確認する。
4. Google側で既存Apps Scriptの権限・受信アカウント・9/13/17時トリガーを確認。即時起動が必要ならGAS Webアプリと `HR_INBOX_GAS_WEBAPP_URL` / `HR_INBOX_MANUAL_SECRET` を設定する。ChatGPT側のGmail接続資格情報をアプリへ流用しない。
5. 正式な送信元ドメイン・固定tenant・通知担当の社員IDを確認し、`HR_INBOX_PROCESS_ENABLED=1`。AIを使う場合だけ `HR_INBOX_AI_ENABLED=1`。新規登録を許可する段階で `HR_INBOX_AUTO_REGISTER=1` と `HR_INBOX_AUTO_SENDER_DOMAINS` を設定する。
6. 10分ごとの `/api/cron/hr-intake` が1回最大3通を処理する。`CRON_SECRET` 未設定・不正署名なら処理しない。同一メールの有料AI再試行はしない。
7. 停止はPROCESS/AI/AUTO_REGISTERを0へ。元メール・応募・契約の履歴は削除しない。

## 検証結果と再現

- 既存Gmail署名・重複8ケース、新着受付API53ケース、書類API33ケース、従来の面談・内定・Office関連の回帰検査を実施。
- `node test/hr-intake-classifier.mjs`：推測値の拒否、広告ルール、必要最小限の入力、不明分類、1,000通分の仮想トークン料金計算。
- PGlite（ローカルPostgres WASM）で実際の新規SQLを実行し、登録・再取得・別職種・返信・広告・不足情報・予算・RLS・RPC権限を検証。架空1,000通の処理試験を含む。
- jsdomで実HTML・イベント処理を実行。一覧の列/JST時刻、既読、書類遷移、メール本文のエスケープ、分類修正のJSON、トライアルの評価ボタン、面談自動保存を確認。
- ブラウザ起動は実行環境のsocket制限で失敗。実ブラウザでの見た目・モバイル操作は未確認。`test/ui/hr-integrated-intake.mjs` をブラウザが使えるCIで実行する。
- 広範な既存Node検査にはSales等の既存失敗23本があり、最新mainの隔離チェックアウトでも再現した。本改修で変えた書類と応募者見出しの期待値は新仕様へ更新し、関連するHR/JST/スキーマ検査63本を確認した。

ローカルPostgres・DOM検証の依存は本番アプリへ追加しない。作業用prefixへ `@electric-sql/pglite@0.3.14` / `jsdom@26.1.0` を入れ、モジュール絶対パスを指定して再現できる。

```bash
HR_PGLITE_MODULE=/absolute/path/to/pglite/dist/index.js node test/integration/hr-intake-pg.mjs
HR_JSDOM_MODULE=/absolute/path/to/jsdom/lib/api.js node test/integration/hr-intake-dom.mjs
```

単価は[Anthropic公式Haiku 5.5資料](https://platform.claude.com/docs/en/models/haiku-5-5/overview)の100Kトークン以下を使用。USD/JPY=180は予算計算の仮定で実勢相場ではない。入力6,000・出力600トークン×1,000通の概算は162円。**実APIによる1,000通の料金・分類精度・失敗率は未測定**。Gmail/Vercel/Supabase等の追加課金も保証していない。
