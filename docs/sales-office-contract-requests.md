# Salesの合格 → Officeの契約書作成依頼

## 対象と現状

対象はSalesの「提案管理」で扱うENGER提案です。HR応募者の採用合格とは別です。
調査時の本番 `gw.8grp.co.jp` はVercel production/READY、
MF main `6dafa62ca3b13df595480d5ccf7b79dbe009b8e2` でした。
添付の提案管理画面を実画素で確認しました。
本番の認証後データ・実案件の操作は検証していません。
2026年10月26日、管理者が実行した前提確認65項目と適用後構成・権限確認71項目の全通過結果を確認しました。
SQLの実行は管理者の手動操作であり、このアプリの公開処理はSQLを実行しません。

## できること

1. Sales提案画面の「合格後の契約書作成」に、合格・Office未依頼・Office対応中・作成完了のカードを表示します。
2. カードを押すと、同じ判定で数えた提案・依頼一覧を表示します。元の営業一覧の絞り込みとは独立です。
3. 現在の営業担当または管理者が、契約種別・作成希望日・稼働開始予定日・依頼内容を確認して、明示的にOfficeへ依頼します。
4. Officeの「契約書作成依頼」で、担当・期限・書類管理場所を確認し、未着手→作成中→確認待ち→作成完了へ進めます。
5. Salesには同じ依頼の進捗を表示します。画面の「更新」・詳細の再表示で最新状態を取得します（リアルタイムpush更新ではありません）。
6. 取消・再依頼・再開は理由と版番号を伴う明示操作です。同じ提案で新しい依頼を重複作成しません。履歴は残します。

## 合格の意味

- ENGERの保存済み現在ステージ「合格」「面談合格」、またはシステムの合格への連携履歴だけを根拠にします。
- 成約・稼働・面談実施から合格を推定しません。
- 連携記録は受信済みの事実です。先方の最新意思や契約締結を独立に検証した意味ではありません。
- 過去記録の自動補完・合格判定・既存候補者の変更はしません。
- すでに営業終了・連絡停止・アーカイブ済みの提案を、契約依頼のために自動再開しません。
- 連携履歴が欠けている場合は未確認のままです。まずENGER側の正本と受信状況を確認します。
- 新SQLはauthenticatedユーザーによるENGER元ステージ/同期履歴の偽装を防ぎますが、適用前の既存値の正当性を保証するものではありません。

## 契約との境界

この機能が作るのは**Officeの作成依頼**であり、契約・署名依頼そのものではありません。
合格・依頼・作成完了でSalesを成約/完了に変えず、既存追客タスク・担当引継ぎを勝手に変更しません。
メール/Slack送信・自動PDF生成・署名・契約締結・課金API呼出しはありません。

契約種別は顧客向けSES契約、BP向け注文書、本人向け雇用契約、本人向け業務委託契約、
または「要確認」から明示的に選びます。「要確認」はOfficeで解決してから作成完了にします。
作成完了にはOffice担当と書類の管理場所/参照番号が必要です。
管理場所はテキスト記録であり、ファイル実在・内容・署名の検証や公開URLの取得を行いません。

既存 `api/sign/orders.js` は社員IDに紐付く人事/社労士向けの作成依頼です。
そのapprove/sendは署名依頼の外部送信を含むため、この機能から呼びません。
既存書類・現場契約へのリンクは、Officeが対象者とテナントを明示確認したときだけ設定します。
人事権限のない担当者にHR書類の機微情報を渡しません。
