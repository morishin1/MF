# 企業評価連携：有効化前の確認事項

## 現在
コード・合成データの検証段階。新連携は `COMPANY_EVALUATION_LINK_ENABLED` が両系で厳密に `1` の場合だけ動き、未設定・その他の値はOFFです。現在この設定変更は行っていません。DB適用・公開・実データ送信も未実施です。

## 追加で扱う情報と宛先
1. ENGER → 既存 `GW_SALES_BASE_URL` の `/api/sales/company-evaluations/review-snapshot`
   - 直近90日・送信日が明示された非ブラスト/未削除の提案を、企業UUID別に集計。
   - 送る項目：企業UUID、提案件数、面談到達件数、決着/面談到達/返信期限経過の件数、見送り理由不明件数、参画到達件数、対象期間、集計日時、snapshot UUID、version、全件取得済みフラグ。
   - 人材名・個人連絡先・メール・見送り理由本文・金額・利益明細は送らない。会社名照合も行わない。
   - 宛先tenantはMFの既存 `SALES_PROPOSAL_TENANT_ID` 固定。本文によるtenant指定を受け付けない。
2. ENGER → 同宛先 `/api/sales/company-evaluations/status` の個別企業読取
   - ENGERで承認済み管理者/マネージャーかつSales利用可の場合だけ、表示中の企業UUIDを送信。
   - 戻す項目：保存評価の改訂番号、下書き/確定、点数、候補/確定ランク、取引方針、判断理由、確認/更新日時、再評価必要フラグ。
   - 根拠本文5項目・個人連絡先・監査actor情報は返さない。

## 間隔と既存からの差
- 既存の毎時 `gw-sales-sync`（既存 `CRON_SECRET` 認証）に、集計送信を追加するコード。新しい予約・cron・資格情報は作らない。
- 既存の提案起票/状態読取と同じ共有HMAC鍵を使うが、専用purposeを分離する。既存purposeの署名では新endpointを呼べない。
- OFF時は追加の集計読取も送信も行わず、既存outbox送信動作だけを継続する。
- 新規用途なので、既存接続があることだけをもって有効化承認とは扱わない。

## 保存と権限
- MF 153：既存企業に紐づく評価sidecarと判断履歴。書込は認証済み・同tenantのmembership adminまたはownerをAPIで確認し、service専用atomic RPCのみ。管理者/営業マネージャーが読取可能。
- MF 154：最終集計snapshotをtenantごとに1件保持。会社別・確認種別ごとのタスク状態を継続保持（初回/最終確認/条件解消時刻）。タスク状態変化の全イベント履歴ではない。
- 確認事項は営業マネージャーの全体閲覧、一般営業は自分に既存企業owner IDで割当された項目だけ。未照合の担当と期限はNULLのまま。
- 5件/面談到達0の担当確認、10件保留審査、15件ブラスト移行審査、見送り理由確認、改善再審査。候補タスクを重複なく生成し、条件消失はcleared（人間の完了とは呼ばない）。
- 実際の提案停止、メール配信、Slack通知、企業マスタ変更、既存権限ルール変更はしない。

## 不完全・競合時
- 不明企業ID・全件未取得・件数上限・ページ重複矛盾・取得中変更を検出した場合は送信しない。
- source取得は複数REST読取であり、厳密な単一DBトランザクションsnapshotではない。keyset＋最終変更probeで保守的に検出し、審査候補にのみ使用する。
- 最大20,000提案/5,000企業。超過時は切り捨てず失敗として表示する。
- MFは時刻逆行・同一snapshot別内容・同時更新競合を拒否。ネットワーク結果不明時にその場で再送しない。
- 連携OFF/エラー/保存先未導入を0件・未評価・Dと推測しない。
