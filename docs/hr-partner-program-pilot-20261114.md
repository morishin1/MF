# HR「パートナー管理」実証版（ENGER / AIまち） — 2026-11-14

## 開発状態
- このPRは、採用HR統合改修PR #354（`feat/hr-integrated-intake-20261114`）をベースにした**レビュー用開発版**。
- **本番未反映。SQL `db/183_hr_external_partner_pilot.sql` は本番DB未適用。外部パートナー登録・支払・顧客への連絡は行っていない。**
- /hr/partners.html を新設し、既存HRナビに「パートナー管理」を追加。応募者・採用面談・トライアル・Office引継ぎは従来どおり。
- 既存の `api/partners` と `gw_partner_companies` は「BP企業」用であり、この個人・副業・フリーランス向け制度とは別。既存の `gw_hr_trial_periods`（採用選考の2週間トライアル）とも別。

## 初期提供機能
1. パートナー登録（氏名・メール・ENGER/AIまち所属・副業/フルリモート/専門業務・得意分野）
2. NDA・業務委託契約の合意文書を管理番号で確認し、稼働開始/停止
3. 事業別に仕事を登録（企業名や住民個人情報を入れず社内参照IDのみ）、計画→割当→成果提出→代表による成果承認
4. 業務ごとに収益・直接費・パートナー報酬を入力し、ENGER/AIまちの貢献利益をそれぞれ表示
5. 初期投資上限30万円、月額固定費上限5万円を**初期仮値**として設定可能（代表のみ編集）。実費と概算6か月回収に必要な月間貢献利益を表示
6. 変更履歴を内部監査テーブルとグループウェア操作ログへ記録

## 情報漏洩を防ぐ前提
- **外部パートナーマイページは未公開**。顧客名・営業リスト・住民相談原文・スキルシート・営業案件の内容をコピーしない。
- `canRecruit && canManageHr` の社内権限チェック＋Bearer JWTの認証強度 `aal2`（TOTP）をAPI全操作に要求する。パートナー登録だけではログイン資格情報を作らない。
- 4つの新表はすべてRLSを有効化。anon/authenticated/PUBLICへのテーブル権限を明示的に取り消し、サーバのservice_roleのみが処理。サーバAPIは常に tenant_id で絞る。
- データベースの新規登録・成果承認は、既存のSales・ENGER・AIまちへの書込権を付与しない。パートナー停止はHR内部の状態であり、外部システム権限停止の自動連動は**未実装**。
- 個人情報がAPIから返るので、セキュリティの事前確認が完了するまで運用しない。

## 投資判断
- 報酬・売上は実績を手動記録する。Sales・Officeからの自動同期、振込・請求・契約送信は**未実装**。
- 現時点の30万円/5万円は費用見積ではなく実証用の上限仮説であり、既存システム利用費・開発稼働を含めて実測する。
- ENGER/AIまち別に`（収益−直接費−パートナー報酬）`を算出。合算した月間貢献利益が`初期投資÷6＋月額固定費`を上回ることを6か月回収目標とする。
- 初期実証では赤字・先行投資の案件は社長による事前判断を必要とする。採算や安全性が確認できなければ拡大しない。

## 導入手順と受入条件
1. PR #354 の内容との競合を確認。HR共通ナビを変更したため、全HR HTMLのJSバージョン文字列を `20261114partner1` へ更新している。
2. プレビューでHTML表示、既存HRナビ、採用機能の回帰、PC/スマホの表示を検証。
3. DBAレビュー後に `db/183_hr_external_partner_pilot.sql` を適用する（**このPRでは未適用**）。
4. MFA登録済みのownerとhr/office担当だけが登録・閲覧でき、recruiter・sales・未ログイン・aal1・他テナントはアクセス拒否されることを検証。
5. 契約参照のないパートナーはactiveにできず、停止後の業務追加・成果変更は拒否されることを検証。
6. 事業の不一致、テナント越境、報酬二重承認、マイナス金額、価格上限超過等を拒否することを確認。
7. 監査ログ・収益計算・投資上限・ソースコード依存関係を検証。
8. 条件達成後に限って本番反映の是非を判断。初期は社内2〜3名、外部5名程度へ段階的に進める。
