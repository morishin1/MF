# 経営ハブ（`/keiei` ホーム）

`/keiei` は **経営者が「見る → 気付く → 判断する → 元システムへ行く」ための画面**です。
業務処理をここで終わらせません。各システムが正本で、`/keiei` はそれを **読んで**、数字と警告と「次の入口」を出すだけです。

| 領域 | 正本 | `/keiei` から |
|---|---|---|
| 売上・案件・請求・入金 | **Board**（外部。API 仕様は別途確認中） | いまは「未接続」の1表示。接続後に数字だけ出す（§7） |
| 採用・社員・入社手続き | HR（`/hr/`・`admin-members.html`・`admin-hr.html`） | 人数と、社長判断待ちなどの警告 → HR へ |
| 経費・会計・月次締め・月初作業 | 管理画面（`admin-expenses.html`・`admin.html`・`admin-closing.html`・`admin-month-start.html`） | 数字と警告 → 各画面へ |
| 営業活動 | Sales（`/sales/`） | ホームには出さない（新しい営業管理は作らない） |
| 給与 | `/keiei` の給与管理（`docs/keiei-pay-management.md`） | 凍結。メニューに残すだけで、ホームには金額を出さない |

このアプリの DB の**正本データは変更しません**。ホームは読み取りだけで、DB 変更・新しい表はありません。

## 1. 画面構成

メニューは3つ（＋小さな入口）。

| メニュー | 画面 | 備考 |
|---|---|---|
| ホーム | 4ブロック（§2） | 既定の画面。旧 `#dashboard` などのブックマークもここへ |
| 入社準備 | 6ステップの一覧・入社案内の作成 | 変更なし（PR #39 のまま） |
| 給与管理 | 一覧・履歴・初回候補・監査ログ・人件費の集計 | 凍結（追加開発なし）。人件費の集計へは、給与管理の一覧から入る |
| （小）設定・セキュリティ | 経営者・二段階認証・経営者の変更履歴・給与の監査ログへの入口 | メニューの下に控えめに置く。ホーム下にも小さなリンク |

### ホームの4ブロック

上から順に。**同じ事実を、2つのブロックに出さない**（各項目は today か risk のどちらか1つ）。

1. **今日の確認** … 経営者が今日、判断・対応するもの。重要度の高い順。0件なら小さく1行（大きく出さない）
2. **人・組織** … 在籍・入社予定・採用選考中・内定・入社準備未完了。給与金額は出さない
3. **お金** … Board は「売上・請求は Board 連携後に表示します」の**1行だけ**。社内の3数字（経費承認待ち・立替支払待ち・会計確認待ち）
4. **リスク・未処理** … 放置すると困るもの。重要度の高い順（重要 → 注意 → 確認）。押したら元システムへ

## 2. 各カードの参照元と遷移先

読み取りだけ。読めなかった元データは 0 にせず、`unreadable`（画面に「一部の元データを読み込めませんでした」）と `value:null`（「取得できません」）にする。

### ① 今日の確認（`block: today`）

| 項目（key） | 重要度 | 数え方 | 参照元 | 遷移先 |
|---|---|---|---|---|
| 経費の承認（代表）`expense_approval` | 重要 | 経費申請の状態が `pending_owner` の件数・合計 | `gw_expense_reports` | `/admin-expenses.html` |
| 稟議の承認（代表）`request_approval` | 重要 | 稟議・休暇申請の `pending_owner` の件数 | `gw_requests` | `/admin-requests.html` |
| 採用の社長判断 `ceo_decision` | 重要 | 応募者の状態が `ceo_decision_pending` | `gw_hr_applicants`（id・段階・状態・期限だけを選ぶ） | `/hr/ceo-review.html` |
| 入社準備（会社の対応）`onboarding_company` | 重要 | 6ステップの判定で「会社の対応待ち」の人数 | 既存の入社準備の判定（`api/keiei` の `onboarding()`＝`lib/onboard-six.js`） | `#onboarding`（/keiei 内） |
| 労働条件通知書 未公開 `notice_unpublished` | 注意 | 入社準備が未完了の人のうち、本人に公開した通知書が無い人数（電子署名の流れの人は数えない） | `gw_labor_notices`（版・公開・確認の列だけ。ファイル名・置き場所は読まない） | `/admin-hr.html`（入社管理。アップロード・公開はそこで行う） |
| 労働条件通知書 本人未確認 `notice_unconfirmed` | 注意 | 公開済みで、本人がまだ「確認しました」を押していない人数 | 同上 | `/admin-hr.html` |
| 経営判断待ちの止まっている仕事 `blocker_owner` | 重要 | 止まっている仕事のうち、経営者へ上がっている（`escalation_level = 2`）もの | `gw_blockers`（会社の社員のものだけ） | `/admin-nippo.html` |

`gw_labor_notices` が無い（`db/110` が未適用）ときは、0件とは出さず、未読込に「労働条件通知書」と出す。

| 項目（key） | 重要度 | 条件 | 参照元 | 遷移先 |

## 3. 経営設定・セキュリティ（`#security`）

主要ブロックではなく、小さな入口から入る画面。

- 経営者の一覧（在籍・ログイン可否・二段階認証の登録状況〔参考。「未設定（任意）」と出すだけで、警告にしない〕）と、警告（1人だけ）
- 経営者の変更履歴（新しい順・20件）: 経営者への追加・経営者から外した・経営者の二段階認証リセットを断った（`gw_activity_log`。この会社の分だけ）
- 給与の監査ログへの入口（`#pay-audit`。既存）
- 緊急復旧手順（`docs/keiei-owner-recovery.md`）の案内

二段階認証は任意のセキュリティ設定（2026-10-01 の方針変更。`docs/mfa-optional.md`）。未登録をリスク・警告にしない（ホームの `mfa_missing` は削除）。他の経営者の登録状況は、認証の管理用 API でしか見えない。取得に失敗したら「—」と出すだけで、警告にも `unreadable` にもしない。

## 5. UI の原則

- 見る → 気付く → 判断する → 元システムへ。ここで業務を完結させない
- 何件あるかより、**何をすればいいか**（押す先の名前を動詞つきで出す）
- 0件は大きく出さない。放置されているものを、重要度の高い順に上へ
- 給与・手当・単価の金額を出さない（応募者の給与列・契約・給与管理の表は読まない）
- 読めなかったものを、0件・問題なしにしない

## 6. 旧 API view の扱い（後方互換）

`GET /api/keiei?view=` のうち、画面（フロント）が呼ぶのは **`hub`・`security`・`payroll`・`onboarding`** だけ。
旧 view（`dashboard`・`expenses`・`revenue`・`cash`・`accounting`）は**物理削除していない**。

- 画面の呼び出しは `keiei/index.html` の `API_VIEW`（画面 → view の対応表）の1か所だけ
- 旧 view のフロントからの呼び出しが 0 件であることは `test/keieiwiring.mjs` が確かめる
- 旧 view が残っていることも同じテストが確かめる（消したときに気付くため）

**削除してよい条件**（別の作業として行う）:

1. `node test/keieiwiring.mjs` が通る（フロントの呼び出しが 0 件）
2. 本番のアクセスログで、`/api/keiei?view=dashboard|expenses|revenue|cash|accounting` の呼び出しが一定期間 0 件（リポジトリ外の呼び出しがないこと）
3. 削除するときは、`api/keiei/index.js` の `VIEWS`・ハンドラ・読み出し関数、`lib/keiei.js` の `buildDashboard`・`summarizeExpenses` などの使われなくなったもの、`test/keieiapi.mjs` の該当テストを一緒に消す

## 7. Board 接続のスロット（未実装。仕様待ち）

Board の API 仕様は別途確認中。**いまは実装しない。** ホームの `money.board` は次の形だけ返す。

```json
{ "status": "unlinked", "message": "売上・請求は Board 連携後に表示します" }
```

接続後に出す数字（経営判断に必要なものだけ）: 今月売上・今月請求・未請求・入金予定・未入金（＋必要なら案件別売上・粗利用の数字）。

- Board と同じ管理機能は作らない。案件・請求書・売上修正は Board で行い、`/keiei` は参照と判断だけ
- 読み取り専用。集計の写しは保存しない（毎回 API を呼ぶ）
- 接続情報（URL・認証）は環境変数（本番の環境変数の追加は、経営者が行う）
- 読めないときは 0 と出さず、「Board未接続」／「取得できません」

## 8. 2026-10 Phase 1：10月の目標と実績・営業ファネル・担当者別

2026-10-05 の経営方針（EIGHT 2026年10月 keiei 統合戦略 §12）にそって、ホームに2つの欄を足した。DB・権限・SQL の変更はない（読み取りだけ）。

並びは **今日の確認 → 10月の目標と実績 → お金 → 人・組織 → 営業ファネル → 担当者別 → リスク・未処理**（経営方針の「会社の状況 → 売上・利益 → 人・組織 → 営業ファネル」の順）。

ファネルは**会社（企業ID）で重複を除く**。同じ会社への2回目のアタック・2件目の案件は1社のまま。日付・月の境目は**日本時間**。

| 欄 | 数え方（今月） | 正本 |
|---|---|---|
| 接触 | 今月アタックを送った会社（送れなかったものは除く）。送信の件数を添える | `gw_sales_approaches` |
| 有効企業・本命案件 | **定義未決**（0 と出さない） | — |
| 商談 | 今月、案件ができた会社（案件の作成日。いまの段階・失注でも消えない） | `gw_sales_deals`（db/116） |
| 提案 | 今月、提案・最終調整・成約に進んだ会社（段階の記録。いまの段階では数えない） | `gw_sales_deal_history` |
| 有料契約 | 今月成約した会社（段階の記録の「成約」、または `won_on` が今月） | 同上 |
| 受注額 | 今月成約した案件の金額（案件金額）の合計。**会計上の売上・粗利ではない**（粗利は持っていない） | `gw_sales_deals` |
| 提案後の停滞 | いま提案・最終調整の案件で、**最後の動き**（その案件の段階の記録・案件の更新・その会社の営業履歴のうち一番新しいもの）から7日以上。①今日の確認にも1項目 | `gw_sales_deals`・`gw_sales_deal_history`・`gw_sales_events`（日時と会社だけ） |

- 社員本人向けの個人ダッシュボードは、`/keiei` が経営者専用のため別の作業（権限の設計が先）
