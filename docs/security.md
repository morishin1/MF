# 情報漏洩対策チェックリスト（会計士レビュー用）

多数の顧問先の財務・取引データと、各社の会計ソフト認証情報を預かるため、漏洩防止が最優先。
リスクの本丸は **①テナント間のデータ越境** と **②預かったAPIトークンの流出** の2つ。
対策は「アプリのif文」ではなく**基盤レイヤーで強制**することを原則とする。

## 1. テナント分離（越境防止）
- [ ] 全テーブルに `tenant_id` を必須化
- [ ] **Postgres RLS** で「自テナントの行しか読めない」を強制（アプリにバグがあっても越境しない）
- [ ] APIは常にログインユーザーのテナントにスコープ。クライアントから `tenant_id` を信用しない
- [ ] 高保証要件が出たら schema-per-tenant / DB-per-tenant を検討

## 2. 会計ソフトの認証トークン管理（最重要）
- [ ] OAuthトークンを**平文保存しない**（KMS/Vaultで暗号化、列レベル暗号化）
- [ ] 復号と会計ソフトAPI呼び出しは**サーバ側のみ**。クライアントに絶対に渡さない
- [ ] ソフトごとのアダプタ層で隔離（MF/freee/弥生）
- [ ] トークンのローテーション・失効・最小スコープ取得

## 3. 書類（PDF）ストレージ
- [ ] バケットは**完全非公開**（公開URLを作らない）
- [ ] アクセスは**短期(数分)の署名付きURL**のみ
- [ ] テナント別プレフィックス + Storage RLS
- [ ] 保存時暗号化（KMS）

## 4. 認証・アクセス制御
- [ ] スタッフ（多数顧客に触れる高価値アカウント）は **MFA必須**
- [ ] ロール分離（admin / staff / client）。顧問先ユーザーは自社のみ、スタッフは担当先のみ（最小権限）
- [ ] セッション管理・自動失効、退職/契約終了時の即時アクセス剥奪

## 5. AI仕訳のデータ取り扱い
- [ ] **学習に使わない / ゼロ保持(zero-retention)** のAPI設定を使用（Claude API は対応可）
- [ ] 処理はメモリ上で完結。AIへの送信内容・PDF本文をログに残さない
- [ ] 不要なPIIは可能な範囲で送信前にマスキング

## 6. 通信・保存・バックアップ
- [ ] 全経路 TLS
- [ ] DB / Storage / バックアップを保存時暗号化
- [ ] バックアップにも保持・削除ポリシーを適用

## 7. 監査・追跡
- [ ] **追記型の監査ログ**に、誰が・いつ・どのテナントの何を閲覧/送信したかを記録
- [ ] 会計ソフトへの送信は**冪等キー**で二重投入を防止し、送信ログを残す

## 8. 運用・コンプライアンス（日本）
- [ ] 個人情報保護法を踏まえた取扱い（委託先管理含む）
- [ ] データ所在地は日本リージョン
- [ ] 顧問先への利用規約・プライバシーポリシー（AI利用・第三者APIへの送信の明示）
- [ ] 投入前の**人による承認を必須**とし、誤仕訳事故を防ぐ

## 現デモ（Phase 0）の位置づけ
- 表示データは**架空のモックのみ**。実顧客データ・実トークンは一切含まない → 公開しても漏洩対象なし。
- 認証は**未実装**（デモ目的）。**実データを載せる前に、本チェックリストの 1・2・4 を満たすこと**（Phase 1）。
- 公開デプロイには内部ファイルを含めない（`.vercelignore`）。
