# AI営業 MVP — 使い方と本番への出し方

設計は `docs/ai-sales-agent-phase0.md`（PR #103）。ここは MVP で**実際に入ったもの**と、**本番に出す手順**だけを書く。

## 1. 入ったもの

| 流れ | 画面 | API | 守り |
|---|---|---|---|
| ⓪ 候補を探す | `/sales/ai.html`「企業を選んで分析」→「① AI で商材を分類して候補を探す」。登録情報＋トップページ1枚で、重点商材ごとに 0〜10 点 | `GET/POST /api/sales/ai/classify`（20社ずつ・3本並列） | 企業マスタ（提案サービス欄など）は書き換えない。結果は `gw_sales_ai_classifications`（1社1行）だけ。不正な提案サービス欄（電話番号など）は AI に渡さず印だけ |
| ① 企業を選ぶ | 候補の表で「上位20社を選ぶ」、または「② アタックリストから直接選ぶ」（1回50社まで） | `GET /api/sales/companies?queue=attack` | NG・非表示・直近30日アタック済みは候補にも一覧にも出ない |
| ② AI がサイトを調べる | 「選択した企業を分析する」→ 分析完了 | `POST /api/sales/ai/analyze`（5社ずつ） | robots.txt を守る・同じサイトの最大4ページ・社内アドレスへ行かない・ページ内の指示に従わせない |
| ③ 商材を決める | 分析結果に商材別の点数（8EC・8RENT／ENGER／無限道場×2） | 同上 | 点数は AI の項目点×配点（35/25/15/10/10/5）をサーバで計算。配点は商材ごとに変えられる |
| ④ 営業文を書く | 詳細 →「AI で営業文を作る」 | `POST /api/sales/ai/drafts` | 分析の無い・送信不可の会社には作らない。事実（出典つき）だけを根拠にする |
| ⑤ 承認する | 「承認待ち」タブ | `PATCH /api/sales/ai/drafts`（approve / reject） | 経営者・営業責任者（manager＋Salesアプリ）だけ。作った人・直した人・依頼した人は不可（API と DB の CHECK） |
| ⑥ 手動で送る | 既存のフォームアタック画面で「AI文面（承認済み）」を選ぶ | `PATCH /api/sales/approaches`（`aiDraftId`） | 最終文面（宛名・差出人・専用URL・署名）はサーバが作り直す。承認後に変わった文面は使えない。担当者が最終文面を確認するまで押せない |
| ⑦ 成果を見る | 既存の KPI・分析（アタック・クリック・返信・商談・案件） | 変更なし | AI 文面で送ったアタックも同じ `sent_at` で数える。`ai_draft_id` で AI 文面かどうかを後から分けられる |

**外部への自動送信はしない。** フォームへの貼り付け・送信は人が行う。

### 送信可否（docs §5.8）

| 判定 | 付ける人 | アタック画面 |
|---|---|---|
| 送信不可 | 規則・AI（営業お断り・自動送信禁止・サポート専用・採用専用） | 専用URLも出さない（サーバで 409）。承認者だけが理由つきで覆せる |
| 要確認 | 規則・AI の既定値（禁止の記載が無いだけでは送ってよいことにしない） | フォームで送るときは、担当者が「確認した」を押すまでコピー・送信完了を押せない（サーバも 409） |
| 確認済み | 人だけ | これまでどおり |

AI の分析が無い会社は、これまでどおり送れる。

### 費用の守り（docs §5.6）

- キーは `SALES_AI_ANTHROPIC_API_KEY` だけ（既存の `ANTHROPIC_API_KEY`・`ANTHROPIC_MODEL` は使わない・変えない）
- 呼ぶ前に予約（DB で設定行をロックして「確定＋予約中＋今回の最大額 ≤ 上限」）→ 呼んだあと実費で確定。並列でも上限を超えない（`test/sql/run.sh` の「131並列」で 20 本同時に確認）
- 月の上限 100 ドル（目標 50 ドル）・1日の上限・1日の分析社数・1時間の呼び出し数
- 自動停止：月の上限到達・直近20回で失敗5回・1時間の呼び出し数超過。再開は管理画面から人が行う
- 画面の費用は AI のトークン代だけ。Vercel・Supabase は各社の管理画面で見る

## 2. 本番に出す手順（すべてユーザーの承認が要る）

順番を守る。**PR0（#104）が先。**

1. **PR0（#104）**：`db/130_sales_access_align.sql` → `db/check_130_sales_access.sql`（❌ が無いこと）→ マージ
2. **この PR の SQL**：Supabase の SQL Editor で
   1. `db/131_sales_ai.sql` を Run
   2. `db/check_131_sales_ai.sql` を Run（❌ が無いこと）
   - 戻すとき：`db/rollback_131_sales_ai.sql`（AI営業のデータだけ消える。既存の Sales には触らない）
3. **Vercel の環境変数**（会話にキーを貼らない）
   - `SALES_AI_ANTHROPIC_API_KEY`：Anthropic で AI営業専用のワークスペースを作り、月の上限（100 ドル）を付けたキー
   - 任意：`SALES_AI_MODEL_LIGHT`（既定 `claude-haiku-5-5`）・`SALES_AI_MODEL_STANDARD`（既定 `claude-sonnet-5-5`）
4. **マージ → 本番反映**
5. **開始**：経営者が `/sales/ai.html`「費用・設定」→ 共通署名を入れて保存 →「開始する」（最初は止まっている）

SQL を当てる前にコードが本番に出ても、既存のアタックは止まらない（AI の表が無ければ、これまでどおり）。

## 3. 最初の試し方（PC 販売・レンタル 20〜50社）

本番の確認 SQL（2026-10-11）では、既存の商材・キャンペーンで PC 販売・レンタルの候補は 0社、提案サービス未設定が 1,120社だった。
だから、まず AI の一次分類で候補を作る（企業マスタは書き換えない）。

1. 「企業を選んで分析」→ 商材「8EC・8RENT」のまま「未分類の企業を AI で分類する」
   （7点以上が 50社 見つかったら自動で止まる。全部やっても約1,000社・1ドル未満・10分前後）
2. 候補の表で「上位20社を選ぶ」（必要なら50社まで）→「選択した○社を詳しく分析する」
3. 「分析結果・営業文」で各社の詳細を開き、**分析の当たり外れ**（合っている／違う／分からない）を付ける
4. 有効企業から数社「AI で営業文を作る」→「承認を依頼する」
5. 営業責任者が「承認待ち」で承認 → 担当者がアタック画面で「AI文面（承認済み）」を選んで手で送る
6. 「費用・設定」で費用を見る（目安：一次分類 20社で約0.4セント、分析 1社 0.1〜0.5 セント、営業文 1件 2〜5 セント）

当たり外れの記録（`gw_sales_ai_analyses.check_result`）で、ENGER・無限道場へ広げるか決める。

## 5. MVP に入れていないもの

- 研修生向けの画面（docs §6）・高度な KPI（商材別の成約・粗利・本命案件）→ MVP の結果を見てから
- Opus での詳しい分析（`deep`）・配点の編集（`gw_sales_ai_settings.score_profiles` に商材ごとの配点を持てる作りだが、画面・API はまだ無い）
- フォームへの自動送信（Phase 1 ではやらない）
