# マーケティング UI/UX：ダッシュボードと3ステップ

更新：2026-10-25。確認用Draft PR #197（PR #196 を基底）。本番・SQL未適用。

## 結論：4つのタブ

| タブ | 利用目的 | 初期の画面 |
| --- | --- | --- |
| ① ダッシュボード | 現在の業務を判断する | 初期表示。KPI・円グラフ・棒グラフ・サイト別公開状況 |
| ② PRを作る | 1つのPRを入力・確認する | 8spの既存リリース草案、発信画面、制作管理 |
| ③ 拡散する | 各サイト・SNS・ブラストメール用の配信内容を準備する | 媒体の連携状態、UTMリンク作成 |
| ④ 効果を分析 | 公開後にサイト流入・反応・問い合わせを比較する | 6KPI・媒体別レポート・既存原本の詳細 |

## 最初のダッシュボード

- 最上段の4枚のカード：表示対象の原稿、確認待ち、公開予定、公開設定済。
- 円グラフ：企画／作成中／確認待ち／公開予定／公開設定済の原稿内訳。
- 横棒グラフ：記事・コラム／SNS／YouTube／キャンペーンの制作件数。
- その下に各サイトの公開・更新状況をカードで表示し、すぐに『PRを作る』『効果を分析する』へ移動できる。
- 円と棒の数値は原本から取得できた範囲のみ。未取得や権限なしを0として集計しない。
- 公開設定済はサイトへの実反映と同義ではない。制作予定は最大300件、公開済みサイト記事は直近30日対象など範囲の限界を明記する。

## PR→拡散→分析

1. PR作成：8sp草案のタイトル、概要、背景、画像、特徴、CTA等を活かす。将来は元原稿IDを保持したままMarketingに編集権限付きで連携する。
2. 拡散：サイト、X、Instagram、Facebook、LINE、YouTube、ブラストメール別に文章・画像・UTMを調整し、公開先と承認版を確認する。外部投稿や一括メール送信は未接続のままにする。
3. 分析：GA4の記事別PV・UTM流入、SNSの提供指標、ブラストメールの配信/クリックをread-onlyで取り込む。問い合わせ・Salesの商談/成約原本に紐付いた分と帰属不明を区別する。

## デザイン

- HR/Sales/Officeと同じ文字、角丸、ボタン、淡色背景、余白。
- 4タブで迷わない画面。スマホでは横スクロール、キーボード矢印で切替可能。
- 初期画面に細かな設定や長い一覧を出さない。制作予定の原本一覧はPRタブの折り畳み内。
- 色だけで判断させず、円グラフの凡例に件数、棒グラフに実数を表示。
- 取得不可、未接続、取得失敗、未計測は0件と区別。

## PR TIMES向け原稿作成（2026-10-25 追加）

PR作成タブは8spの既存 member/release.html?id=new に合わせて入力項目を変更した。
1. 基本情報：リリース種別（新サービス、新商品、イベント、キャンペーン、コラボ・提携、調査、会社情報、その他）、タイトル、サブタイトル。
2. 概要・背景：発表の概要を200〜300字目安で入力、背景・目的を任意入力。
3. ポイント・特徴：見出しと説明の組み合わせを最大3件。
4. 種別に応じた開催／提供／発売情報：日付、期間、時間、会場、料金、対象、提携先、詳細URL（不要な項目は非表示）。
5. 今後の予定・展望。
6. 会社概要：会社・団体名、代表者、所在地、設立、事業内容、会社URL。
7. お問い合わせ先：部署、氏名、電話またはメール、受付時間。
8. 画像：対象ファイル名と説明を一時保持。画像ファイル自体はアップロードされない。PR TIMESへ別途添付する。

PR TIMES掲載用草案の組み立ては、8spのjs/space-release.jsと**同一ソース**をMFに持ち込み再利用。
草案は『リード→背景→特徴→概要→今後→画像説明→会社概要→問い合わせ先』の順で構成される。
本文の直接編集とプレビュー、草案全文コピー、手元AI校正向けプロンプトコピーを実装。AI APIへの送信なし。事実や数字の創作もしない。
既存8spの権限/保存処理はこの画面から迂回しない。この画面はブラウザ内の一時作成のみで再読み込み時に入力消失。保存・正式承認・PR TIMES入稿・SNS投稿は未接続。
外部公開の実行と効果測定は既存正本のアクセス権・公開URL照合・GA4/SNS/blastmailの計測接続後に別段階で開発する。
