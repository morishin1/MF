# 労働条件通知書を電子で渡すときの確認（労働基準法施行規則 第5条第4項）

2026年9月11日づけの確認依頼に対する、mf（社内グループウェア）側の回答です。

## 前提

労働基準法施行規則 第5条第4項は、労働条件を書面以外の方法で明示するとき、
**労働者が出力して書面を作成できること** を求めています。
つまり「画面で読めればよい」ではなく、**本人が自分の手元にファイルとして残せ、紙にも出せる**
必要があります。

mf の契約・電子署名は、送った時点でPDFを作って保管する作りなので、
求められているのは「そのPDFに本人が手を届かせる導線」でした。今回そこを足しました。

---

## 確認結果

| # | 確認項目 | 結果 | どこで |
|---|---|---|---|
| 1 | PDF出力・ダウンロード | **可** | 本人の「契約書」画面／会社の「契約・電子署名」画面 |
| 2 | 印刷（A4） | **可** | 本人の「契約書」画面の［印刷］ |
| 3 | スマホからの保存・退職後の扱い | **一部対応**（下記） | 同上 |

### 1. PDF出力・ダウンロード — 可

本人の `contracts.html` に **［PDFを保存］** を足しました。一覧からも、1件を開いた画面からも押せます。

- 押すと `Content-Disposition: attachment` の付いたURLが返り、**開かずにそのまま保存**されます。
  ブラウザのPDFビューアに付いている保存ボタンを探させません。
- ファイル名は書類の題名（例：`労働条件通知書（署名済）.pdf`）が付きます。
- 署名前・署名済みのどちらも取り出せます。署名済みには「電子署名記録」のページが付いています。
- 会社側（`admin-esign.html`）にも同じ［保存］を足しました。
- 取り出した記録は監査ログ（`gw_sign_events` の `downloaded`）に残ります。
  「渡していない」「受け取っていない」の言い合いになったときの手がかりになります。

### 2. 印刷 — 可

本人の画面に **［印刷］** を足し、印刷用のCSSを入れました。

- 用紙は **A4・余白 18mm/16mm**（`@page`）。
- メニュー・ボタン・署名欄・署名の記録は紙に出しません。本文だけが出ます。
- 画面では本文を 60vh の枠に収めていますが、印刷時はこの高さ制限を外すので、
  **全文が複数ページに分かれて出ます**（1画面ぶんで切れません）。
- 本文は 11pt・行間 1.9 で、条項が詰まらない形にしています。

PDFで届いた書類（社労士が作ったものなど）は、この画面からは紙に出せません
（別ドキュメントの中身のため）。その場合は［PDFで読む］で開いて、
**そこで印刷してください** と案内が出ます。

### 3. スマホ・退職後 — 一部対応

**スマホ**：対応しています。mf はブラウザだけで動くので、iOS・Android のどちらでも
［PDFを保存］が使えます（iOS Safari では「ファイル」アプリに保存されます）。
画面も 400px 幅まで崩れません。

**退職後**：ここは仕組み上の限界があるので、正直に書きます。

- mf は Supabase の `auth.users` でログインを見ています。
  **アカウントを止めると、本人は契約書の画面を開けなくなります。**
- したがって「退職後もいつでも取りに来られる」状態には **していません**。

代わりに、次の2つを入れました。

1. 署名済みの一覧に、常時この案内を出す：

   > **お手元にも控えを残してください。**
   > 退職などでログインできなくなると、この画面からは取り出せなくなります。
   > いまのうちに「PDFを保存」でご自身の端末に保存しておくことをおすすめします。

2. 一覧の各行に［保存］を置き、**画面を開かずに1クリックで落とせる**ようにしました。

### 「自動配信連携（締結と同時にメール添付で送る）」について

ご提案の代替案のうち、**メール自動送信は現時点では実装していません**。
理由は、mf にメールを送る仕組み（SMTP／送信サービス）が入っていないためです。
入れるなら送信サービスの契約・ドメイン認証（SPF / DKIM / DMARC）から必要になります。

そのうえで、**メール添付はおすすめしません**。締結済みの労働条件通知書には
氏名・住所・賃金が載ります。メールは経路の暗号化が相手のサーバ任せで、
受信箱に残り続け、転送もできてしまいます。

代わりに、次のどちらかをご検討ください。どちらも、決めていただければ実装できます。

- **(A) 退職手続きのチェック項目にする** … 退職の手続き（`admin-hr.html`）に
  「契約書のPDFを本人が保存したことを確認」を1項目足す。会社側から促せます。
  既存の仕組みに乗るので、追加で入れるものがありません。
- **(B) 退職後も一定期間だけ開ける** … 退職から N か月は、契約書の画面だけ開けるようにする。
  ログインの扱いを変えることになるので、他システム（無限道場・タイムカード・会計）と
  同じ `auth.users` を使っている点をふまえた設計が要ります。

## 締結までの流れ（今回あわせて足したもの）

労働条件通知書の作成依頼からの導線も、あわせて1本につなぎました。

1. **依頼を作る** … `admin-esign.html` の「作成依頼」タブ、
   `workflow.html` の「人事の手続き」、または名簿（`admin-members.html`）の［書類を依頼］から。
   **最初に「誰あての書面か」を決めます。**
2. **社労士へ渡す** … ［依頼文をコピー］で、条件がそろった依頼文が作られます。
   提示する条件の欄は、労基則第5条で必ず書く項目を固定の欄にしてあるので、
   人によって書く項目が変わりません。必須が空のままでは止まります。
3. **届いたPDFを取り込む** … 依頼の行に［書面を取り込む］。
   取り込んだ時点でSHA-256を控え、状態が「確認待ち」になります。
   中身は［見る］で画面いっぱいに開いて確かめられます。
4. **そのまま署名依頼** … ［この内容で署名依頼］を1回押すだけ。
   **宛先はもう決まっているので、打ち直しません。**
   送る時点でPDFを別の場所へ写すので、あとから依頼側の書面を差し替えても、
   署名依頼の中身は変わりません。取り込み時とハッシュが違えば送りません。
5. **本人が署名** … 本人の「契約書」画面にPDFがそのまま出ます。
   署名すると「電子署名記録」のページが付いたPDFが作られ、双方から取り出せます。

## 未対応・確認いただきたいこと

- **メール自動送信**（上記）。(A) か (B) か、あるいは不要か。
- **PDFで届いた書類の印刷**は、開いたPDFの画面から印刷する形です。
  mf の画面からそのまま紙に出すには、PDFの中身をこちらで描き直すことになるため、
  社労士が作った書面をそのまま渡す目的と合いません。
- **署名の強さ**は変わっていません。mf のログイン（メール＋パスワード）＋
  日時・IP・利用環境・同意文言の記録による署名で、
  **認定認証業務による電子署名ではありません**。画面にもそう明記しています。
  労働条件通知書の交付としてはこれで足りますが、
  それ以上の証拠力が要る契約は、立会人型のサービスをご検討ください。
