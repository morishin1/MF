# 端末管理を、追加費用0円で回す

対象は**自社PCだけ**。だから、買わなくても回る形にした。

| 買わないもの | 代わりにどうするか |
|---|---|
| 商用のコード署名証明書（年 3〜10万円） | 初回だけ管理者が対象PCで実行する。更新は社内の鍵で確かめる |
| MDM（Intune 等、1台あたり月額） | Windows のブラウザポリシー（レジストリ）で拡張を配る |
| 端末1台ごとのライセンス | 無い。台数で増える費用はゼロ |
| 拡張ストアの登録料 | 社内で `.crx` をホストする（自社サーバ） |

かかるのは、すでに払っている Vercel と Supabase だけ。端末を増やしても増えない。

---

## 1. 初回インストール（管理者がやる）

商用のコード署名証明書を使わないので、初回に Windows の警告（SmartScreen）が出る。

**社員に「警告を無視して実行してください」と覚えさせない。**
それを覚えた人は、本物の怪しいEXEでも同じことをする。
だから、**最初の1回だけは管理者か社内IT担当が、対象PCの前で入れる**。

```
1. 本人がマイページ →「会社PCのセキュリティ設定」
2.「この会社PCを設定する」→ EIGHT-Agent-Setup-<札>.exe が落ちる
3. そのまま実行（名前は変えない）
4. SmartScreen が出たら「詳細情報」→「実行」
5. 「このアプリがデバイスに変更を加えることを許可しますか」→ はい
6. ブラウザが自動でもどる（device-setup.html?pair=<札>）
7. 本人が「内容を確認しました」を押す ← ここまで記録は始まらない
```

社員がやるのは 7 だけ。コマンドも、登録コードの入力も、
ブラウザ拡張の手動インストールも無い。

### 誰のパソコンかは、1 の時点で決まる

落とすファイルの名前に、その人のための1回きりの札が入っている
（`EIGHT-Agent-Setup-<札>.exe`）。インストーラはそれを読むので、
あとから社員名を選ぶ場面がない。

**中身は変えていない**ので、署名もハッシュもそのまま通る。
配る版を人ごとに作り分ける必要もない。

名前を変えられて読めなかったときは、インストーラが自分で札を作る。
そのときだけ、画面で1回「このパソコンを設定する」を押す。止まらない。

管理者が代わりに入れる必要があるとき（本人が使えない等）は、
管理者のマイページからではなく、**本人のアカウントで**始めてもらう。
管理者のブラウザで本人の札を開いても、結びつかない（403）。

7 の「内容を確認しました」は、**本人が読んで確認するまで記録が始まらない**。
本人が押せない事情があるときは、管理画面の「周知済みにする」で、
いつどう周知したかを残す。

### EXE が1回で済ませること

| | 中身 |
|---|---|
| 1 | Agent を `C:\Program Files\EIGHT` に置く |
| 2 | サービスとして登録（起動時に自動で上がる） |
| 3 | ログオンした人の画面で動くほう（UI）を自動起動に |
| 4 | Chrome のポリシーに拡張を登録（`ExtensionInstallForcelist`） |
| 5 | Edge のポリシーに拡張を登録（同上） |
| 6 | Native Messaging の置き場所を登録 |
| 7 | このPCの札をサーバに預ける → ブラウザが開く |
| 8 | 本人が押したら、社員アカウントと同じ Device ID で紐付く |
| 9 | 管理画面に1台として出る（Agent / Chrome / Edge が1行） |

Agent とブラウザ拡張は**同じ Device ID** を持つ。
管理画面では、1台のPCとして1行に出る。

## 2. ブラウザ拡張は、社員に入れさせない

Windows のポリシー（HKLM のレジストリ）に書くと、Chrome も Edge も
起動時に自社サーバから拡張を取りにいって、勝手に入る。
社員は消せない。MDM は要らない。

```
HKLM\SOFTWARE\Policies\Google\Chrome\ExtensionInstallForcelist
HKLM\SOFTWARE\Policies\Microsoft\Edge\ExtensionInstallForcelist
  1 = <32文字のID>;https://mf.8grp.co.jp/ext/updates.xml
```

インストーラが書く（`agent/cmd/eight-agent-setup/main.go` の `forceInstall`）。
ほかの会社のポリシーを上書きしないよう、空いている番号に書く。

`.crx` と `updates.xml` の作り方は `agent/extension/README.md`。

---

## 3. 自動更新は「落としたEXEをそのまま実行」にしない

証明書が無いので、Windows は落としたEXEが誰の作かを確かめてくれない。
そこを素通しにすると、配布先のURLが乗っ取られた時点で、
**全台で任意のプログラムが動く**。

そこで、配る版に社内の鍵（Ed25519）で署名する。無料。

### 3-1. 鍵を作る（最初の1回だけ）

```
cd agent
go run ./cmd/eight-agent-keygen -new -out ~/eight-update.key
```

- 秘密鍵 … `~/eight-update.key`（0600）。**Git に入れない、Slack に貼らない**
- 公開鍵 … 画面に出る。これをビルドに焼き込む

```
UPDATE_KEY=<公開鍵> EXT_ID=<拡張のID> ./build.sh
```

`UPDATE_KEY` が空だと、エージェントは自動更新を**一切しない**。
確かめられないものを落として実行するくらいなら、古い版のままでいる。

### 3-2. 版を配るたびに署名する

```
cd agent
go run ./cmd/eight-agent-keygen \
   -key ~/eight-update.key \
   -version 0.3.0 \
   -url https://mf.8grp.co.jp/agent/EIGHT-Agent-Setup.exe \
   -file dist/EIGHT-Agent-Setup.exe
```

署名の対象は4つまとめて。

```
version \n url \n sha256 \n size
```

ハッシュだけに署名すると、同じハッシュのまま URL を差し替えられる余地が残る。
4つまとめてあるので、それができない。

### 3-3. 登録する（Supabase の SQL Editor）

```sql
insert into public.gw_device_releases
  (tenant_id, version, url, sha256, size_bytes, signature, key_id, published)
values
  ('<テナントのUUID>',
   '0.3.0',
   'https://mf.8grp.co.jp/agent/EIGHT-Agent-Setup.exe',
   '<SHA-256>',
   <大きさ>,
   '<署名>',
   '<鍵の目印>',
   true);
```

署名・ハッシュ・大きさのどれかが無い行は `published = true` にできない
（`db/058_release_signing.sql` の制約が止める）。
「とりあえず公開して、署名はあとで」を作らないため。

### 3-4. エージェント側で起きること

```
6時間ごと
  ↓
/api/devices/manifest を読む
  ↓
① 焼き込んだ公開鍵で、版・URL・ハッシュ・大きさの署名を確かめる
     合わない → URL を開きにすらいかない。終わり
  ↓
② https から落とす（http は拒否）。言われた大きさ＋1バイトで打ち切る
  ↓
③ 落ちてきた中身の SHA-256 を確かめる
     合わない → 消す。実行しない
  ↓
④ EIGHT-Agent-Setup.exe -update を実行（登録も同意もやり直さない）
```

①②③のどれか一つでも合わなければ、**実行しない**。
拒んだことは `agent_update_refused` として管理画面に残る。

実装: `agent/internal/release/release.go`（テスト `release_test.go`）、
`agent/cmd/eight-agent-svc/platform_windows.go` の `checkUpdate`。

### 3-5. 鍵を無くしたら

新しい鍵を作り、`UPDATE_KEY` を入れ替えて組み直し、
**手で配り直す**（古い鍵で署名した版は通らなくなる）。
台数が少ないうちはこれでよい。

## 4. これは証明書の代わりではない

| | 商用のコード署名証明書 | この仕組み |
|---|---|---|
| SmartScreen の警告 | 出なくなる | **出る**（初回のみ、管理者が押す） |
| 「誰が作ったか」を Windows が確かめる | する | しない |
| 更新ファイルの取り違え・すり替え | 防ぐ | **防ぐ** |
| 費用 | 年 3〜10万円 | 0円 |

守っているのは「配っているものが、うちが作ったものか」だけ。
自社PCだけが対象で、初回は管理者が入れるので、それでよいと決めた。

**将来、証明書を用意したくなったら足せる。**
署名が無いことを理由に、ビルドもインストールも止めない作りにしてある
（`agent/build.sh` は警告を出すだけで、最後まで通る）。
この鍵の仕組みは、証明書を足したあとも残しておいてよい。

## 5. 管理画面で見えること

端末ごとに、まずこれだけ。

```
田中太郎 / DESKTOP-A123 / Windows 11
  ● Agent 接続中   ● Chrome 連携済   ● Edge 連携済     最終通信 3分前
```

問題があるPCだけ、行をクリックして詳細を見る。

| 印 | 意味 |
|---|---|
| ● 緑 | つながっている |
| ● 黄 | 入っているが、まだ本人の確認待ち |
| ● 赤 | 届いていない（ソフトが止まっている / 拡張が消された） |

「全部緑・最終通信が新しい」なら、それ以上は開かなくてよい。
