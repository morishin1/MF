# ENGER 企業サマリー × マッチング精度向上（10社パイロット）
更新: 2026-11-07 JST。**設計・調査結果であり、生成・推薦の本番稼働ではない。**

## ゴール（企業概要ではなく商談につながる推薦）
1. AI収集した会社紹介から「人材需要」「案件提供可能性」「得意職種・技術」を**仮説**として抽出する。
2. 企業名/法人番号/公式URLを照合。SalesとENGERの**同一法人の紐づけ**ができなければ正式な候補判定を行わない。
3. 具体的な需要は営業担当がヒアリングして「確認済み」にする。公開求人は採用傾向を示すだけで、SES発注の証拠にはしない。
4. **確認済みの案件**（募集継続・予算・提案受付・所属/商流確認）と**有効な人材**の間で既存 `src/lib/match.ts` の決定論的スコアを使う。既存の「候補側に2件以上の提案があれば除外」の運用は変更しない。
5. 企業の確認済み案件/ニーズがある場合だけ、スキル・職種経験・単価・勤務条件・稼働日・商流など、業務上関連する条件から再ランク付け。**AIの推定だけで加点やハード除外をしない**。年齢・国籍等の属性による新しい順位付けを追加しない。
6. 提案を見せたときは「一致した根拠」「満たさない条件」「未確認項目」「データ確認日」を付ける。取引先・パートナーの機密情報は営業先に表示しない。
7. 提案結果（企業からの返答・案件の有効/無効・面談・成約・見送りと理由）を既存ENGERの `dx2_match_ai_evaluations` / `dx2_match_feedback` およびSales提案ステージに紐づける。フィードバックが不足している間は自動で重み変更しない。

## 精度を検証する出力
企業ごとに2つの区分を分けて表示する:
- **調査候補（仮説）**: 公式HPなどの事実から読み取れた職種・技術。出典URL/日付を伴い「需要未確認」と表示。提案・送信しない。
- **提案候補（確認済み）**: 企業ID一致＋担当による求人/案件/募集状況の確認＋候補者の条件確認を満たしたもの。既存マッチスコアで順位付けし、人材ID/案件ID・理由・不足・確認日を表示。

### 比較指標（既存順位付け vs 企業情報活用）
- Precision@3: 各社上位3候補に対して担当者/先方が「提案可能」と評価した割合。**未評価を正解扱いしない**。
- Verified-fit@3: 上位3件で会社ID・案件募集・候補稼働・条件がすべて確認できた割合。
- 面談化率、辞退/NG率と理由、成約率（追跡期間が十分な場合）、データ収集率/法人同定一致率、APIコスト。
- 同一期間・同一候補母集団のA/B比較にする。10社だけでは成約率の統計的改善は確定できないため、営業レビューと失敗理由を検証する。

## 新しいAI分析JSONの例（フィールドのみ）
```json
{
  "demand_hypotheses": [
    {"role": "バックエンド開発", "skills": ["Java"], "evidence": "public_job_posting",
      "source_url": "https://example.invalid/recruit", "checked_at": "2026-11-07", "status": "hypothesis"}
  ],
  "supply_hypotheses": [],
  "confirmed_needs": []
}
```
- `confirmed_needs` はAIが生成しない。実際の確認記録は権限付きの別テーブルに持つ。公開求人→確認済SES案件への自動昇格は禁止。
- 会社名/コーポレートサイト不一致は別法人/旧社名を確認するまで保留。
- 別顧客の秘密情報をAI入力に含めない。公開するモーダルはパートナー名・連絡先を隠す。
