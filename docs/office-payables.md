# Office「請求・支払」（支払管理）

`/office/billing.html` は **「支払管理」｜「案件別」** の2タブ。既定は「支払管理」。「案件別」は、これまでの案件ごとの請求・BP請求・支払の状況で、機能は何も削っていない（操作は月次業務の案件の画面）。

支払管理は、請求書を受け取ってから MFクラウド用CSVを出すまでを1画面で行う。

```
請求書を受け取る → PDF/JPEG/PNG をアップロード → 内容確認（支払先・金額・請求日・対象月・締め・支払期日）
  → 仕訳を設定 → 支払予定にする → 実際に払ったら支払済みにする → MFクラウド用CSV
```

別の Excel で支払予定表を作らなくても、「何を・いつ・いくら払うか」が一覧で分かる。BP請求書だけでなく、外注・業務委託・家賃・SaaS・通信費・広告費・仕入・会場費・専門家報酬・その他経費を扱う。

## 支払期日の決め方（勝手に推測して確定しない）

1. 請求書に明記された支払期日（`due_source = invoice`）
2. 経理担当が入力した支払期日（`manual`）
3. 支払先マスタから自動計算（`master`）。対象月＝締め月として、`payment_month_offset` か月後の `payment_day` 日（31＝月末）
4. 不明なら「支払期日未設定」（日付を入れない）

休日調整は［設定］で **前営業日／翌営業日／調整しない**（`lib/holidays.js` の営業日表。2027年末まで）。調整は自動計算（3）だけに効く。請求書に明記された日付は調整しない。

## AI読取（候補）

ファイルを置くと［AIで読み取る］で、支払先・請求番号・請求日・支払期日・小計・消費税・合計・登録番号・摘要の**候補**を入力欄に入れる（黄色）。**読取候補 → 人が確認 → 確定**：読取だけでは請求書は登録されず、「読取候補の内容を、請求書と見比べて確認しました」にチェックしないと登録できない。支払期日は、書かれていなければ空（計算しない）。実装は `lib/office-invoice-ai.js`（勤務表の読取と同じ作り：`lib/office-timesheet-ai.js`）。

## 仕訳

- 請求書ごとに、借方・貸方それぞれ 勘定科目／補助科目／部門／取引先／税区分／インボイス区分／金額／税額 ＋ 摘要・仕訳メモ・タグ。
- 初期値は **支払先の「前回確定した仕訳」→ なければ支払先マスタの標準仕訳**。
- **複合仕訳**：1枚を複数科目に分けられる（例：通信費 20,000＋消耗品費 30,000＋外注費 50,000／未払金 100,000）。画面に「借方・貸方・**差額 N円**」を出し、**貸借が合わないと［仕訳を確定］は押せず、CSV にも出せない**（API も 409）。請求書の税込金額と仕訳の合計が違うときは警告（源泉徴収・値引きがあり得るので止めない）。
- インボイス区分は **適格／80%控除／70%控除／50%控除／30%控除／控除なし**（`lib/office-invoice-defs.js` の `INVOICE_CLASSES` の1か所）。
- 勘定科目・補助科目・部門・税区分は **自由入力＋候補リスト**。MFクラウドの正式名称と一致させるのは人（候補は［設定］で足せる）。MF の API 同期はしない。

## 支払

未払い → **支払予定**（支払予定日・支払金額・支払方法・支払元口座・メモ）→ **支払済み**（実支払日・実支払額・振込手数料（任意）・支払元口座・メモ）。期限を過ぎて未払いなら「期限超過」。誤登録は **理由つきで取り消す**（物理削除しない。`status = void`・取消理由・日時・人を残す）。取り消すと、支払予定の登録に戻る。

## MFクラウド用CSV

[MFクラウドCSV] で 対象月・**未出力のみ／全件**・**仕入計上／支払／両方** を選ぶ。仕訳帳 27列、日付 `yyyy/MM/dd`、UTF-8 **BOM付き**、CRLF。24〜27列は空欄。

- **仕入計上**：確認済みで仕訳確定済みの請求書。取引日＝仕訳日→請求日→対象月の末日。MF仕訳タイプ＝債務。
- **支払**：**支払済みだけ**（支払予定は出さない）。仕入計上の貸方（未払金など）を借方に、支払元口座を貸方に。取引日＝実支払日。振込手数料があれば借方に支払手数料を1行足す。MF仕訳タイプ＝経費・債務支払。
- **複合仕訳**は同一取引No・同一取引日の複数行。借方と貸方を上から1行ずつ組にし、余った側は空。
- 出せないもの（貸借不一致・仕入計上の仕訳が未確定の支払など）があれば、CSV を出さず理由を返す。
- 出力すると **出力バッチ**（`gw_office_mf_exports`・出力者・日時・種別・バッチID）と、請求書・支払の **初回／最終の出力日時** を残す。

**「CSV出力済み」は「MFへ登録済み」ではない。** 画面にも「CSV出力済み」としか出さない（MF に取り込まれたかは、この画面では分からない）。

### MFクラウドで実際に取り込めるかの確認（初回に1度）

要件書の27列・複合仕訳の書き方は、実際の MFクラウドで取り込んでみないと確かめられない。**[docs/mf-import-test/README.md](mf-import-test/README.md)** の手順で、ダミーのCSV（画面の［MFクラウドCSV］→「インポート確認用のサンプルCSV」でも出せる）を使って確認する。

## 権限

| 操作 | 経営者 | 責任者 | 経理 |
|---|:-:|:-:|:-:|
| 一覧・詳細を見る／請求書を登録／内容を確認 | ○ | ○ | ○ |
| 仕訳・支払予定・支払済み・取消・支払先マスタ・設定・MF CSV | ○ | 見るだけ | ○ |

MFA は要求しない（Office の方針）。月次完了した月は、登録・仕訳・支払の変更を断る（CSV の出力は断らない）。

## API

- `GET /api/office/invoices?month=YYYY-MM` 一覧・サマリー・支払先・設定・候補／`?id=` 詳細
- `POST /api/office/invoices { action }` `upload` `read` `register` `update` `preview_due` `confirm` `unconfirm` `save_journal` `schedule` `pay` `cancel_payment` `void`
- `GET/POST /api/office/vendors`（`create` `update` `set_active` `save_settings`）
- `GET/POST /api/office/mf-csv`（GET＝見込み、POST＝出力、`GET ?sample=1`＝確認用サンプル）
- BP請求書の登録・照合・承認は従来どおり `api/office/payables.js`（月次業務の画面）。支払管理の一覧には BP請求書も出て、承認済みなら仕訳・支払・CSV に進める

## DB（db/134_office_payables_general.sql）

- 追加：`gw_office_vendors`・`gw_office_invoice_journals`・`gw_office_mf_exports`・`gw_office_mf_export_items`・`gw_office_payables_settings`（RLS 有効・ポリシー無し＝API だけ）。バケット `office-invoices`（非公開）。
- 既存表への列追加（すべて nullable か default）：`gw_vendor_invoices`（`vendor_id`・`invoice_kind`・請求日・支払期日・仕訳状況・ファイル・MF出力日時ほか）／`gw_office_payments`（支払方法・口座・実支払額・手数料・取消理由・MF出力日時ほか）。
- **変えないもの**：`partner_company_id` は元から nullable（NOT NULL の解除は不要）。「partner か vendor が必須」という CHECK は足さない（既存の BP 請求に partner 未設定があり得る）。新規の一般請求書で `vendor_id` を必須にするのは **API の役目**。
- 適用前後の確認：`db/check_134_office_payables_general.sql`／戻す：`db/rollback_134_office_payables_general.sql`（一般経費の請求書・支払・仕訳・マスタ・出力記録は消える。BP の請求書・明細・支払・月次完了は消えない）。
- 適用の順番：SQL → デプロイ。デプロイが先でも、新しい支払管理だけ「SQL を流してください」(503) と出て、ほかは止まらない（月次・案件別は、この SQL が無くても動く）。
