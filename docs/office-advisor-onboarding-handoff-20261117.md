# GW入社届出 → 社労士タスク自動連携（2026-11-17）

## 目的
GWで入力済みの入社情報を担当社労士へ二重入力なしで伝える。社労士はGWの専用画面で内容を確認し、確認結果・不足事項をOfficeに返す。

## 画面と動作
- 本人：/onboarding/ で入社フォームを入力。途中保存の間は社労士へ通知しない。
- 本人：必要な同意を終えて「提出」を押すと、GWで入社届出の確認タスクを1名1件作る。
- Office：/office/professionals.html?tab=labor で、未完了・未割当・期限を確認し、担当社労士を指定する。
- 社労士：GWの通知リンクからMFA付き専用画面を開き、入社情報と不足項目を確認し、コメント・完了でOfficeへ返す。
- 社労士アカウント未登録なら未割当タスクを保存するが、通知したとは表示しない。

## データ連携
- 正本は gw_employees / gw_contracts / gw_onboard_profiles とし、社労士詳細を開いたときのみ必要事項を参照する。
- 表示する項目：氏名、カナ、生年月日、住所、電話、入社日、雇用区分、契約期間、週の所定労働時間、業務内容、基礎年金番号、雇用保険番号、扶養の有無。未入力項目を明示する。
- マイナンバー・振込口座・緊急連絡先・給与額・評価・日報は社労士向け表示や通知に含めない。
- タスク説明文と通知本文に住所や保険番号を保存しない。MFA・テナント・担当者の権限チェックと閲覧監査を適用する。
- 本人の提出操作で同期。途中保存のたびには通知しない。
- source_key=onboard-profile:<employee_uuid> の一意制約で二重作成を防止。再提出で閉じたタスクだけを再開し、既存の確認履歴を残す。
- 既存の書類提出に連動する社労士タスクやOfficeのPDF保管運用は変更しない。

## 本番適用前の条件
- 社労士アカウントをGWで招待し labor_advisor 権限を付与する（11/17時点は0名）。
- 本人提出→1名1タスク→担当通知→社労士詳細→結果の戻し、を実アカウントとMFAで確認する。
- 他テナント、税理士、一般社員、他の担当社労士が閲覧できないことを確認する。
- 入力途中の下書きでは通知せず、繰り返しの提出で二重タスクが作られないことを確認する。
- 外部メールでの個人情報送信は行わない。通常メール送信、過去分一括遡及、外部行政申請、契約書自動生成は対象外。
- タスク完了は社会保険の資格取得・雇用契約の法的成立を自動認定しない。
