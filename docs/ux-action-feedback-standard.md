# 進めない理由を必ず伝える — 全サービス共通 UI/UX ルール

## 目的
HR / Sales / Office / KEIEI / 日報で「次へ進めない」「保存できない」「提出ボタンが消えた」をなくす。

**基本動作**: 操作ボタンは原則表示したまま。ユーザーが押した瞬間に前提条件を検証し、未達の場合は「不足していること」と「直す場所」をセットで伝える。エラーを隠して無条件に進めることはしない。

## 共通コンポーネント
- \`js/action-feedback.js\` / \`css/action-feedback.css\`
- \`KPActionFeedback.show({ title, message, actionLabel, actionHref })\` : 同一オリジン内の登録・入力画面へ案内
- \`KPActionFeedback.show({ title, message, actionLabel, onAction })\` : 項目へスクロール、再確認など画面内の操作へ案内
- 使うときに画面側でCSS / JSを読み込む。画面から技術的なSQLエラーを直接表示しない。
- アラートは押したときだけ開く（ページを開いた瞬間に連発させない）。Esc・「閉じる」でキャンセル可。
- 原則として単一の不足を短く提示する。複数の入力不足は最大3件程度をまとめ、修正先へ移動する。

## 表示形式（必須）
1. **理由**：例「翌営業日の予定が未登録です」
2. **必要な操作**：例「翌営業日の仕事予定を1件以上登録してください」
3. **次へ進むボタン**：例「カレンダーで予定を登録」
4. 対応後に再検証して続行。理由が解消したと確認できるまで成功を表示しない。

## NG
- 未入力の説明なしにボタンを消す・押せなくする
- 「エラーです」「保存できません」だけ表示する
- 入力欄の最下部だけに赤字を出し、現在操作した場所から見えない
- APIエラー（ネットワーク/DB）を未入力と決めつける
- 表示だけ制御して、直接APIからの不正な操作を許してしまう

## 画面別の適用チェックリスト
| 対象 | 代表的な原因 | 表示すべき修正導線 | 実装段階 |
|---|---|---|---|
| 日報 | 翌営業日の予定なし / 日報未入力 / 週次未完了 / AIレビュー未確認 | カレンダー登録 / 該当入力欄へ移動 / 再確認 | Phase 1 |
| Sales（提案管理） | 担当未選択 / CS条件不達 / 引継ぎ先未設定 / 一括選択が空 / 権限不足 | 担当設定 / 対応記録 / チェックボックス選択 | 今後適用 |
| HR | 労働条件通知書未添付 / 同意前 / 社労士確認待ち | 該当書類のアップロード / 手順を案内 | 今後適用 |
| Office（業務予定・申請） | 必須日時が空 / 時間重複 / 申請項目不足 | 対象日の入力欄へ移動 | 今後適用 |
| KEIEI | 入力不足 / 権限不足 / 関連ステータス未達 | 担当確認 / 必須項目 / 管理者への確認 | 今後適用 |

**権限・個人情報**: 閲覧権限を持たない対象の詳細をアラートに表示しない。更新処理の前提条件は必ずAPI/DB側でも検証する。

## テスト観点
- 操作ボタンが見える。条件不足で押すと理由と登録先が現れる
- 条件を満たすと従来の保存・提出処理が動く（新しいダイアログが無条件送信しない）
- 通信エラーと未入力を区別する。再確認可能
- PC・スマホ・キーボード操作で見える。権限のないユーザー情報は漏れない
